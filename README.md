# T-Box_Re — 사내 파일 공유 서비스 t-box 재구축

교육용으로 일부러 취약하게 만든 t-box(해킹 실습 대상)를, **실습에서 뚫린 5가지 취약점이 없는 형태**로 처음부터 다시 만드는 과제 저장소입니다.

| 항목 | 내용 |
|---|---|
| 스택 | 순수 PHP 8.1 (프레임워크 없음) · PostgreSQL 14 · nginx 1.18 · Ubuntu 22.04 — 실습 VM 설치본 그대로 (운영 전환 시 업그레이드, SECURITY R-21) |
| 진행 방식 | AI와 기능 하나씩 → **내가 직접 공격해 검증** → 한글 커밋 |
| 상태 | 1~10단계 구현·Fable 검토 완료 (2026-09-11) — 사용자 자기 공격(관문 ③) 일괄 수행 대기, 순서는 `STAGES.md` 2-1. 방화벽·SSH 강화 적용(`deploy/hardening.sh --apply`)·WAL·원격 로그는 미적용(운영 결정) |

## 실습에서 뚫린 5가지 → 이번 설계의 방어 (요약)

| 공격 | 방어 | 검증 |
|---|---|---|
| 프론트 권한 우회 | 모든 요청을 서버 `Authz` 가 판단, 라우트에 권한 정책 필수, CSRF | T-1 |
| 권한 없는 데이터 노출 | SQL `WHERE` 에서 제외 — 응답에 아예 없음 | T-2, T-3 |
| XSS | 서버 이스케이프 + `textContent` + CSP + 다운로드 `attachment` | T-4 |
| SQL 인젝션 | Prepared Statement 만, 정렬 허용 목록, 오류 은닉 | T-5 |
| SSRF | "URL로 가져오기"는 `src/Fetch.php` 한 곳에서만: https·443 만, 도메인 화이트리스트, IP 검증 + 고정 접속, 리다이렉트 금지, 업로드와 동일 검증 | T-6 |

자세한 근거와 남은 위험은 `SECURITY.md` 를 보세요.

## 화면 (`PRD.md` F-20 · 10장)

기능별로 화면이 나뉘어 있고, **좌측 내비가 있는 공통 셸**(`src/views/shell_*.php`)을 함께 씁니다.
내비 항목은 서버 HTML 에서 전부 `hidden` 으로 나가고 `GET /api/me` 의 `can_*` 플래그가 참일 때만
열립니다 — **보이는 것은 편의일 뿐이고, 막는 것은 라우트 정책입니다.** 개발자도구로 항목을
되살려도 아래 정책이 다시 403 으로 막고 그 시도가 `authz.route|deny` 로 감사 로그에 남습니다.

| 화면 | 경로 | 라우트 정책 | 내용 |
|---|---|---|---|
| 로그인 | `/login` | public | 아이디·비밀번호 → (2단계 인증을 켠 계정만) 6자리 코드 |
| 파일 | `/` | authenticated | 목록·검색·정렬·페이지, 「파일 올리기」·「URL 로 가져오기」 **대화상자**(올릴 위치 = 지금 연 폴더), 행 작업(**미리보기**·다운로드·수정·삭제) |
| 휴지통 | `/trash` | `role:Admin` | 삭제된 파일 목록과 복구 (30일) |
| 내 계정 | `/settings` | authenticated | 내 정보(아이디·역할·팀) · 비밀번호 변경 · 2단계 인증 |
| 계정 관리 | `/users` | `user.manage` | 계정 생성·역할/팀/만료 변경·임시 비밀번호 재발급·2단계 인증 초기화 |
| 조직·권한 | `/org` | `org.manage` | 팀 생성·이름 변경·비활성화, 구성원 표·배정, 권한 매트릭스 **조회** |
| 감사 로그 | `/audit` | `audit.read` | 육하원칙 6필터 + 기록 표 |
| 위키 | `/wiki` · `/wiki/{book}` · `/wiki/{book}/{slug}` | `role:Admin` | 문서를 초보자 말로 다시 쓴 해설 — 책 셋(Qaredi · t-box · 커뮤니티)을 골라 들어간다. 옛 `/wiki/{slug}` 는 `/wiki/tbox/{slug}` 로 308 |

### 조직·권한 (`PRD.md` F-19 · `ARCHITECTURE.md` 5.9)

`/org` 는 **관리자 전용**(`org.manage`)이며 세 가지를 합니다.

- **팀 관리** — 팀 만들기 · 이름 변경 · 비활성화/활성화. 변경마다 **사유가 필수**이고
  감사 로그 `team.create`·`team.update` 에 사유와 **이전값 → 새값**(`detail.before`/`after`)이 남습니다.
  **팀은 지우지 않습니다** — 파일(`files.team_id`)·계정(`users.team_id`)·감사 기록이 팀을
  가리키고 있어, 지우면 "어느 팀의 파일이었나" 를 되짚을 수 없기 때문입니다. 그래서 삭제 대신
  `is_active=false` 로 내리고, 그것도 **활성 구성원이 0명일 때만** 됩니다(먼저 재배정 — 400
  `team_has_members`). 비활성 팀은 `GET /api/teams` 선택지에서 빠지고, 그 팀으로의 새 배정·
  업로드·URL 가져오기·등급 변경은 400 으로 막힙니다. 이미 그 팀에 있는 파일·계정은 그대로입니다.
- **구성원 배정** — 팀별 구성원(아이디·역할·활성)을 보여 주고, 배정은 **새 API 를 만들지 않고**
  기존 `PATCH /api/users/{uid}` 의 `team_id` 변경을 그대로 부릅니다. 자기 자신 금지·마지막
  관리자 보호·**세션 즉시 종료**(T-22) 같은 규칙이 두 곳으로 갈라지지 않게 하기 위해서입니다.
- **권한 매트릭스 조회** — `permissions` 16행(역할 × 접근 레벨)을 **읽기 전용**으로 보여 줍니다.
  편집 기능은 넣지 않았습니다: 화면에서 고칠 수 있게 하려면 앱 DB 계정에 그 표의 변경 권한이
  필요해지고, 그 순간 앱의 결함 하나가 **권한 상승** 경로가 됩니다. 앱 계정 `tbox_app` 은 이
  표에 **SELECT 만** 갖습니다(`db/grants.sql`, `ARCHITECTURE.md` 6.2-1 · 10장). 편집이 필요해지면
  별도 DB 롤·2인 승인·`permission.change` 감사와 함께 `PRD.md` **Q-12** 로 결정합니다
  (`SECURITY.md` R-43).

### 미리보기 (`PRD.md` F-18 · `ARCHITECTURE.md` 5.8)

파일 목록의 행마다 있는 「미리보기」 단추는 **내려받지 않고** 내용을 확인하는 모달을 엽니다.
**권한은 다운로드와 한 글자도 다르지 않습니다** — 같은 `Authz::decideRead`, 같은 403 문구, 같은
sha256 대조를 거치고 `file.preview` 로 감사 로그에 남습니다. 다른 것은 응답의 모양뿐입니다.
무엇을 보여 줄지는 **서버가 DB `files.ext`(업로드 때 finfo 로 확정한 값)로만** 정합니다 —
요청 값으로 형식을 고를 수 없습니다.

| 갈래 | 확장자 | 보여 주는 것 | 상한 |
|---|---|---|---|
| 이미지 | `png jpg jpeg gif` | 원본을 그대로 (`<img>`) | 업로드 상한 100MB |
| PDF | `pdf` | 원본을 그대로 (`<iframe sandbox>`) | 같음 |
| 텍스트 원문 | `txt md` | 글자 그대로 (마크다운을 HTML 로 바꾸지 않습니다) | 앞 1MiB 를 읽어 64KiB 표시 |
| 표 | `csv` | 표 한 칸씩 글자 그대로 | 200행 × 50열 |
| 압축 항목 목록 | `zip` | 항목 이름·크기·압축 크기·폴더 여부 (**내용은 풀지 않습니다**) | 200개 표시, 전체 개수 별도 |
| 문서 발췌 | `docx pptx xlsx hwpx` | 서식 없이 글자만 | 멤버 8MiB, 발췌 20,000자 |
| 정보만 | `hwp`·그 밖 | 이름·크기·형식·sha256 앞 12자·올린 사람·시각 | — |

**격리 방식**: 이미지·PDF 만 `inline` 으로 보내고, 그 응답에 `Content-Security-Policy: sandbox;
default-src 'none'` 과 `X-Content-Type-Options: nosniff`·`Cache-Control: no-store` 를 붙입니다 —
브라우저가 그 응답을 **불투명 출처**로 다루므로 PDF 안의 스크립트가 t-box 출처·쿠키·DOM 에
닿지 못합니다. 나머지 갈래는 전부 JSON 으로 받아 `textContent` 로만 그립니다(`<img onerror=…>`
같은 문자열도 글자로만 보입니다). 다운로드(F-06)의 "항상 첨부" 규칙은 그대로이고, 미리보기는
**별도 경로**(`/api/files/{id}/preview`·`/preview/raw`)입니다.

> **PDF 는 브라우저에서 실측이 필요합니다.** 토큰 없는 `sandbox` 안에서 PDF 뷰어를 띄우지 않는
> 브라우저가 있습니다. 모달 안에서 보이지 않으면 「새 탭에서 열기」를 쓰세요 — 그 응답에도 같은
> CSP 가 그대로 붙습니다. (`STAGES.md` 12단계 자기 공격 체크 항목)

### 위키 (`PRD.md` F-21 · `ARCHITECTURE.md` 5.10 · `SECURITY.md` R-56)

`/wiki` 는 이 사이트를 **어떻게 만들었나**를 초보자 말로 풀어 쓴 해설입니다. 2026-09-23 부터
**책 셋**으로 나뉘어, `/wiki` 를 열면 책 고르기 타일 셋이 먼저 나오고 눌러서 들어갑니다
(사용자 지시 「위키 접속 시 Qaredi · T-box · Community 셋을 보여 주고 골라 들어가게」).

| 책 | 주소 | 담는 것 |
|---|---|---|
| Qaredi | `/wiki/qaredi` | 사이트 전체 — 이름·런처·폴더 구조, 두 앱의 관계와 통합 기록. 단계 번호 `Q-0`·`Q-1` |
| t-box | `/wiki/tbox` | 파일 공유 — 안내 글(이 서비스는 무엇인가 · 용어 사전 · 역할과 접근 등급 · 보안 요구사항 S-01~S-11 · 남은 위험 R-xx · 어떻게 검토하나 · 2026-09-11 사고 · 문서 지도)과 단계 글. 단계 번호 정수 1~28 |
| 커뮤니티 | `/wiki/community` | 개인 업무 공간 — 블록 문서·공개 범위·이력·상태·공유. 단계 번호 `3`·`3-B`·`4-A`·`4+`(그 단계 뒤 보정) |

글 한 편은 `/wiki/{book}/{slug}` 이고, 글마다 「원문 위치」가 달려 있어 자세한 내용은 원문
문서로 이어집니다. 책이 나뉘기 전의 주소 `/wiki/{slug}` 는 t-box 책에 그 글이 있으면
`/wiki/tbox/{slug}` 로 **308**(북마크·글 속 링크가 끊기지 않게), 없으면 404 입니다.

- **원문 마크다운을 보여 주지 않습니다.** 마크다운을 HTML 로 바꾸는 파서는 HTML 을 통과시키는
  통로가 되기 쉽고(저장형 XSS), 외부 라이브러리도 쓰지 않기 때문입니다(`PRD.md` S-10-C).
  글은 `wiki/<책>/*.json` 의 **구조화된 데이터**(문단·목록·번호 목록·표·코드·말풍선·용어·원문 위치·
  글 링크·체크리스트)이고, 서버(`src/Wiki.php`)가 태그를 만듭니다.
- **글에서 온 문자열은 예외 없이** `htmlspecialchars(ENT_QUOTES | ENT_SUBSTITUTE)` 를 거칩니다
  (`PRD.md` S-03). 인라인 표기는 **백틱 한 가지**뿐이고, 그 변환도 이스케이프한 **뒤**에 합니다 —
  글에 `<script>alert(1)</script>` 가 적혀 있어도 태그가 아니라 글자로 보입니다. 백틱 개수가
  홀수면 짝이 맞지 않으므로 글자 그대로 둡니다.
- **관리자만 볼 수 있습니다**(`role:Admin`). 위키에는 남은 위험·서버 설정·사고 경위가 풀려 있어
  Guest(협력사)·Employee 가 읽으면 그대로 공격 지도가 되기 때문입니다(`SECURITY.md` R-56).
  범위를 넓히려면 라우트 네 줄(`public/index.php`)을 바꾸고 R-56 을 다시 판단합니다.
  좌측 내비의 「위키」 항목은 `GET /api/me` 의 `can_view_wiki` 가 참일 때만 열리지만, 그것은
  **편의**이고 막는 것은 라우트 정책입니다.
- **글 열람은 감사 로그에 남기지 않습니다**(`PRD.md` F-21) — 문서를 읽는 일은 보안 사건이 아니고
  개인정보도 없습니다.
- 글은 저장소 루트 `wiki/<책>/`(`wiki/qaredi/` · `wiki/tbox/` · `wiki/community/`)에 있습니다.
  **`public/` 밖이라 URL 로 직접 열 수 없고**, 서버가 읽어 그립니다. 책 이름은 고정 목록
  (`Wiki::BOOKS`)과 정확히 같을 때만 받고 경로에는 목록 쪽 글자가 들어갑니다. 글 이름(slug)은
  `^[a-z0-9][a-z0-9-]{0,39}$` 이며, 라우터 자리표시자와 `Wiki::pathFor()` 가 같은 정규식으로 두 번
  보고 `realpath` 로 `wiki/<책>/` 안인지 확인합니다. `/wiki/../x`·`/wiki/ZZ` 처럼 형태가 맞지
  않으면 라우트에 맞지 않아 **404**, 없는 책·글도 다른 404 와 **같은 문구**입니다.

**커밋 전 구조 검사** — 모르는 블록 종류·빠진 필드·범위 밖 값은 그 글을 **500** 으로 끝냅니다
(조용히 건너뛰면 반쪽짜리 글이 나오고도 아무도 모릅니다). 그 500 을 화면에서 처음 만나지
않도록 아래를 돌립니다. DB·세션 없이 `src/Wiki.php` 한 파일만 읽습니다. 세 책을 하나씩 보고,
**빠진 글**도 찾습니다 — 세 STAGES 파일의 0장 표에서 ✅ 인 단계마다 그 책에 같은 번호의 단계
글이 있어야 합니다(예외는 스크립트의 `WIKI_MISSING_EXCEPTIONS` 에 이유와 함께).

```bash
php scripts/wiki_check.php
# == 위키 구조 검사 : /var/www/qaredi/tbox-v2/wiki ==
#
# -- 책 qaredi --
# 글 파일 3개, 차례 항목 3개
# -- 책 tbox --
# 글 파일 30개, 차례 항목 30개
# -- 책 community --
# 글 파일 12개, 차례 항목 12개
#
# -- 빠진 글 검사 (STAGES 0장 ✅ × 위키 단계 글) --
#   …
# 책 3권 · 글 파일 45개 · 차례 항목 45개
#
# 결과: 통과 (구조 문제 0건 · 빠진 글 0건, 글 45편)
#   (글 수는 2026-09-23 실행 기준 — 글이 늘면 달라진다)
#   문제(구조·빠진 글·같은 단계 번호 둘·wiki/ 바로 아래 남은 *.json)가 0건이면 종료 코드 0, 있으면 1
#   경고(차례에 없는 글·링크 대상 없음·표 칸 수 불일치)는 화면이 뜨므로 종료 코드에 넣지 않습니다
```

### 내 활동 (`PRD.md` F-12 · `ARCHITECTURE.md` 5.11)

`/activity` 는 **내가 한 일만** 최근 순서로 보여 주는 화면입니다. 좌측 내비의 「내 활동」은
역할과 상관없이 **모든 로그인 사용자에게 보입니다** — 자기 이력은 누구나 볼 수 있습니다.

- **대상은 언제나 세션 본인입니다.** 서버 SQL 의 조건이 `actor_id = 세션 본인`으로 고정돼 있고,
  요청에서 대상을 받지 않습니다. 주소에 `?user_id=1`·`?actor=admin01` 을 붙여도 **읽지 않으므로**
  결과가 달라지지 않습니다(`PRD.md` S-02, T-33). 요청 파라미터는 `page` 하나뿐입니다.
- **IP·기기 정보(User-Agent)·상세(detail)는 보이지 않습니다** — 본인 것이라도 그렇습니다.
  응답에서 지우는 것이 아니라 **SELECT 자체에 넣지 않습니다**: 응답에 없으면 새지 않습니다.
  (관리자의 감사 로그 화면 `/audit` 에는 있습니다. 그쪽은 조사용이고 `audit.view` 로 기록됩니다.)
- 보이는 것은 **시각 · 요약 · 결과** 세 칸이고, 20건씩 넘겨 봅니다. 보이는 행동은 파일(올리기·
  받기·미리보기·수정·삭제·복구·URL 가져오기)·공유 링크(만들기·회수)·계정(로그인·로그아웃·
  비밀번호 변경·2단계 인증 켜기/끄기)입니다 — 코드에 적힌 **고정 목록**이며 요청이 고르지 못합니다.
- **이 화면을 보는 것 자체는 감사 로그에 남지 않습니다**(`PRD.md` F-12) — 자기 이력 열람은
  보안 사건이 아니기 때문입니다.

### 공유 링크 (`PRD.md` F-13 · `ARCHITECTURE.md` 5.12 · `SECURITY.md` R-57)

파일 하나를 **로그인 없이** 토큰만으로 받는 주소 `https://…/s/{토큰}` 을 만듭니다.
사내망·VPN 안에서만 열립니다 — 인터넷 공개는 여전히 비목표입니다(`PRD.md` NG-4, Q-5).

| 항목 | 규칙 |
|---|---|
| 만들 수 있는 사람 | **그 파일을 고칠 수 있는 사람**(Admin 전부 · Manager 본인·자기 팀 · Employee 본인 · Guest 불가). 파일 목록에서 「수정」 단추가 보이는 행에만 「공유 링크」 단추가 있습니다 |
| 만료 | 기본 24시간, **최대 7일**(1~168시간). 앱이 보고 DB `CHECK` 가 한 번 더 봅니다 |
| 횟수 | 기본 1회, 최대 10회. 받을 때마다 1씩 오르고 다 쓰면 그 링크는 끝입니다 |
| 회수 | **만든 사람 또는 관리자**. 「내 계정」 → 「내 공유 링크」에서 누릅니다. 행은 지우지 않고 `revoked_at` 만 채웁니다(추적을 위해) |
| 실패 | 없음·만료·회수·소진 **전부 404 「찾을 수 없습니다」 한 문구**입니다. 어느 쪽으로 막혔는지는 감사 로그에만 남습니다 |
| 기록 | `share.create`·`share.revoke`·`share.download`(allow/deny). 받는 쪽은 로그인한 사람이 없으므로 **누가 열어 줬나(발급자)·어느 링크인가·남은 횟수**가 상세에 남습니다 |

> ### ★ 주소는 만들 때 한 번만 보입니다
> 서버는 토큰의 **sha256 만** 갖고 있습니다(세션 쿠키와 같은 방식). 원문은 만든 직후 응답에
> 한 번 나오고 그 뒤에는 서버도 모릅니다 — 「내 공유 링크」 목록에도 주소가 없습니다.
> 창을 닫기 전에 「복사」로 옮겨 두고, 잃어버렸으면 **다시 만드세요**(옛 링크는 회수하고).
> DB 가 통째로 새어도 그 값으로는 링크를 되살릴 수 없습니다.

**주의**: 주소를 받은 사람은 **누구나**(사내망 안에서) 그 파일을 받습니다. 메신저·메일로 전달되는
순간 그 경로가 곧 공격면입니다(`SECURITY.md` R-57). 그래서 기본값이 **1회·24시간**이고, 다 쓴
링크는 회수해 두는 편이 안전합니다. `/s/` 경로에는 IP 단위 속도 제한(분당 60회)이 걸려 있습니다.

### 민감정보 검출 (`PRD.md` F-22 · `ARCHITECTURE.md` 5.13 · `SECURITY.md` R-58)

파일을 올릴 때(그리고 URL 로 가져올 때) **형식 검사 뒤·저장 전에** 내용을 한 번 살펴봅니다.

- 찾는 것 세 가지: ① **주민등록번호**(형태 + 뒷자리 첫 숫자 1~4 + 검증 숫자) ② **카드번호**
  (13~19자리 + Luhn 검사) ③ **키워드**(`급여`·`연봉`·`주민번호`·`계좌번호`·`여권번호` — 코드 상수).
  ①②는 형태만 보지 않고 **계산까지 맞아야** 셉니다 — 그냥 13자리 숫자는 걸리지 않습니다.
- 하나라도 보이면 `public`·`internal` 로는 **올릴 수 없습니다**(400 「민감정보가 보여 team 또는
  admin-only 로만 올릴 수 있습니다」). `team`·`admin-only` 로는 올라가고, 목록의 파일명 옆에
  **「민감」 배지**가 붙습니다. 그 뒤 **등급을 낮추는 변경도 거부**됩니다(관리자도 같습니다).
- **검출된 값은 어디에도 남기지 않습니다.** 감사 로그에 남는 것은 패턴 **이름과 건수**뿐입니다
  (`{"rrn":1}`). 화면 문구에도 숫자가 나오지 않습니다(`PRD.md` S-07).

> ### ★ 한계 — 검출은 보조 장치입니다 (`SECURITY.md` R-58)
> 검사는 **미리보기가 글자를 뽑을 수 있는 형식**(txt·md·csv·docx·pptx·xlsx·hwpx)만 봅니다.
> **이미지·PDF·암호가 걸린 zip·스캔해 찍은 문서는 검사하지 못합니다.** 반대로 우연히 검증
> 숫자가 맞는 숫자열을 잘못 짚기도 합니다(오탐). 그러므로 「민감」 배지가 없다고 안전한 것이
> 아니고, **접근 등급을 고르는 책임은 올리는 사람에게 있습니다.** 같은 문구가 업로드 화면에도
> 있습니다 — "검출기가 있으니 등급은 대충" 이 되면 오히려 위험이 커집니다.

### 악성코드 검사 (`PRD.md` F-54 · `ARCHITECTURE.md` 5.28 · `SECURITY.md` R-02 · R-86)

올라온 파일은 **바로 받을 수 있는 상태가 아닙니다.** 저장되는 순간에는 「검사 중」이고,
1분마다 도는 검사 배치가 백신(ClamAV)으로 훑은 뒤에야 내려받기가 열립니다. 「검사 중」 동안에는
다운로드·미리보기·공유 링크가 모두 막히고(「검사 중입니다. 잠시 뒤 다시 시도하세요」), 보통
**1~2분**이면 끝납니다. 악성코드가 나오면 그 파일은 **「격리됨」**이 되어 아무도 받지 못하고,
바이트는 서버의 격리 폴더로 옮겨집니다(지우지 않습니다 — 나중에 무슨 일이 있었는지 확인하기
위한 증거입니다). 목록의 파일명 옆에 **「검사 중」(회색)·「격리됨」(빨강)** 배지가 붙고, 그동안
그 행의 다운로드·미리보기 단추는 눌리지 않습니다. 격리가 일어나면 **관리자에게 즉시 경보**가
갑니다(AL-19) — 올린 사람의 PC 를 점검하라는 뜻입니다.

> ### ★ 한계 — 백신은 **알려진 것만** 잡습니다 (`SECURITY.md` R-86)
> ClamAV 는 이미 알려진 악성코드의 **시그니처**와 맞춰 볼 뿐입니다. 새로 만든 악성코드,
> 특정 회사를 노리고 만든 문서, **암호가 걸린 zip 속**은 잡지 못합니다. 그러므로 이 검사는
> **직원 PC 의 백신을 대신하지 않습니다.** 받은 파일은 내 PC 의 백신이 한 번 더 보는 것이
> 맞고, 「격리됨」이 없다고 해서 안전이 보장된 것은 아닙니다. 반대로 정상 파일이 잘못
> 걸리는 일(오탐)도 있으며, 그때 푸는 창구는 화면에 없습니다 — 관리자에게 알리면 서버에서
> 확인합니다.

### 실행 파일이 든 압축본 (`PRD.md` F-65 · `ARCHITECTURE.md` 5.29 · `SECURITY.md` R-94)

zip 안에 `.php`·`.sh`·`.exe` 같은 **실행 파일**이 하나라도 있으면 t-box 는 그 압축본을 받지
않습니다. 막는 이유는 서버가 위험해서가 아니라 **직원 PC 로 배달되는 것**을 막기 위해서입니다.
다만 관리자가 **자기가 만든 것이 맞고 내용을 안다**고 밝히는 경우에 한해 길이 하나 열립니다 —
`admin-only` 등급으로, 웹 화면에서, 확인란에 체크하고, **그 요청마다** 비밀번호와 2단계 인증
코드를 다시 넣어야 합니다(로그인한 상태여도 매번 묻습니다 — 쿠키만 훔친 사람은 코드를 만들 수
없기 때문입니다). 올리기 창에서 그런 압축본을 고르면 파일 줄 아래에 **무엇이 걸렸는지(항목
이름)** 와 확인란·비밀번호·코드 칸이 펼쳐집니다. 관리자가 아니거나 다른 등급으로 올리면
지금까지처럼 「잘못된 요청입니다」로 끝나고, 프로그램 토큰·URL 가져오기로는 아예 열리지
않습니다.

그렇게 올라온 파일은 목록에 **「실행 파일 포함」** 배지가 붙고 **그때부터 계속 그렇게 다뤄집니다**:
공유 링크를 만들 수 없고, 프로그램 토큰으로 받을 수 없고, 미리보기가 열리지 않으며, 접근 등급도
바꿀 수 없습니다(`admin-only` 고정). 받을 때도 다운로드 단추가 **확인 창**을 열어 올린 사람·올린
날짜·경고를 보여 주고 **비밀번호와 2단계 코드를 다시** 묻습니다. 이 업로드가 일어나면 관리자
전원에게 **즉시 경보**가 갑니다(AL-21). 백신 검사(ClamAV)는 이 파일에도 그대로 돕니다.

> **막지 못하는 것** — 관리자가 **알고도** 악성 묶음을 올리거나 받는 경우, 그리고 관리자
> PC 자체가 감염돼 본인이 직접 코드를 치는 경우입니다(`SECURITY.md` R-94). 받은 압축본은
> 내 PC 의 백신으로 한 번 더 보고, 보낸 사람과 용도를 모르면 열지 마세요.

### 프로그램 토큰 — 내 계정에서 본인이 발급합니다 (`PRD.md` F-66 · `ARCHITECTURE.md` 4.7 · `SECURITY.md` R-97)

PC 프로그램(업로드 도구, 로컬 비서 등)이 t-box 를 부를 때 쓰는 토큰은 **본인이** 「내 계정」
화면의 **「프로그램 토큰」** 절에서 만듭니다. 전에는 관리자가 남의 것까지 만들 수 있었는데,
그 길을 없앴습니다 — 관리자 화면을 훔친 사람이 아무 계정의 자격을 만들어 두는 것을 막기
위해서입니다. 관리자는 남의 토큰을 **보고 회수**할 수는 있지만 만들지는 못합니다.

만들 때 세 가지를 함께 정합니다.

- **이름과 용도** — 어느 프로그램에 심었는지 나중에 알아보기 위한 것이고, 감사 기록에 함께 남습니다.
- **범위** — 「읽기만」 · 「읽기 + 올리기」 · 「읽기 + 올리기 + 지우기」 중 하나. 프로그램에 필요한
  만큼만 고르면, 그 토큰이 새어도 나머지는 닫혀 있습니다. **계정 권한보다 넓은 범위는 고를 수
  없습니다**(올릴 수 없는 역할은 「읽기만」뿐). 범위는 창구를 좁힐 뿐이고, 파일 하나하나를
  받을 수 있는지·지울 수 있는지는 지금처럼 요청마다 다시 판단합니다.
- **현재 비밀번호와 2단계 인증 코드** — 발급 요청마다 넣습니다. 로그인한 상태여도 매번 묻습니다
  (쿠키만 훔친 사람은 코드를 만들 수 없기 때문입니다). 그래서 **2단계 인증을 켜지 않은 계정은
  발급할 수 없고**, 그때는 폼 대신 「2단계 인증을 켜야 발급할 수 있습니다」가 보입니다.

토큰 값은 **발급 직후 한 번만** 보입니다 — 서버에는 지문(sha256)만 남아 다시 보여 줄 방법이
없습니다. 그 자리에서 복사해 프로그램에 심고, 잃으면 회수하고 새로 발급하세요.

**180일이 지나면 만료됩니다.** 만료된 토큰으로 부르면 프로그램은 「만료된 API 토큰입니다 — 내
계정에서 새로 발급하세요」를 받습니다(틀린 토큰과 다른 문구입니다 — 무엇을 하면 되는지 알려
주려고 일부러 갈랐습니다). 만료가 14일 안으로 다가오면 「내 계정」 화면 위에 안내가 떠서
미리 바꿔 심을 수 있습니다. 계정당 살아 있는 토큰은 **5개**까지입니다.

> 토큰 발급은 한 건만 있어도 관리자 전원에게 **즉시 경보**가 갑니다(AL-20) — 토큰은 2단계 인증
> 없이 그 계정의 권한으로 움직이는 자격이라, 드문 일을 드물게 알리는 것이 마지막 그물입니다.
> 창구별로 어떤 범위가 필요한지는 `API.md` 0장·13장에 있습니다.

### 재인증 — 관리 기능을 쓰기 전에 비밀번호를 한 번 더 (`PRD.md` F-23 · `ARCHITECTURE.md` 4.0 · `SECURITY.md` R-59)

**계정 관리 · 조직·권한 · 감사 로그 · 휴지통 · 위키**는 로그인만으로 열리지 않습니다.
그 영역에 들어갈 때 **비밀번호를 한 번 더** 확인하고, 확인한 창은 **15분** 동안만 열려 있습니다
(GitHub·AWS 의 "sudo 모드" 와 같은 방식).

- **로그인 직후에도 한 번은 묻습니다.** 로그인은 이 창을 열지 않습니다 — 자리를 비운 사이의
  브라우저나 새어 나간 세션 쿠키만으로는 관리 기능에 닿지 못하게 하는 것이 목적입니다.
- 화면에서 관리 메뉴를 누르면 **`/reauth` 화면**(비밀번호 한 칸)으로 가고, 확인하면 원래 가려던
  화면으로 돌아갑니다. 화면을 열어 둔 채 15분이 지나면 그 자리에서 **작은 창(모달)** 이 떠서
  다시 묻고, 확인하면 막혔던 요청이 다시 나갑니다.
- 확인은 **그 기기, 그 창(세션)** 에만 적용됩니다. 다른 기기의 로그인에는 영향이 없습니다.
- **재인증은 권한을 만들지 않습니다.** Employee 가 비밀번호를 맞혀도 `/users` 는 그대로 403 입니다
  (막는 순서가 "권한 확인 → 재인증 확인" 이기 때문입니다).
- 비밀번호를 틀리면 **로그인과 같은 카운터**로 셉니다 — 5회면 계정이 10분 잠기고 그 계정의 모든
  세션이 끊깁니다(`SECURITY.md` R-48). 맞히면 카운터는 0 으로 돌아갑니다.
- 2단계 인증 코드는 다시 묻지 않습니다(로그인에서 이미 거쳤습니다). 「내 계정」의 비밀번호 변경·
  2단계 인증 창구(`/api/me/*`)와 파일 기능은 **재인증과 무관**하게 그대로 씁니다.

```bash
# 직접 확인 (Admin 계정으로 로그인한 뒤)
curl -s -b jar http://127.0.0.1:8082/tbox/api/users
# → 403 {"error":"관리 기능을 쓰려면 비밀번호를 다시 확인해야 합니다","next":"reauth"}
curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' -b jar http://127.0.0.1:8082/tbox/users
# → 302 /reauth?to=users     (돌아갈 곳은 고정 표의 키 다섯 개뿐입니다 — 주소를 요청 값으로 받지 않습니다)
```

최초 로그인 강제 절차(`PRD.md` F-16)는 **파일 화면(`/`)에만** 있습니다. 절차가 남은 계정이
다른 화면을 열면 서버가 `/` 로 **302** 를 보내고(그 시도는 `auth.gate|deny` 로 남습니다),
API 요청은 예전과 같이 **403 `{"next":…}`** 입니다.

### 관리자 영역 — 관리 기능의 단일 입구 (`PRD.md` F-24 · `ARCHITECTURE.md` 5.14)

관리자에게만 왼쪽 메뉴에 「**관리**」 묶음이 보이고, 그 안의 일곱 항목(관리자 페이지 · 계정 관리 ·
조직·권한 · 권한 매트릭스 · 감사 로그 · 휴지통 · 위키)으로 각 화면에 들어갑니다. 허브(`/admin`)의
카드로도 같은 곳에 갑니다 — 두 길의 **주소도 권한도 같습니다**.

> 26단계 전에는 메뉴에 「관리자 페이지」 하나뿐이어서, 카드로 들어간 뒤에는 뒤로가기 말고
> 돌아올 길이 없었습니다. 또 관리 화면이 재인증을 물으면 왼쪽 메뉴가 통째로 닫히는 문제가
> 있었습니다(재인증을 「최초 로그인 강제 절차」와 같이 취급했기 때문입니다). 둘 다 고쳤습니다.

- **일반 화면의 메뉴에는 관리 항목이 없습니다.** 관리자가 아닌 계정의 화면에는 「관리자 페이지」도
  보이지 않습니다. (메뉴를 개발자도구로 되살려도 `/admin` 은 **403** 입니다 — 막는 것은 메뉴가
  아니라 서버의 라우트 정책입니다.)
- 기존 주소(`/users` · `/org` · `/audit` · `/trash` · `/wiki`)는 **그대로** 살아 있습니다.
  문서와 위키가 그 주소를 가리키기 때문입니다 — 없어진 것은 메뉴 항목이지 주소가 아닙니다.
- 허브에는 카드 외에 **공유 링크 전체**(누가 어떤 파일의 링크를 발급했고 지금 상태가 무엇인지 —
  토큰은 저장하지 않으므로 여기에도 없습니다)와 **최근 경보 50건**(`/var/log/tbox-v2/alerts.log`
  를 읽기만 합니다), 그리고 **재인증 상태**가 함께 나옵니다.
- 관리자 영역도 **재인증 15분 창**(F-23)을 그대로 지납니다. 들어갈 때 비밀번호를 한 번 더 묻고,
  창이 닫히면 `/reauth?to=admin` 으로 보냅니다.

#### 역할로 보기 — 다른 역할의 눈으로 확인하기 (`PRD.md` F-39 · `ARCHITECTURE.md` 5.20)

관리자 페이지의 「**역할로 보기**」 카드에서 역할(Manager · Employee · Guest)과 팀을 고르고
「이 역할로 보기」를 누르면, **그 순간부터 서버가 여러분을 그 역할로 판정합니다.**
화면만 흉내 내는 것이 아닙니다 — 파일 목록에서 볼 수 없는 등급이 실제로 빠지고,
남의 파일 삭제는 403 이 됩니다. 「보이는 것」과
「할 수 있는 것」이 어긋나지 않게 하려는 장치입니다.

- **아래로만 갑니다.** 고를 수 있는 역할에 Admin 이 없고, 보는 중에는 다시 켤 수도 없습니다
  (먼저 「원래대로」를 눌러야 합니다). 켤 때는 비밀번호를 한 번 더 확인합니다.
- **실제 계정은 바뀌지 않습니다.** 보는 역할은 그 브라우저의 그 로그인에만 붙고(서버의 세션 행),
  로그아웃하면 사라집니다. 다른 기기의 로그인에는 영향이 없습니다.
- **화면 맨 위에 띠**가 나옵니다 — 「지금 Employee · 영업팀 · 검토(부평점) 으로 보는 중 —
  실제 계정 admin01(Admin)」 과 「원래대로」 단추. 보는 동안에는 「관리」 묶음이 닫히므로
  이 띠가 돌아오는 길입니다.
- **활동이 없으면 30분 뒤 저절로 풀립니다.** 쓰는 중에는 끊기지 않습니다. 그 사이에 관리자
  권한을 잃으면(강등) 다음 요청에서 바로 풀립니다.
- **기록은 사람으로 남습니다.** 감사 로그의 「누가」는 언제나 실제 계정과 실제 역할이고,
  「어떤 역할로 보였나」는 상세(`acting_as`)에 함께 남습니다.

```bash
# 관리자 세션 (재인증을 마친 뒤)
curl -s -X POST -b jar-admin -H 'Content-Type: application/json' -H "X-CSRF-Token: $TOK" \
     -d '{"role":"Employee","team_id":1}' http://127.0.0.1:8082/tbox/api/me/act
# → 200, 응답은 /api/me 와 같은 모양 ("role":"Employee","acting":true,"real_role":"Admin")
curl -s -X POST -b jar-admin -H 'Content-Type: application/json' -H "X-CSRF-Token: $TOK" \
     -d '{"role":"Admin"}' http://127.0.0.1:8082/tbox/api/me/act      # → 400 (위로는 갈 수 없습니다)
curl -s -X DELETE -b jar-admin -H "X-CSRF-Token: $TOK" http://127.0.0.1:8082/tbox/api/me/act   # → 원래대로
```

```bash
# 비관리자 세션
curl -s -b jar-employee http://127.0.0.1:8082/tbox/admin           # → 403 {"error":"권한이 없습니다"}
curl -s -b jar-employee http://127.0.0.1:8082/tbox/api/admin/shares # → 403 (시도는 authz.route|deny 로 남습니다)
# 관리자 세션, 재인증 전
curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' -b jar-admin http://127.0.0.1:8082/tbox/admin
# → 302 /reauth?to=admin
```

### 권한 매트릭스 편집 (`PRD.md` F-25 · `ARCHITECTURE.md` 5.15 · `SECURITY.md` R-60)

역할 × 접근 등급 표(`permissions` 16행)를 `/admin/permissions` 화면에서 바꿉니다.
**이 표를 바꾸는 것은 보안 정책을 바꾸는 것**이라, 다섯 가지가 **전부** 있어야 바뀝니다.

| 조건 | 무엇을 확인하나 |
|---|---|
| ① 관리자 + 재인증 | 라우트 정책 `role:Admin` + 15분 창 (F-23) |
| ② 2단계 인증 코드 | **요청마다** 새 코드. 한 번 쓴 코드는 다시 못 씁니다(`code_reused`) |
| ③ 사유 | 필수 1~500자. 감사 로그에 그대로 남습니다 |
| ④ 서버 불변 규칙 | 아래 표 |
| ⑤ 별도 DB 계정 | 쓰기는 `tbox_perm`(그 표에 SELECT·UPDATE 만) 으로만. 앱 계정 `tbox_app` 은 **여전히 읽기만** |

바꿀 수 없는 것(서버가 400 으로 막고 `permission.change deny invariant` 로 남깁니다)

- **관리자(Admin) 행 네 칸은 전부 켜진 채 고정** — 관리자가 스스로를 잠글 수 없습니다.
- **「올리기」를 켜려면 같은 칸의 「읽기」도 켜져 있어야** 합니다.
- **손님(Guest)의 관리자(admin-only) 칸은 꺼진 채 고정**입니다.
- 역할·등급은 4×4 안의 값만, 그리고 **실제로 바뀌는 칸이 0개인 요청**도 거부합니다.

화면에서는 잠긴 칸이 흐리게(체크 불가) 보이고 이유가 툴팁으로 뜹니다. 「적용」 전에
**변경 미리보기**(`Guest · internal : 읽기 아니오 → 예`)로 무엇이 바뀌는지 확인합니다.

바뀐 뒤

- **효과는 다음 요청부터**입니다 — 이미 로그인해 있는 사람에게도 즉시 적용됩니다
  (권한 표를 요청마다 읽기 때문입니다).
- **칸마다 한 줄**씩 감사 로그 `permission.change allow` 에 이전값 → 새값·사유가 남습니다.
- 경보 **AL-13** 이 **건수와 무관하게 즉시** 울립니다(정상 작업이어도 알립니다).

왜 앱 계정으로 바꾸지 않나 — 앱의 어느 한 곳에 결함(SQL 인젝션 등)이 생겨도 권한 표는 못 바꾸게
하려는 것입니다. 확인은 이렇게 합니다:

```bash
sudo -u postgres psql -d tbox_re -c '\dp permissions'
#  tbox_app=r/tbox_owner     ← 읽기만
#  tbox_perm=rw/tbox_owner   ← 이 계정만 쓰기 (다른 표 권한은 0)
sudo -u postgres psql -d tbox_re -c "SET ROLE tbox_app; UPDATE permissions SET can_read=can_read WHERE false;"
# → ERROR:  permission denied for table permissions
```

`tbox_perm` 의 비밀번호는 `deploy/install.sh` 가 만들어 `.env` 의 `DB_PERM_USER`·`DB_PERM_PASS`
두 줄에 넣습니다(예시는 `.env.example` 의 주석만). 두 줄이 없으면 **매트릭스 편집 요청만**
500 이 되고 나머지 기능은 정상입니다.

### URL 가져오기 허용 사이트 (F-43)

- 관리자 페이지 → 「URL 가져오기 허용 사이트」에서 호스트 이름을 넣고 뺀다(비밀번호 재확인 · 사유 · 인증 앱 코드). https 만, 정확한 호스트 이름만(와일드카드·IP 금지), 사내망 주소는 넣어도 서버가 거부한다. 목록이 비면 홈의 「URL 로 가져오기」 단추가 보이지 않는다.
- 구글 드라이브·OneDrive 는 「링크가 있는 모든 사용자」로 공개된 문서만 가져올 수 있다(공유 링크를 그대로 붙이면 된다). 필요한 호스트: `drive.google.com` `drive.usercontent.google.com` `docs.google.com` / `1drv.ms` `onedrive.live.com`. 로그인이 필요한 문서는 내려받아 올린다.

### 관리자 영역을 관리망에서만 (선택, 기본 꺼짐) (`SECURITY.md` R-61)

`/admin` 과 `/api/admin` 을 **특정 IP 대역에서만** 열 수 있습니다. nginx 사이트 파일
(`deploy/sites/tbox-v2.conf` · `tbox-v2-local.conf`)에 그 블록이 **주석 상태**로 들어 있습니다.

**기본은 꺼짐입니다.** 이 서비스의 접속 출처가 셋(사내망 두 대역 · 프록시 경유 외부)이라,
자기 출처를 빠뜨린 채 켜면 **관리자 자신이 관리자 영역에서 잠깁니다**
(`SECURITY.md` 8.4-16 의 관리망 기본값 사고와 같은 함정입니다).

켜는 순서

1. **지금 내 출처를 먼저 확인합니다** — 여기가 핵심입니다.
   ```bash
   sudo tail -n 50 /var/log/nginx/tbox-v2.access.log   # 첫 칸이 (프록시가 복원한) 실제 IP
   ```
   이 VM 은 리버스 프록시 뒤에 있어 `set_real_ip_from` 이 복원한 주소가 기준입니다 —
   **프록시 IP 를 allow 에 적으면 안 됩니다**(그러면 모든 외부 접속이 통과합니다).
2. `deploy/sites/tbox-v2.conf` 의 `# location ^~ /admin { … }` 두 블록에서 주석을 풀고
   `allow` 줄을 ①에서 확인한 대역으로 바꿉니다. `deny all;` 은 마지막에 그대로 둡니다.
3. 반영합니다.
   ```bash
   sudo bash deploy/switch-site.sh v2   # 사이트 파일 설치
   sudo nginx -t && sudo systemctl reload nginx
   ```
4. **로그인한 창을 닫지 말고** 다른 창에서 `/admin` 접속을 확인합니다. 막히면 ②를 되돌리고
   다시 reload 합니다.

끄면(기본) 관리자 영역을 막는 겹은 **라우트 정책 `role:Admin` 과 재인증 15분 창** 둘입니다 —
네트워크 겹은 그 위에 더하는 세 번째 겹이지 대체가 아닙니다.

## 버전과 변경 이력 (`PRD.md` F-47 · `ARCHITECTURE.md` 5.23)

| 무엇 | 어디 |
|---|---|
| 지금 버전 | 저장소 루트 `VERSION` 한 줄 · 로그인한 화면 왼쪽 아래 `v1.0.0` |
| 변경 이력 | `CHANGELOG.json`(진실) → `CHANGELOG.md`(생성) · 화면에서는 왼쪽 아래 버전 번호를 누르면 **「변경 이력」 창** |
| 깃 | 발행마다 태그 `vX.Y.Z`, 원격에도 push — `git tag -l` · `git describe --tags` |

번호 규칙 `X.Y.Z` — **X 대규모**(뽐낼 만한 업데이트) · **Y 중규모**(공치사 정도) · **Z 버그 수정 등 작은 것**. 위 자리가 오르면 아래는 0.

발행은 한 번에:

## 설치 · 실행

실습 VM(Ubuntu 22.04 · PHP 8.1 · PostgreSQL 14 · nginx 1.18) 기준입니다. 설정 내용은 `ARCHITECTURE.md` 3장 배포 메모와 8·9·10장 그대로입니다.


PostgreSQL 역할·DB·스키마·최소 권한, 설정 파일 `.env`(저장소 루트) 생성(`APP_SECRET` 포함), **시드 계정 5개**,
php-fpm 풀(`/etc/php/8.1/fpm/pool.d/tbox.conf`), nginx 사이트 파일 설치와 로컬 포트 enable,

백업 디렉터리 `/var/backups/tbox-v2`(0700 root), cron 일정 `/etc/cron.d/tbox-v2`, logrotate 설정.
**도메인에 공개 중인 버전은 바꾸지 않습니다** — 그건 2)의 몫입니다. (TLS 인증서는 만들지 않습니다. 아래 "왜 80 포트인가" 참고.)

**커뮤니티 스키마는 `install.sh` 가 만들지 않습니다.** 새로 설치할 때는 1) 뒤에 아래 세 줄을 이 차례로 돌립니다.
`db/community/schema.sql` 이 지금 커뮤니티 모양 전부이고(3단계 마이그레이션 `2026-09-22_community_stage3.sql` 은 이 파일을 `\ir` 로 읽는 껍데기),
`grants.sql` 은 REVOKE 뒤 GRANT 라 여러 번 돌려도 같습니다. **그다음 아래 마이그레이션을 전부 돌립니다** — `schema.sql` 둘에 없고
마이그레이션으로만 들어오는 것이 셋 있습니다(2026-09-26 확인): 휴대폰 경보 표(`2026-09-30_f70_push.sql`) · 커뮤니티 휴지통 영구 삭제 함수
`community.purge_trash`(`2026-09-26_community_purge.sql`) · `community.page_versions.created_at`(`2026-09-23_community_version_squash.sql`).

저장소 폴더(`/var/www/tbox-v2`)에서 칩니다 — postgres 계정이 상대 경로 `db/…` 를 읽습니다.

```bash
sudo -u postgres psql -d tbox_re -v ON_ERROR_STOP=1 -c 'CREATE SCHEMA IF NOT EXISTS community AUTHORIZATION tbox_owner;'
sudo -u postgres psql -d tbox_re -v ON_ERROR_STOP=1 -c 'SET ROLE tbox_owner' -f db/community/schema.sql   # 표 주인은 tbox_owner(SET ROLE 은 -f 까지 이어진다)
sudo -u postgres psql -d tbox_re -v ON_ERROR_STOP=1 -f db/community/grants.sql
```

**이미 돌고 있는 DB 에는 마이그레이션이 따로 필요합니다.** `install.sh` 는 표가 이미 있으면 `schema.sql` 을 건너뛰므로,
나중에 더해진 칸·표는 `db/migrations/*.sql` 로 들어옵니다. `install.sh` 는 무엇이 빠졌는지 알려 주기만 하고(4-4-1 확인 목록)
**자동으로 적용하지는 않습니다**(운영 DB 에 DDL 을 몰래 거는 스크립트를 만들지 않습니다).

- **파일 이름 차례로** 적용합니다. 이미 들어간 것은 표·칸을 다시 만들지 않게 쓰여 있습니다 — 2026-09-26 확인: 새로 설치한 임시 DB 에
  `db/migrations/*.sql` 을 전부 다시 돌려 오류 0, 모양(`pg_dump -s`)이 운영과 같음(칸 순서 다섯 곳만 다름 — 운영은 뒤에 붙였으므로).
  **예외 하나**: `2026-09-22_community_stage3.sql` 은 커뮤니티 표를 처음 만드는 파일이라 표가 있으면 멈춥니다 — 새 설치(위 세 줄)에서는 건너뜁니다.
  몇 파일은 데이터 조건에 맞는 행만 고치는 `UPDATE` 가 있습니다(예: `2026-09-11_users_first_login.sql`) — 다시 돌려도 오류는 없지만 「아무 일도 없음」은 그때 데이터에 따라 다릅니다.

```bash
cd /var/www/tbox-v2
for f in db/migrations/*.sql; do
  case "$(basename "$f")" in
    2026-09-22_community_stage3.sql) continue ;;                          # 새 설치는 위 세 줄이 대신한다
    2026-09-29_app_role_timeouts.sql|2026-09-30_f70_push.sql) role='' ;;  # 역할을 만들거나 바꾼다 — postgres 그대로
    2026-09-12_share_links.sql|2026-09-13_folders.sql|2026-09-16_api_tokens.sql|2026-09-17_fetch_hosts.sql|2026-09-22_api_tokens_scope_expiry.sql)
      role='' ;;                                                          # 운영에서 이 표들의 주인이 postgres(아래 참고) — tbox_owner 로는 못 고친다
    *) role='SET ROLE tbox_owner' ;;                                      # 표 주인 = tbox_owner
  esac
  sudo -u postgres psql -d tbox_re -v ON_ERROR_STOP=1 ${role:+-c "$role"} -f "$f" || { echo "멈춤: $f"; break; }
done
```

  이 루프는 새 설치 임시 DB 와 운영 모양(운영 `pg_dump -s` 를 부은) 임시 DB 양쪽에서 끝까지 오류 0(2026-09-26). 「멈춤:」 이 찍히면 그 파일부터 원인을 보고 다시 돈다.
- **운영 DB(tbox_re) 는 반영 스크립트로만** 바꿉니다 — `/var/www/qaredi/scripts/apply-*-db-*.sh` 가 기준 판 확인 · 마이그레이션 · 채우기 배치 · 확인을 한 번에 하고 실패하면 되돌립니다.
- **검색 색인 채우기** — 마이그레이션은 칸만 만듭니다. **파일**은 칸이 비어도 결과는 같고 느린 길을 탈 뿐이지만(목록이 빈 칸도 찾는다), **페이지·댓글**의 한글 검색은 색인만 보므로 채우기 전까지 **빈 칸 댓글과 옛 규칙으로 색인된 페이지가 결과에서 빠집니다** — 미루지 말고 마이그레이션 바로 뒤에 돌립니다. 앱 계정으로(`.env` 를 그룹으로 읽는 `tbox-php` — 반영 스크립트도 이 모양):

```bash
cd / && sudo -u tbox-php php /var/www/tbox-v2/scripts/qf2_backfill_search.php --dry-run   # 2026-10-01_qf2_search.sql 뒤 — 페이지·댓글(바꿀 행 수만)
cd / && sudo -u tbox-php php /var/www/tbox-v2/scripts/qf2_backfill_search.php
cd / && sudo -u tbox-php php /var/www/tbox-v2/scripts/qf2b_backfill_files.php --dry-run   # 2026-10-02_qf2b_files_search.sql 뒤 — 파일 이름·설명
cd / && sudo -u tbox-php php /var/www/tbox-v2/scripts/qf2b_backfill_files.php             # 끝나면 --dry-run 이 「바꿀 0」 이어야 한다
```

- 역할에 닿는 것: `2026-09-29_app_role_timeouts.sql`(표·칸 없이 tbox_app 역할 설정만 — 문장 15초·유휴 60초 · 클러스터 공용) · `2026-09-30_f70_push.sql`(휴대폰 경보 표 둘 **과** 보내는 역할 tbox_push — 운영은 `apply-f70-host-2026-09-24.sh` 가 OS 계정·키와 함께).
- 참고(2026-09-26 실측): 운영의 `api_tokens`·`fetch_hosts`·`folders`·`share_links`(와 그 시퀀스)는 소유가 `postgres`(그때 postgres 로 마이그레이션을 돌림), 새 설치는 `tbox_owner` 입니다. 앱 계정 권한(`tbox_app`·`tbox_backup`)은 같습니다 — 이 넷을 고치는 마이그레이션은 `tbox_owner` 가 아니라 postgres 로 돌려야 합니다.

**멱등합니다.** 두 스크립트 모두 여러 번 실행해도 안전하고, 이미 있는 저장소 루트 `.env` 의 비밀번호는 바꾸지 않습니다.
운영 전환 검토용으로 옮겨 두었던 `/etc/tbox-v2/tbox.env` 가 남아 있으면 값을 그대로 보존해 저장소 루트 `.env` 로 **되돌려 옮깁니다**(`mv`).
패키지는 설치하지 않습니다 — 없으면 무엇이 없는지 알려 주고 멈춥니다.

### 왜 80 포트인가 — 세 버전을 한 포트로 (`ARCHITECTURE.md` 3장 배포 메모)

이 VM 의 외부 노출 구조는 VM 에서 바꿀 수 없습니다. 강사 리버스 프록시가 TLS 를 종단하고 `http→https` 301 을 한 뒤
VM 의 **80 포트 하나**로만 전달합니다. 그래서 VM 은 TLS 를 하지 않고(자체 서명 인증서 불필요), 도메인으로 보이는 웹은 한 번에 한 버전입니다.

```
브라우저 ──https──▶ 강사 리버스 프록시 (changkwon.mso.so = 112.220.89.250, TLS 종단, http→https 301)
                       └──http──▶ 이 VM : 80 포트 하나 (프록시 내부 IP 192.168.104.100)
```

| 버전 | 디렉터리 | 공개 사이트 | 항상 열린 로컬 포트 | DB | php-fpm 풀 |
|---|---|---|---|---|---|
| v1 실습(취약) | `/var/www/html` (강사 저장소, 불변) | `tbox-v1` | `127.0.0.1:8081` | `tbox` | 기본 `www` |
| **v2 보안 보완 (이 저장소)** | `/var/www/tbox-v2` | `tbox-v2` | `127.0.0.1:8082` | `tbox_re` | `tbox` (tbox-php) |
| v3 새 T-BOX (미착수) | `/var/www/tbox-v3` | `tbox-v3` | `127.0.0.1:8083` | 별도 | 별도 |

- 실제 접속 IP 는 `set_real_ip_from 192.168.104.100` + `real_ip_header X-Forwarded-For` 로 복원합니다 — **프록시 IP 가 보낸 헤더만** 신뢰하므로 다른 곳에서 온 위조 헤더는 무시됩니다 (`SECURITY.md` R-30·R-31).
- HSTS(`S-09-1`)는 공개용 `tbox-v2` 에만 붙습니다. 로컬 8082(평문)에 붙이면 접속이 불가능해집니다.
- v2 저장소는 `/var/www/tbox-v2` 로, v1 웹 루트(`/var/www/html`) 밖입니다 — v1 경유로 v2 의 소스·`.env`·SQL 에 닿는 URL 이 없습니다 (`SECURITY.md` R-29).

### 접속 주소

| 대상 | 주소 | 비고 |
|---|---|---|
| **공개 (도메인)** | `https://changkwon.mso.so/` | 지금 80 포트에 꽂힌 버전. `switch-site.sh status` 로 확인 |
| v1 실습 (로컬 전용) | `http://localhost:8081/` | SSH 포워딩 필요 |

```bash
ssh -L 8081:127.0.0.1:8081 -L 8082:127.0.0.1:8082 changkwon@VM
# 그다음 브라우저에서 http://localhost:8082/
```

#### 설정 파일 — 저장소 루트 `.env` (`PRD.md` S-09-6)

실제 설정은 저장소 루트 `.env` 한 곳에만 있습니다. `public/` 밖이라 URL 로 보이지 않고, `.gitignore` 의 `.env` 줄로 Git 에는 들어가지 않습니다.
소유 `changkwon:tbox-php`, 권한 `0640` — 개발자(`changkwon`)는 읽고 고치고, 앱 계정(`tbox-php`)은 그룹으로 **읽기만** 해 자기 설정을 고쳐 쓸 수 없으며, 그 외 계정은 읽지도 못합니다.
`deploy/install.sh` 가 만들고 소유·권한을 매번 맞춥니다. 키 목록은 저장소의 `.env.example` 을 보세요(값 없음, 이것만 커밋).
(운영 전환 시 `/etc/tbox-v2/tbox.env`(`root:tbox-php`)로 이전 검토 — 심층 방어. `PRD.md` S-09-6)

```bash
ls -l .env                           # -rw-r----- changkwon tbox-php  이어야 합니다 (앱 그룹 밖이면 sudo)
cat .env                             # 값 보기
nano .env                            # 값 고치기
sudo systemctl reload php8.1-fpm     # 고친 뒤 반영
```

`APP_SECRET`(CSRF 토큰 HMAC 키)이 없으면 설치 스크립트가 `openssl rand -hex 32` 로 만들어 덧붙입니다 — 기존 값은 바꾸지 않습니다.

### 시드 계정 (2단계)

`install.sh` 7절은 `scripts/seed_users.php` 를 실행해 아래 5계정과 **검토 계정 10개**(`claude_` 5 · `qa_` 5 — 아래 「검토 계정」 절)를 만듭니다.
계정별로 **없는 것만** 만들고(이미 있는 계정의 비밀번호는 바꾸지 않습니다), 새로 만든 줄만 파일에 덧붙입니다.
비밀번호는 계정마다 무작위 16자로 생성되며, **저장소·README 에는 적지 않습니다**(`PRD.md` S-09-6).
평문은 `/etc/tbox-v2/seed-accounts.txt`(`0600 root`) 한 곳에만 있습니다.
인자는 정확히 일치하는 하나만 받습니다 — 없음(시드 + 검토) · `--no-qa`(시드만, 운영 배포) · `--claude-only`(`claude_` 5개만). 그 밖의 글자는 사용법 오류로 끝납니다.

| 아이디 | 역할 | 팀 |
|---|---|---|
| `admin01` | Admin | — |
| `manager01` | Manager | 개발팀 |
| `employee01` | Employee | 개발팀 |
| `employee02` | Employee | 영업팀 |
| `guest01` | Guest | — |

> 10단계부터 **Guest 계정에는 만료일이 함께 들어갑니다**(생성 시점 + 90일, `SECURITY.md` R-12).
> 만료된 뒤에는 비밀번호가 맞아도 로그인할 수 없습니다.
>
> 🔴 **11단계 패치 뒤 첫 로그인에는 비밀번호 변경 · 2단계 인증 등록이 강제됩니다**
> (`PRD.md` F-16). 패치 시점에 살아 있던 계정 전부(시드 5개 · 검토 5개 포함)가 대상이며,
> 마이그레이션 `db/migrations/2026-09-11_users_first_login.sql` 이 플래그만 켭니다 —
> 계정을 지우거나 다시 만들지 않습니다. 그래서 위 표의 비밀번호로 로그인하면
> 곧바로 「비밀번호를 변경해 주세요」 화면이 뜨고, 그 절차를 마치기 전에는 다른 기능이
> 전부 **403** 입니다(서버 관문이 막습니다. 화면만 되살려도 소용없습니다).

```bash
sudo cat /etc/tbox-v2/seed-accounts.txt      # 한 줄에 "아이디 역할 비밀번호"
```

#### 🔴 시드 비밀번호 파일은 **쓰고 나면 지웁니다** (`SECURITY.md` R-33)

`/etc/tbox-v2/seed-accounts.txt` 는 **평문 비밀번호**가 그대로 들어 있는 파일입니다.
`0600 root` 라 일반 사용자는 못 읽지만, root 를 얻은 침입자에게는 계정 전부가 한 번에 넘어갑니다.
그래서 이 파일의 수명을 아래처럼 정합니다.

| 순서 | 할 일 | 명령 |
|---|---|---|
| 1 | 계정 주인이 **첫 로그인** | 브라우저에서 `/` |
| 2 | **「내 계정」 화면(`/settings`) → 비밀번호 바꾸기** 로 각자 비밀번호 변경 (10자 이상) | `POST /api/me/password` |
| 3 | 전원이 바꾼 것을 확인 — `password_changed_at` 이 채워졌으면 본인이 바꾼 것입니다 (11단계 F-16) | 아래 SQL |
| 4 | **파일 삭제** | `sudo shred -u /etc/tbox-v2/seed-accounts.txt` |

```bash
# 3) 아직 최초(또는 임시) 비밀번호를 쓰고 있는 계정 — password_changed_at 이 비어 있습니다
sudo -u postgres psql -d tbox_re -c \
  "SELECT username, role, must_change_password, mfa_setup_required, password_changed_at
     FROM users WHERE is_active AND password_changed_at IS NULL ORDER BY id"

# 4) 전원이 바꿨으면 지웁니다 (되돌릴 수 없습니다)
sudo shred -u /etc/tbox-v2/seed-accounts.txt
```

> 과제 기간에는 관문 ③(사용자 자기 공격)에서 시드 계정으로 로그인해야 하므로 **파일을 남겨 둡니다**
> — 위험을 알고 받아들인 상태입니다(`SECURITY.md` R-33). 운영 배포에서는 위 4단계를 반드시 끝냅니다.
> 비밀번호를 잃어버린 계정은 파일을 되살릴 수 없으므로, Admin 이 계정 관리 화면(`/users`)에서
> **새 계정을 만들어 넘기거나** `psql` 로 해시를 교체합니다.

## 폴더 (`PRD.md` F-26 · `ARCHITECTURE.md` 5.16)

파일 화면 왼쪽이 **폴더 트리**입니다. 폴더는 분류이면서 **권한의 울타리**입니다 —
파일과 똑같은 접근 등급(`public` · `internal` · `team` · `admin-only`)을 폴더도 갖습니다.

### 무엇이 달라지나

| 질문 | 답 |
|---|---|
| 볼 수 없는 폴더는 어떻게 보이나요 | **아예 보이지 않습니다.** 감춰 둔 것이 아니라 서버 응답에 들어 있지 않습니다. 주소를 손으로 고쳐 열어도 「권한이 없습니다」(403) 입니다 |
| 폴더를 열면 안의 파일이 다 보이나요 | 아닙니다. 폴더는 **들어올 수 있는 최소 자격**이고, 파일마다 자기 등급으로 한 번 더 걸러집니다. 그래서 열어도 비어 보일 수 있습니다 |
| 폴더 이름은 누가 보나요 | 그 폴더를 **읽을 수 있는 사람 모두**입니다. 이름 자체가 정보가 되므로 사람 이름·금액·사건명을 넣지 마세요 (화면에도 같은 안내가 있습니다, `SECURITY.md` R-63) |
| 검색(`?q=`)은 지금 폴더 안에서만 하나요 | 아닙니다 — **검색은 폴더를 가리지 않습니다.** 검색어를 넣으면 볼 수 있는 파일 전체에서 찾고, 결과 표에 「폴더」 경로 열(`A / B`)이 함께 나옵니다. 검색어를 지우면 다시 지금 열어 둔 폴더만 보입니다 |
| `team` 폴더 안에 `admin-only` 를 둘 수 있나요 | 됩니다. 팀이 같아야 하는 것은 **폴더와 하위가 둘 다 `team` 일 때**뿐입니다 |
| 저장 위치가 바뀌나요 | 아닙니다. 실제 파일은 예전 그대로 무작위 이름으로 저장됩니다 — 폴더는 DB 안의 분류일 뿐이라 경로가 바뀌지 않습니다 |

### 지켜지는 규칙 세 가지

1. **하위는 부모보다 넓을 수 없습니다.** `admin-only` 폴더 안에 `public` 파일을 넣을 수 없습니다
   (거부 문구: 「잘못된 요청입니다」, 감사 로그 사유 `parent_narrower`). 업로드 · URL 가져오기 ·
   파일 이동 · 파일 등급 변경 · 폴더 만들기 · 폴더 이동 · 폴더 등급 변경 **일곱 자리 모두**에 적용됩니다.
2. **폴더 등급을 좁힐 때**는 안에 그보다 넓은 것이 남아 있으면 거부됩니다(`children_exceed`).
   「하위 폴더·파일에도 이 등급을 적용합니다」를 켜면 넓은 것들을 **함께 좁혀 줍니다**
   (구글 드라이브의 「하위에도 적용」과 같습니다). 이때 내가 고칠 수 없는 항목이 하나라도 있으면
   **전부 되돌립니다** — 반만 바뀐 상태로 남지 않습니다.
3. **폴더 등급을 넓히는 것은 관리자만** 할 수 있습니다(파일 등급을 낮추는 규칙과 같습니다).

### 쓰는 법

| 하고 싶은 것 | 어디서 |
|---|---|
| 폴더 만들기 | 왼쪽 트리의 「새 폴더」 — 이름 · 등급(부모보다 넓은 등급은 목록에 없습니다) · 팀 |
| 들어가기 · 나오기 | 트리의 폴더 이름을 누르거나, 위쪽 경로(`루트 › A › B`)에서 원하는 자리를 누릅니다 |
| 이름 변경 · 등급 변경 · 삭제 | 폴더에 들어간 뒤 트리 아래 단추 셋. 삭제는 **안이 완전히 비었을 때만** 됩니다(휴지통에 있는 파일도 「있는」 것으로 셉니다) |
| 파일 옮기기 | 파일 행의 폴더 단추 → 옮길 폴더를 골라 「여기로 이동」 |
| 폴더를 정해 올리기 | **고르지 않습니다** — 「파일 올리기」 대화상자는 언제나 **지금 열어 둔 폴더**에 올립니다(맨 위에 「올릴 위치: 이카운트 › 이카운트 양식」처럼 보입니다). 등급도 그 폴더 것을 물려받습니다. 다른 폴더에 올리려면 그 폴더로 들어가서 여세요 |

누가 폴더를 고칠 수 있나: **만든 사람**, 그 폴더가 자기 팀 것인 **Manager**, 그리고 **Admin** 입니다.
모든 만들기 · 이름 변경 · 이동 · 등급 변경 · 삭제는 감사 로그에 `folder.*` 로 남습니다.

## 일괄 업로드 (`PRD.md` F-27 · `ARCHITECTURE.md` 5.17)

「파일 올리기」 대화상자에서 **여러 개를 한 번에** 고르거나 상자 안으로 **끌어 놓을** 수 있습니다.
한 번에 최대 **50개**이고, 등급 · 팀 · 설명은 고른 파일 전부에 똑같이 적용됩니다. 올라가는 폴더는
**지금 열어 둔 폴더** 하나입니다. 올리는 동안에는 대화상자가 닫히지 않습니다(진행 표가 사라지지 않게).

### 어떻게 보내나 (중요)

화면은 파일을 **하나씩 순서대로** 보냅니다. 한 번에 몰아 보내지 않습니다.

- 서버 규칙은 **한 글자도 바뀌지 않았습니다** — 요청 하나에 파일 하나입니다.
  그래서 파일마다 확장자 · 실제 내용(MIME) · 크기 · 하루 총량(2GB) · 민감정보 검사가 그대로 돌고,
  감사 로그도 파일 수만큼 남습니다.
- 동시에 하나만 보내는 이유: 한 사람이 서버의 처리 일꾼을 전부 차지하지 않게 하고,
  하루 총량이 파일 순서대로 정확히 누적되게 하기 위해서입니다 (`SECURITY.md` R-64).

### 표를 읽는 법

| 상태 | 뜻 |
|---|---|
| 대기 | 아직 차례가 오지 않았습니다 |
| 올리는 중… | 지금 이 파일을 보내고 있습니다 |
| 완료 | 저장됐습니다 |
| (붉은 문구) | 그 파일만 거부됐습니다. **문구는 서버가 준 그대로**입니다 (예: 「민감정보가 보여 team 또는 admin-only 로만 올릴 수 있습니다」) |
| 중단 | 앞에서 권한 문제(403)나 로그인 만료(401)가 나서 나머지를 보내지 않았습니다 |

거부된 파일이 있어도 **나머지는 계속 올라갑니다.** 다만 권한 문제는 나머지도 같은 결과이므로
그 자리에서 멈춥니다 — 같은 거부를 50번 감사 로그에 쌓지 않기 위해서입니다.

> 끌어 놓기가 안 되는 브라우저에서는 상자 안의 파일 선택 단추를 쓰면 됩니다(같은 동작입니다).

## 계정 관리 (10단계 · `PRD.md` F-10)

Admin 만 `/users` 화면과 `GET/POST /api/users`, `PATCH /api/users/{uid}` 를 쓸 수 있습니다.
다른 역할은 화면도 API 도 **403** 이고, 그 시도 자체가 `authz.route|deny` 로 감사 로그에 남습니다.

| 규칙 | 내용 |
|---|---|
| 1인 1개 | 계정은 사람마다 하나입니다. 공용 계정·시드 계정을 실무에 쓰지 않습니다 — 감사 로그의 「누가」는 계정이 사람에 1:1 로 묶일 때만 성립합니다 (`PRD.md` 3장 · S-07) |
| 사유 필수 | 계정 생성·역할 변경·비활성화·재활성화에는 **사유(`reason_text`, 500자)가 필수**입니다. 없으면 400 이고, 적은 사유는 감사 로그 `detail.reason_text` 에 남습니다 (S-07 "관리자 행동 사유", R-20) |
| 비밀번호 | **Admin 이 비밀번호를 정하지 않습니다**(11단계 F-16). 서버가 임시 비밀번호 16자를 만들어 **생성 응답에 딱 한 번** 돌려주고, 저장은 Argon2id 해시뿐입니다. 요청에 `password` 키를 넣으면 400 입니다. 감사 로그에는 값이 아니라 `detail.temp_password_issued: true` 만 남습니다 |
| 첫 로그인 | 새 계정은 **비밀번호 변경 → 2단계 인증 등록**을 마쳐야 다른 기능을 쓸 수 있습니다. 마치기 전의 모든 요청은 403 `{"next":"password_change"\|"mfa_setup"}` 이고 `auth.gate|deny` 로 남습니다 |
| 재발급 · 초기화 | 비밀번호를 잊었거나 인증 앱이 든 휴대폰을 잃으면 Admin 이 **임시 비밀번호 재발급**·**2단계 인증 초기화**를 합니다. 둘 다 **사유 필수 · 자기 자신 금지**이고, 대상의 **모든 세션이 끊깁니다** |
| 역할 | `Admin`·`Manager`·`Employee`·`Guest` 넷뿐입니다. 그 밖의 값은 400 입니다 |
| Guest 만료 | **Guest 계정은 만료일이 필수**입니다(`SECURITY.md` R-12). 만료된 뒤에는 비밀번호가 맞아도 로그인할 수 없고 `user.expired` 가 남습니다. DB CHECK 가 마지막 그물입니다 |
| 자기 자신 | Admin 도 **자기 역할·활성 상태는 바꿀 수 없습니다**(`self_change`). 자기 계정의 비밀번호·2단계 인증은 「내 계정」에서 합니다 |
| 마지막 관리자 | **마지막 활성 Admin** 은 강등·비활성화되지 않습니다(`last_admin`). 관리자가 0명이 되면 아무도 되돌릴 수 없습니다 |
| 전 기기 로그아웃 | 역할·팀을 바꾸거나 계정을 끄면 **그 사람의 모든 세션이 즉시 삭제**됩니다 (`PRD.md` T-22, `SECURITY.md` R-10). 끊은 개수는 `detail.sessions_revoked` 에 남습니다 |
| 삭제 없음 | 계정을 지우는 기능은 없습니다. 파일·감사 로그가 계정을 가리키고 있어 지우면 추적이 끊어집니다 — 그만 쓸 계정은 **비활성화**합니다 |

```bash
# 목록 (Admin 세션 필요. 비밀번호 해시·TOTP 비밀은 응답에 없습니다)
curl -s -b jar https://changkwon.mso.so/tbox/api/users

# 계정 만들기 — 비밀번호는 보내지 않습니다. 201 응답의 temp_password 가 한 번만 나옵니다
curl -s -b jar -X POST -H 'Content-Type: application/json' -H "X-CSRF-Token: $TOKEN" \
  --data-binary '{"username":"hong.gildong","role":"Employee",
                  "team_id":1,"reason_text":"2026-09-11 입사 (인사팀 요청)"}' \
  https://changkwon.mso.so/tbox/api/users
# → {"id":25,"username":"hong.gildong",…,"temp_password":"…16자…"}
#   이 값은 **다시 볼 수 없습니다.** 안전한 경로로 본인에게만 전달하고, 본인은 첫 로그인에서 바꿉니다.

# 임시 비밀번호 재발급 · 2단계 인증 초기화 (사유 필수 · 자기 자신 금지 · 대상 세션 전부 종료)
curl -s -b jar -X POST -H 'Content-Type: application/json' -H "X-CSRF-Token: $TOKEN" \
  --data-binary '{"reason_text":"본인 확인 후 비밀번호 분실 재발급 (2026-09-11)"}' \
  https://changkwon.mso.so/tbox/api/users/25/password/reset
curl -s -b jar -X POST -H 'Content-Type: application/json' -H "X-CSRF-Token: $TOKEN" \
  --data-binary '{"reason_text":"휴대폰 분실 — 인증 앱 재등록 필요 (2026-09-11)"}' \
```

## 2단계 인증 (TOTP) — 10단계 · `SECURITY.md` R-05 · R-85

비밀번호 하나만으로는 Admin 계정이 털리면 급여·인사 자료가 통째로 넘어갑니다.
그래서 **2단계 인증(TOTP, RFC 6238)은 Admin 에게 필수**이고(11단계 F-16 → F-52 2026-09-16 사용자 결정 · `PRD.md` F-52)
다른 역할은 선택입니다. 켜 두기를 권장하며, 켜지 않은 계정은 로그인할 때마다 홈에 권장 안내가 나옵니다.

| 언제 | 무슨 일이 일어나나 |
|---|---|
| 새 계정의 첫 로그인 | ① 임시 비밀번호로 로그인 → ② **비밀번호 변경** → ③ Admin 이면 **2단계 인증 등록**. 마치기 전에는 홈 화면이 그 절차만 보여 주고, 서버는 다른 요청을 403 `{"next":…}` 으로 막습니다. Admin 이 아니면 ② 까지만 강제이고 ③ 은 권장 안내로 권합니다 |
| 기존 계정 (패치 뒤 첫 로그인) | 같습니다. 이미 2단계 인증을 켜 둔 계정은 ③ 을 건너뜁니다 |
| 2단계 인증을 끄면 | 끌 수는 있습니다. Admin 이면 **다음 요청부터 다시 등록을 요구**합니다 — "끄기" 는 비밀 키를 갈아 끼우는 길이지 면제가 아닙니다. 다른 역할이면 막히지 않고 홈에 권장 안내가 다시 나옵니다 |
| 켜지 않은 채로 쓰면 | Admin 이 아니면 모든 화면·기능을 그대로 씁니다. 홈 위쪽에 「2단계 인증을 켜 두는 것을 권장합니다」 안내가 뜨고, 「나중에」를 누르면 **그 브라우저의 이 세션 동안만** 숨습니다(서버는 아무것도 저장하지 않으므로 다음 로그인에 다시 나옵니다) |
| 인증 앱을 잃으면 | 본인은 로그인할 수 없습니다. Admin 이 **2단계 인증 초기화**(사유 필수)를 하면 대상이 Admin 이면 다음 로그인 뒤 다시 등록해야 하고, 아니면 권장 상태가 됩니다 |
| 필수 역할을 늘리려면 | `src/Auth.php` 의 `Auth::MFA_REQUIRED_ROLES` 목록에 역할 이름 한 단어를 더합니다(문서 `PRD.md` F-52 · `SECURITY.md` R-85 먼저) |

| 항목 | 값 |
|---|---|
| 방식 | TOTP (HMAC-SHA1 · 30초 · 6자리 · 허용 오차 ±1스텝) |
| 인증 앱 | Google Authenticator · Microsoft Authenticator · Aegis · FreeOTP 등 표준 TOTP 앱이면 모두 (전부 무료). 유료 비밀번호 관리자(1Password 등)에 든 TOTP 기능도 됨 |
| 구현 | `src/Totp.php` — 외부 라이브러리 없이 `hash_hmac('sha1')` 로 직접 (공급망 최소화, S-10-C) |
| 비밀 보관 | `users.mfa_secret`(base32). **켜져 있을 때만** 값이 있고, 끄면 `NULL` 로 지웁니다 |
| 화면 | **QR 코드**·비밀 키·`otpauth://` 주소를 함께 보여 줍니다. 인증 앱의 「QR 코드 스캔」이 기본 경로이고, 비밀 키 손 입력·링크는 카메라를 못 쓸 때의 대안입니다 (외부 라이브러리 없이 서버가 만든 QR — `src/Qr.php`) |

### 코드는 어디서 나오나요 (인증 앱)

6자리 코드는 서버가 보내 주는 것이 아니라 **스마트폰 인증 앱이 30초마다 스스로 만들어 냅니다.**
앱과 서버가 같은 비밀 키와 같은 시계를 보고 각자 계산하기 때문에, 네트워크도 문자메시지도 필요 없습니다.

켜는 순서 (「내 계정」 화면 `/settings`)

1. 스마트폰에 **인증 앱**을 설치합니다 — Google Authenticator · Microsoft Authenticator ·
   Aegis(Android, 오픈소스) · FreeOTP(iOS·Android, 오픈소스) 중 아무거나 됩니다. **모두 무료**이고 계정 가입 없이 쓸 수 있으며, 등록 뒤에는 인터넷 없이도 코드가 나옵니다.
2. 「내 계정」 화면(`/settings`)에서 **「2단계 인증 켜기」** — 서버가 **QR 코드**와 비밀 키, `otpauth://` 주소를 보여 줍니다.
   이때는 아직 **켜지지 않았습니다**. 비밀 키는 **다시 보여 주지 않으므로 지금 옮겨 적습니다.**
3. 앱에서 **「QR 코드 스캔」** 을 고르고 화면의 QR 을 찍습니다 — 이것이 기본 경로입니다.
   카메라를 쓸 수 없으면: 스마트폰에서 이 화면을 보고 있다면 **「인증 앱에 바로 추가 (otpauth 링크)」** 를 누르고,
   그것도 안 되면 앱에서 **「설정 키 입력」(수동 입력)** 을 골라 계정 이름 `t-box:아이디` · 키는 화면의 비밀 키를
   그대로 넣습니다. 종류는 **시간 기반(Time based) · 6자리** 입니다.
4. 앱에 뜬 6자리 코드를 **「확인하고 켜기」** 에 적습니다.
   코드가 맞아야 켜집니다 — 등록에 실패한 사람이 자기 계정에 못 들어가는 일을 막기 위해서입니다.
5. 그 뒤 로그인은 **두 걸음**이 됩니다 — 먼저 아이디·비밀번호만 넣고 「로그인」,
   그러면 **그때 코드 칸이 나타나므로** 인증 앱의 6자리를 넣고 다시 「로그인」 합니다.
   (2단계 인증을 켜지 않은 계정에는 코드 칸이 아예 나타나지 않습니다. 비밀번호가 틀리면
   코드 칸도 나오지 않습니다 — 비밀번호를 모르는 사람은 그 계정의 2단계 인증 여부를 알 수 없습니다.)

### 인증 앱 없이 코드 구하기 (`scripts/totp_code.php`) — 검토·시험용

스마트폰을 못 쓰는 상황(서버에서 관리자가 직접 시험할 때)에서는 같은 계산을 서버에서 합니다.
화면에 나온 비밀 키를 그대로 넣으면 **지금의 코드 한 개와 남은 초**를 찍습니다.

```bash
# 사용법 (인자 없이 실행하면 사용법을 내고 종료 코드 2)
sudo php /var/www/tbox-v2/scripts/totp_code.php

# 지금의 코드 (비밀은 화면 「2단계 인증 켜기」 가 보여 준 값)
sudo php /var/www/tbox-v2/scripts/totp_code.php JBSWY3DPEHPK3PXP
# 282760
# 남은 시간: 17초 (30초마다 바뀝니다)
```

> ⚠️ **비밀 키를 어디에도 남기지 마세요.** 이 명령은 비밀을 인자로 받으므로
> 셸 히스토리(`~/.bash_history`)에 그대로 남습니다 — 명령 앞에 **공백 한 칸**을 두고 실행하거나
> (`HISTCONTROL=ignorespace`), 실행 뒤 해당 줄을 지웁니다.
> 비밀을 스크립트·설정 파일·메모장에 적어 두면 2단계 인증의 의미가 사라집니다.
> 이 스크립트 자체는 DB 에 붙지 않고 감사 로그도 쓰지 않습니다(비밀·코드를 기록하지 않기 위해).
> 계산은 화면·로그인과 **같은 `src/Totp.php`** 가 하므로 값이 어긋날 일이 없습니다.

끄려면 **현재 비밀번호와 지금의 코드**가 모두 필요합니다 — 세션만 훔친 사람이 2단계 인증을
꺼 버리지 못하게 하기 위해서입니다.

> 코드가 없거나 틀리면 응답은 로그인 실패와 **똑같은 401 문구**입니다
> ("이 계정은 2단계 인증을 쓴다" 를 알려 주지 않습니다). 사유는 감사 로그에만
> `auth.mfa|deny|code_required`·`bad_code` 로 남고, **실패 5회면 계정이 10분 잠깁니다**
> — 비밀번호를 알아낸 공격자가 코드 6자리를 무제한으로 시험하지 못하게 하는 장치입니다.
>
> **인증 앱을 잃어버렸다면** 스스로 끌 수 없습니다. Admin 이 `psql` 로 되돌립니다:
> `sudo -u postgres psql -d tbox_re -c "UPDATE users SET mfa_enabled=false, mfa_secret=NULL WHERE username='아이디'"`
> (이 작업은 감사 로그에 남지 않으므로, 누가 왜 했는지 운영 기록에 따로 남깁니다.)

계정이 이미 있으면 스크립트는 `건너뜀` 만 출력하고 아무것도 바꾸지 않습니다(비밀번호 파일도 그대로 둡니다).
비밀번호를 잃어버렸다면 `sudo -u postgres psql -d tbox_re -c 'DELETE FROM users'` 후 재설치가 아니라,
10단계 계정 관리(F-10)나 `psql` 로 해시를 직접 교체하세요 — `users` 를 지우면 파일·감사 로그의 참조가 깨집니다.

### 스마트폰이 어려울 때 — 2단계 코드 생성기 (`public/assets/totp-generator.html`)

스마트폰에 인증 앱을 넣기 어려운 분을 위한 **대안**입니다 (`PRD.md` F-17).
HTML 파일 **한 개**로, 브라우저에서 열어 비밀 키를 붙이면 6자리 코드를 30초마다 계산합니다.
**네트워크 요청이 0** 이라 인터넷 없이도, 서버에 접속하지 않아도 동작합니다 — 계산은 브라우저
안에서 표준 암호 기능(WebCrypto HMAC-SHA1)으로 하며, 서버·로그에 아무것도 남기지 않습니다.

**① 내려받기** — 둘 중 편한 쪽

```bash
# (가) SSH 터널을 열어 둔 상태에서 브라우저로 열고 "다른 이름으로 저장"
http://localhost:8082/tbox/assets/totp-generator.html

# (나) 파일을 직접 복사
scp changkwon@192.168.105.44:/var/www/tbox-v2/public/assets/totp-generator.html .
```

> 내려받은 파일은 **내 PC 에 두고 파일로(`file://`) 엽니다.** 브라우저 주소창에 끌어다 놓으면 됩니다.
> (`crypto.subtle` 은 `https`·`file://`·`localhost` 에서만 동작합니다. 평문 `http` 로 다른 PC 에서
> 열면 "암호 계산 기능을 쓸 수 없습니다" 라고 안내가 나옵니다.)

> **휴대폰에서 쓰기 (F-46).** 인증 앱을 넣기 어려운 분은 휴대폰 브라우저로 t-box 주소의
> `/assets/totp-generator.html` 을 연 뒤, 브라우저 메뉴의 **「홈 화면에 추가」** 를 누르면 앱처럼
> 열립니다(주소창 없는 전체 화면). 480px 이하에서는 입력칸·버튼이 화면 폭을 다 쓰고 버튼은 손가락에
> 맞는 높이(44px 이상)가 되며, 코드 글자는 크게 나옵니다. 아이콘과 이름은 같은 폴더의
> `totp-generator.webmanifest` 가 정하고, **아이콘까지 파일 안에 들어 있어 외부에서 받아오는 것이
> 하나도 없습니다.** 설치되는 앱(APK)이 아니라 **브라우저가 만든 바로가기**이므로 스토어·결제·광고가
> 없고, 지우는 것도 바로가기를 지우면 끝입니다. 다만 그 휴대폰이 곧 두 번째 겹이므로, 로그인하는
> PC 와 **다른 기기**에 두어야 의미가 있습니다(`SECURITY.md` R-40).

**② 쓰는 순서**

1. 「내 계정」 화면(`/settings`)의 **「2단계 인증 켜기」** 가 보여 준 **비밀 키**(또는 `otpauth://` 주소)를 복사합니다.
   t-box 화면도 생성기도 비밀 키를 **4자씩 띄어**(`GEZD GNBV GY3T QOJQ …`) 보여 줍니다 — 옮겨 적기 오류를
   줄이려는 **표시 방식**일 뿐, 값은 같습니다(띈 채로 붙여 넣어도 됩니다).
2. 생성기의 입력 칸에 붙입니다. 칸 아래에 **4자 묶음으로 다듬어진 키**가 나오니 t-box 화면의 값과 눈으로 대조하세요.
3. **「코드 만들기」** — 6자리 코드, 남은 초, **다음 코드**가 나옵니다. 이 단계는 **아무것도 저장하지 않습니다**
   (창을 닫으면 사라집니다). 경계에서 코드가 바뀔 것 같으면 「다음 코드」 를 쓰세요.
4. 다음부터 붙여 넣기가 번거로우면 **잠금 문구**(**12자 이상**, 단어 2~3개 권장)를 정해 **「잠가 저장」** 을 누릅니다.
   그때부터 첫 화면은 **「잠금 문구 + 열기」** 만 나옵니다 — 문구를 넣고 **「열기」**.
   (「잠금」 = 메모리의 키만 지움 · 「지우기」 = 저장된 암호문까지 지움)
5. 6자리를 **「확인하고 켜기」** 에 넣어 2단계 인증을 확정합니다. 이후 로그인의 코드 칸에도 같은 값을 씁니다.
6. **시각은 t-box 서버와 맞춥니다**(F-42) — 생성기는 열릴 때와 5분마다 `GET /api/time` 으로 서버 시각을 받아
   「서버 − PC」 차이만큼 보정하므로, PC 시계가 틀려도 코드는 맞습니다. 「시각 확인」 칸의 상태 줄이
   **「서버와 동기화됨」**(맞춘 상태) · **「오프라인 · 저장된 보정값 사용」**(지난번 차이로 계산) ·
   **「오프라인 · PC 시각 사용」**(한 번도 못 맞춤 — 이때만 PC 시계를 맞추세요) 을 알려 줍니다.
   파일(`file://`)로 열었으면 상태 줄 아래 칸에 t-box 주소를 한 번 적어 둡니다.

> 터미널에서 확인하고 싶으면 `sudo php scripts/totp_code.php "GEZD GNBV GY3T QOJQ …"` — 공백·하이픈·소문자를
> 알아서 다듬으므로 4자 묶음을 그대로 붙여 넣어도 같은 코드가 나옵니다.

**③ 자체 점검 버튼** — 「자체 점검 실행」 을 누르면 **9개**를 확인해 `9/9 통과` 를 보여 줍니다:
RFC 6238 부록 B 의 **공개 시험값 6개**(계산이 표준과 같은가) + 잠금 점검 3개 — ① 무작위 키를 임시 문구로
잠갔다가 같은 문구로 풀면 원본과 같은가 ② **다른 문구로는 풀리지 않는가** ③ 저장 형식의 암호문 안에
평문 비밀 키가 들어 있지 않은가. 비밀 키 없이도 누를 수 있고, **저장된 값은 건드리지 않습니다**(메모리에서만).
잠금 점검은 60만 회 반복 때문에 몇 초 걸립니다.
같은 시험값을 서버 구현(`src/Totp.php`)으로 계산하면 값이 일치합니다:

```bash
php -r 'require "src/Totp.php"; foreach ([59,1111111109,1111111111,1234567890,2000000000,20000000000] as $t) echo $t, " ", Totp::code("GEZDGNBVGY3TQOJQGEZDGNBVGY3TQOJQ", $t), "\n";'
# 287082 081804 050471 005924 279037 353130
```

**④ 저장은 「잠금 문구」로 잠급니다** (`PRD.md` F-17-2) — 비밀 키를 **평문으로 저장하지 않습니다.**
「잠가 저장」 을 누르면 문구에서 `PBKDF2-SHA256`(무작위 salt, **60만 회**)으로 잠금 키를 만들고
`AES-GCM`(무작위 IV)으로 비밀 키를 암호화해 **암호문만** 그 브라우저에 남깁니다
(`localStorage` 키 `tbox-totp-vault` = `{"v":1,"kdf":"PBKDF2-SHA256","iter":600000,"salt":…,"iv":…,"ct":…}`).
문구·잠금 키·평문 비밀 키는 **어디에도 저장하지 않습니다** — 푼 값은 메모리 변수에만 있습니다.

> ⚠️ **문구를 잊으면 되돌릴 방법이 없습니다.** 암호문은 쓸모가 없어지므로, t-box **「내 계정」**에서
> 2단계 인증을 **끄고 다시 켜서 새 비밀 키**를 받아야 합니다(끌 때도 코드가 필요하니, 코드를 만들 수 있을 때
> 미리 하세요. 이미 못 여는 상태라면 `README` 위쪽의 Admin `psql` 절차로 되돌립니다).

이전 방식(평문 `localStorage` 저장)으로 저장해 둔 값이 남아 있으면 파일을 열 때 **즉시 지우고** 안내합니다 —
그 경우 비밀 키를 다시 붙여 넣고 문구로 잠가 저장하세요.

> ⚠️ **`SECURITY.md` R-40 — 이 방법은 두 번째 겹을 약하게 만듭니다.**
> 비밀 키가 **로그인하는 그 PC** 에 있으면, 그 PC 를 쥔 사람(악성코드·자리 비움·공용 PC)은
> 비밀번호와 코드를 **함께** 얻습니다. 스마트폰 인증 앱은 기기가 분리돼 있어 더 강합니다 —
> **가능하면 앱을 쓰고**, 이 생성기는 앱을 쓸 수 없을 때의 대안으로만 쓰세요.
> 쓰더라도 ⓐ 로그인용 PC 와 **다른 기기**에 두거나, ⓑ 「잠가 저장」 하지 말고 쓸 때마다 붙여 넣고,
> ⓒ 공용 PC 에서는 쓰지 않습니다. 저장하더라도 문구는 **추측하기 어려운 단어 2~3개**로 정합니다 —
> 암호문만 훔친 사람은 문구를, 문구만 아는 사람은 암호문을 따로 구해야 합니다(F-17-2).

### 서버 시간대 — KST 로 통일 (2026-09-11)

VM 은 UTC 로 설치돼 있었고 감사 로그·`date`·cron 이 모두 UTC 로 보여 사용자가 읽기 어려웠습니다.
세 층을 **같은 값**으로 맞췄습니다. 하나만 바꾸면 화면과 로그의 시각이 9시간 어긋나 보이니 항상 함께 바꿉니다.

| 층 | 설정 | 확인 |
|---|---|---|
| OS (`date`, cron, auth.log, nginx 로그) | `sudo timedatectl set-timezone Asia/Seoul` → `cron`·`rsyslog` 재시작, `nginx` reload | `timedatectl` → `Time zone: Asia/Seoul (KST, +0900)` |
| PostgreSQL (`now()` 표시, 날짜 필터 해석, 서버 로그) | `ALTER SYSTEM SET timezone='Asia/Seoul'; ALTER SYSTEM SET log_timezone='Asia/Seoul'; SELECT pg_reload_conf();` (`postgresql.auto.conf` 에 기록돼 `postgresql.conf` 의 `Etc/UTC` 를 덮음) | `psql -Atc "show timezone"` |
| PHP (`date()`, 경보 AL-7 업무시간 판정) | `/etc/php/8.1/{fpm,cli}/conf.d/99-tbox-timezone.ini` = `date.timezone = Asia/Seoul` (사본 `deploy/php/99-tbox-timezone.ini`) → `php8.1-fpm` 재시작 | `php -r 'echo date("c");'` → `+09:00` |

**저장된 데이터는 바뀌지 않습니다.** 모든 시각 컬럼이 `TIMESTAMPTZ`(절대 시각)이고 앱은 DB `now()` 와
오프셋이 붙은 `date('c')` 만 쓰므로, 바뀐 것은 표시·해석입니다. 같은 사건이 전에는 `07:15+00`, 지금은 `16:15+09` 로 보입니다.
감사 로그 화면에서 날짜 필터 `2026-09-11` 은 이제 **한국 시간 하루**를 뜻합니다.
cron 일정(03:00 백업 등)도 KST 로 돕니다.

앱 계정 `tbox-php` 는 여기를 읽지도 못합니다 — 앱이 뚫려도 "정리된 전체 데이터 사본"에는 닿지 않습니다.

### 서버 밖 사본 — 사용자 PC 가 매일 끌어옵니다 (F-55, `PRD.md` S-08 3-2-1 · `SECURITY.md` R-88)

위 산출물은 **같은 디스크·같은 서버**에만 있습니다. 서버 root 를 잡은 공격자는 데이터·백업·키를 한 번에 지울 수 있습니다(2026-09-11 사고 ⑥).
그래서 **사용자 PC 가 매일 05:00 서버에서 끌어와(pull)** 서버 밖 사본을 만듭니다. 서버에는 아무것도 더 두지 않습니다 — 원격 자격증명이 서버에 있으면 그 사본도 함께 지워집니다.

- 스크립트와 설정 순서: `deploy/pc/README.md` (Windows PowerShell, `deploy/pc/pull_backup.ps1`)
- 가져오는 것: `db/`·`files/`·`weekly/`·`monthly/` 의 **암호화 산출물 + `.sha256`**, `/var/log/tbox-v2/*` — 최근 3일분. 평문(`files-mirror/`)은 옮기지 않습니다
- PC 에서 최신 db·files 를 `.sha256` 과 대조하고, 45일 지난 사본은 지웁니다(서버와 같은 보관 정책)
- 키(`backup.key`)는 **백업 폴더에 두지 않습니다** — `-Key <USB경로>` 로 한 번만 따로 받습니다(아래 「키 관리」)
- 매일 확인: PC 에서 `Get-Content C:\tbox-backup\pull.log -Tail 3` → 마지막 줄이 `OK` 인지. 자동 경보는 없습니다(R-88)


### 🔑 백업 키 관리 (`SECURITY.md` R-08, `PRD.md` S-10-E)

> **키를 잃으면 모든 백업이 쓸모없는 바이트 덩어리가 됩니다.** 복구 수단이 통째로 사라집니다.

- 키는 `/etc/tbox-v2/backup.key`(0600 root) 한 곳에 있습니다. `deploy/install.sh` 가 `openssl rand -hex 32` 로 만들고,
  **이미 있으면 절대 바꾸지 않습니다** (바꾸면 그 전 백업을 못 엽니다).
- **사본을 서버 밖에 2인 보관하세요.** 사내 비밀 관리 도구(Vault/Bitwarden)에 넣고, 파일·메일·메신저로 돌리지 않습니다.
  서버가 죽어서 복구하는 상황인데 키가 그 서버에만 있으면 아무것도 못 합니다.
- 키는 백업과 **다른 장소**에 둡니다. 같은 디렉터리에 두면 백업을 가져간 사람이 키도 함께 가져갑니다.
- 연 1회 회전합니다 (`PRD.md` S-11-B). 회전하면 **옛 키도 보관 기간 동안 함께 보관**해야 옛 백업을 열 수 있습니다.

```bash
sudo cat /etc/tbox-v2/backup.key        # 값 보기 (화면·히스토리에 남지 않게 주의)
sudo gpg --batch --decrypt --passphrase-file /etc/tbox-v2/backup.key \
     /var/backups/tbox-v2/db/db-YYYYMMDD-HHMM.dump.gpg | pg_restore -l | head   # 키가 맞는지 확인
```

### 복구 절차 (`ARCHITECTURE.md` 11.2 · `PRD.md` 7.8)

`scripts/restore.sh` 가 아래 순서를 그대로 수행합니다. **산출물은 이름만** 넘깁니다(경로를 받지 않습니다).

```bash
# 0) 무엇이 있는지 본다
sudo ls -l /var/backups/tbox-v2/db /var/backups/tbox-v2/files

# 1) 파일만 복구 (실수로 지운 업로드 되돌리기)
sudo bash scripts/restore.sh --files files-20260911.tar.gz.gpg

# 2) DB 복구 — 리허설은 반드시 별도 DB 에서 (운영 DB 에 --clean 은 되돌릴 수 없다)
sudo -u postgres createdb -O tbox_owner tbox_re_restore
sudo bash scripts/restore.sh --db db-20260911-0441.dump.gpg --dbname tbox_re_restore
sudo -u postgres psql -d tbox_re_restore -c '\dt'          # 표 6개
sudo -u postgres dropdb tbox_re_restore

# 3) 진짜 사고로 운영 DB 를 되돌려야 할 때만 (서비스를 멈추고)
sudo bash scripts/restore.sh --db db-20260911-0441.dump.gpg \
     --dbname tbox_re --yes-production --stop-service

# 4) ★ 운영 DB 를 복구한 뒤에는 최소 권한을 다시 건다 — 덤프는 --no-privileges 로 떠서
#    복구된 표에 tbox_app · tbox_backup 권한(ACL)이 비어 있다 (9단계 검토 실측: 복구 DB \dp 공란).
#    이 단계를 빼면 앱이 DB 에 아무것도 못 하거나(권한 없음), 반대로 PUBLIC 기본 권한이 남는다.
sudo -u postgres psql -d tbox_re -v ON_ERROR_STOP=1 -f db/grants.sql
sudo -u postgres psql -d tbox_re -c '\dp audit_logs'      # tbox_app=ar / tbox_backup=r 이어야 한다
sudo systemctl start php8.1-fpm                             # --stop-service 를 썼다면
```

| 3 | `sha256sum -c` 로 산출물 무결성 확인 | 깨진 백업으로 덮는 것은 아무것도 안 하는 것보다 나쁘다 |
| 4 | `gpg -d \| pg_restore --clean --if-exists` (역할 `tbox_owner`) | 평문 덤프를 디스크에 남기지 않는다 |

### 서버 기준선 점검 (T-17 ~ T-19)

```bash
sudo bash scripts/check_baseline.sh      # 읽기 전용. 아무것도 바꾸지 않는다
sudo bash deploy/hardening.sh            # 무엇을 바꿀지 출력만 (dry-run)
# 적용 — ★ 콘솔에서, 또는 다른 SSH 창을 하나 더 열어 둔 채 사람이 직접
sudo bash deploy/hardening.sh --apply --i-have-a-second-session \
     [--admin-net 10.0.4.0/24] [--allow-users "changkwon@10.0.4.0/24"] \
     [--sudo-password changkwon] [--lock-user eric]
```

> `--apply` 는 **원격 SSH 세션을 끊을 수 있습니다.** `ufw enable` 은 기본 거부 상태로 켜지고,
> `PasswordAuthentication no` 는 공개키를 등록하지 않은 계정을 잠급니다.
> 적용 전에 ① 공개키 로그인이 되는지 ② VM 콘솔로 들어갈 방법이 있는지 ③ 관리망 대역이 맞는지 확인하세요.

**순서는 출력 → 협의 → 적용입니다.** 먼저 옵션 없이 돌려 무엇이 바뀌는지 보고(위 1행),
내 계정이 아닌 것(`eric` 등)은 **계정 소유자(강사)와 협의**한 뒤, 마지막에 `--apply` 를 줍니다.
`--apply` 는 `--i-have-a-second-session`(다른 SSH 창·콘솔을 열어 두었다는 확인) 없이는 거부합니다.

| 옵션 | 뜻 | 기본 |
|---|---|---|
| `--admin-net <CIDR>` | 22 번을 허용할 관리망 대역 | `10.0.4.0/24` (사용자의 실제 SSH 출처 `10.0.4.173` 이 있는 대역) |
| `--allow-users "<계정>@<대역>"` | sshd `AllowUsers` 로 **접속 계정·출처**를 제한 | 넣지 않음 |
| `--sudo-password <계정>` | `/etc/sudoers.d/99-<계정>-nopasswd` 를 `ALL=(ALL:ALL) ALL` 로 바꿔 sudo 에 비밀번호를 요구 (`visudo -c` 검사, 실패 시 원복) | 현황만 출력 |
| `--lock-user <계정>` | `passwd -l <계정>` — **협의 후에만** | 하지 않음 |
| `--from-ip <IP>` | 현재 세션 출처 IP 를 직접 지정 (자동 탐지 실패 시) | 자동 탐지 |

> **자기 잠금 방지**: 스크립트는 현재 세션의 출처 IP를 찾아, 그 IP가 `--admin-net` 과
> `--allow-users` 안에 들어 있는지 먼저 검사하고 **아니면 거부**합니다(종료 코드 2).
> 예전 기본값 `192.168.0.0/16` 은 관리자의 출처(`10.0.4.173`)를 **빼고** 침입 출처(`192.168.200.50`)를
> **넣는** 값이었습니다 — 그래서 기본값을 `10.0.4.0/24` 로 바꿨습니다(더 넓게 필요하면 `--admin-net 10.0.0.0/8`).

> **실효값은 `sshd -T` 로 검증합니다** — 파일을 썼다고 적용된 것이 아닙니다.
> `/etc/ssh/sshd_config` 의 `Include /etc/ssh/sshd_config.d/*.conf` 는 **글꼴 순서**로 읽고
> sshd 는 **같은 키워드의 첫 값이 이깁니다.** 이 서버의 `50-cloud-init.conf` 는 `PasswordAuthentication yes`
> 라서, 예전 드롭인 이름 `tbox.conf` 로는 적용해도 비밀번호 로그인이 그대로 켜져 있었습니다(SECURITY 8.4-12).
> 그래서 드롭인 이름은 **`00-tbox.conf`** 이고, 충돌하는 남의 드롭인은 `--apply` 때
> `<이름>.conf.disabled-by-tbox-<날짜>` 로 **이름만 바꿔**(삭제하지 않고) Include 에서 뺍니다.
> 적용 뒤에는 `sshd -T` 의 `passwordauthentication`·`permitrootlogin`·`maxauthtries`·`allowusers` 를
> 목표값과 문자열로 대조해 하나라도 다르면 **실패(종료 코드 2)** 로 끝납니다. 직접 볼 때는:
>
> ```bash
> sudo sshd -T | grep -iE 'passwordauth|permitroot|maxauth|kbdinteractive|allowusers'
> ```

### ★ 로그인 실패는 「누가」로 찾을 수 없습니다

`auth.login` 은 세션이 만들어지기 **전**이라 `actor_name` 이 비어 있습니다 (`ARCHITECTURE.md` 7.3).
입력된 아이디는 **`target_name`** 에 남습니다. 그래서 "이 계정으로 로그인 실패가 몇 번 있었나" 는
「누가」가 아니라 **「무엇을(target)」 필터에 계정명**을 넣어 찾습니다.

```bash
# 화면·API
curl -s -b jar 'http://127.0.0.1:8082/tbox/api/audit?action=auth.login&result=deny&target=employee01'

# psql 로 직접
sudo -u postgres psql -d tbox_re -c "
  SELECT happened_at, target_name, ip, reason, summary
    FROM audit_logs
   WHERE action='auth.login' AND result='deny'
   ORDER BY id DESC LIMIT 20"
```

같은 이유로 **운영 배치(9단계)** 행도 `actor_*` 가 비어 있습니다 — cron 이 남긴 것이라 사람이 없습니다.
`action` 으로 고릅니다: `file.purge` · `backup.run` · `backup.restore` · `audit.integrity` · `alert.raised`.
(`user_agent` 가 `cli:스크립트명`, `detail.route` 가 `cli:스크립트명` 입니다.)

### ★ 내 행동과 AI 검토 행동 가르기

AI(Claude)의 검토 요청은 **두 겹**으로 표시됩니다 (`PRD.md` S-07 "검토 요청 표식").

1. 계정이 `claude_` 로 시작합니다 (`claude_admin01`·`claude_manager01`·`claude_employee01`·`claude_employee02`·`claude_guest01` — 2026-09-24 부터의 새 시험) — 또는 `qa_` 로 시작합니다 (`qa_admin01` …`qa_guest01` — 옛 시험)
2. `User-Agent` 가 `tbox-review/<날짜>` 입니다

둘 다 아니면 사용자(또는 침입자)의 행동입니다. 감사 로그 화면(`/tbox/audit`)은 둘 다 맞는 행의 「누가」 칸에 배지 **「Claude」** 를, 한쪽만 맞는 행에 **「확인 필요」** 를 붙입니다(판정은 서버 `src/Origin.php` — 표식은 흉내 낼 수 있어서 둘 다 맞을 때만 Claude 로 봅니다).

```sql
-- 사용자 행동만 보기 — 「검토 계정 **그리고** 검토 UA」인 행만 뺀다(화면 배지와 같은 규칙 · src/Origin.php)
-- 한쪽만 맞는 행(UA 만 흉내 낸 사람 · 남의 검토 계정 이름을 댄 로그인 실패)은 **남는다** — 그것이 볼 것이다
SELECT happened_at, actor_name, target_name, ip, action, result, summary
  FROM audit_logs
 WHERE NOT (
         (COALESCE(actor_name, '') LIKE 'qa\_%' OR COALESCE(actor_name, '') LIKE 'claude\_%'
          OR (actor_name IS NULL AND action = 'auth.login' AND result = 'allow'
              AND (COALESCE(target_name, '') LIKE 'qa\_%' OR COALESCE(target_name, '') LIKE 'claude\_%')))
         AND COALESCE(user_agent, '') LIKE 'tbox-review/%')   -- COALESCE: NULL 이 섞이면 NOT(…) 이 NULL 이 되어 행이 사라진다
 ORDER BY id DESC LIMIT 20;
```

#### 해시 체인 — 봉인 시점과 재봉인 (2026-09-12, `SECURITY.md` R-50)

cron 은 00:05 에 **어제** 회전 파일을 봉인합니다. `--verify` 는 체인에 **오늘** 날짜 항목이 있으면
「열린 날 — 검산 제외」로 표기하고 실패로 세지 않습니다(오늘 파일은 하루 종일 자라므로 해시가
확정값이 아닙니다).

**오늘은 봉인할 수 없습니다** — `sudo php scripts/audit_chain.php --date $(date +%F)` 는
`[사용법 오류] 오늘(열린 날)과 미래 날짜는 봉인하지 않는다 — 어제 이전만` 을 내고 끝냅니다
(체인 파일·감사 기록을 건드리기 전입니다). 오늘 값을 적어 두면 내일의 `--yesterday` 가 그 날을
만나 해시가 달라 AL-6 헛경보를 냅니다. 오늘 상태가 궁금하면 `--verify` 를 쓰세요.

2026-09-12 이전에는 인자 없이 **오늘**을 적어, 00:00 회전 직후의 빈 파일(0줄)이 봉인되고 어제는
봉인되지 않았습니다. 그래서 `--verify` 가 매일 실패하고 AL-6 헛경보가 났습니다 — 변조가 아니라
설계 결함이었습니다. 그때 잘못 적힌 항목은 **사람이 한 번** 바로잡습니다.

```bash
sudo php scripts/audit_chain.php --verify              # 지금 상태 보기 (열린 날은 제외 표기)
sudo php scripts/audit_chain.php --reseal 2026-09-11   # 닫힌 날 하나를 다시 봉인 (일회성)
sudo php scripts/audit_chain.php --verify              # 다시 검산해 통과를 확인
```

`--reseal` 은 다음을 함께 합니다.

| 무엇 | 어떻게 |
|---|---|
| 옛 값 보존 | 덮어쓰기 **전**의 해시·줄수·바이트수를 `audit.integrity allow` 의 `detail.resealed_from_hash`·`resealed_from_lines`·`resealed_from_bytes` 에 남깁니다. 이 기록이 없으면 재봉인은 증거 조작과 구분되지 않습니다 |
| 연결 복구 | 그 항목의 해시를 갱신하고 **뒤따르는 항목의 `prev` 를 다시 잇습니다**(`detail.relinked` = 다시 이은 개수) |
| 범위 제한 | 날짜 하나만 받고, 오늘·미래에는 쓸 수 없습니다. `--reseal` **없이** 닫힌 날이 달라지면 지금처럼 AL-6 경보를 남기고 체인을 고치지 않습니다 — 그것이 변조 신호입니다 |

**빈 자리표시 항목은 cron 이 스스로 메웁니다** — 옛 결함이 남긴 `<날짜> e3b0c4… <prev> 0 0`
(0줄 0바이트 = 빈 파일의 해시) 줄은 "그 날의 확정 해시" 가 아니라 **한 번도 봉인되지 않은 자리표시**
입니다. 그 날짜를 봉인할 차례가 오면 cron 이 AL-6 없이 처음 봉인하듯 갈아 끼우고, 감사 로그
(`audit.integrity allow`)의 `detail` 에 `placeholder: true` 와 옛 값(`resealed_from_hash`·
`resealed_from_lines`·`resealed_from_bytes`)을 남깁니다. 그래서 `--reseal` 을 손으로 돌릴 필요가
있는 것은 **자리표시가 아닌** 닫힌 날(실제 값이 적혀 있는데 달라진 날)뿐입니다.

체인 파일 `/var/lib/tbox-v2/audit-chain.txt` 는 `0600 root` 라 `sudo` 로만 다룹니다.

파일 내용은 남기지 않고 `detail.sha256` 으로만 가리킵니다.

## 검토 계정 (`claude_*` · `qa_*`) — 운영 배포에서는 만들지 않습니다

`scripts/seed_users.php` 는 기본으로 시드 계정 5개와 **검토 계정 10개**를 함께 만듭니다(역할·팀은 같은 이름의 시드 계정과 같습니다).

| 접두 | 계정 | 쓰임 |
|---|---|---|
| `claude_` | `claude_admin01` · `claude_manager01` · `claude_employee01` · `claude_employee02` · `claude_guest01` | **새로 쓰거나 고치는 시험** (2026-09-24, `PRD.md` F-71) |
| `qa_` | `qa_admin01` · `qa_manager01` · `qa_employee01` · `qa_employee02` · `qa_guest01` | 옛 시험 — 지우지 않습니다(옛 기록 확인용) |

검토 계정은 AI 검토(관문 ②)가 남기는 행을 사용자의 행동과 갈라 놓기 위한 것이며, **과제 환경 전용**입니다.
`claude_guest01` 은 만들 때부터 **90일 뒤 만료**됩니다(Guest 규칙, `SECURITY.md` R-12) — 연장은 계정 관리 화면에서 사유와 함께 합니다.

```bash
php scripts/seed_users.php --no-qa        # 검토 계정(qa·claude 둘 다)을 만들지 않는다 (운영 배포)
php scripts/seed_users.php --claude-only  # claude_ 5개만 (시드·qa 는 보지도 않는다)

# 새 claude_ 계정의 첫 로그인 절차(비밀번호 변경 → 2단계 등록)는 창구를 그대로 타는 CLI 로 마칩니다.
# 비밀번호·2단계 비밀은 명령 인자·화면에 나오지 않고 /etc/tbox-v2 의 두 파일(0600 root)에만 적힙니다.
sudo php scripts/review_account_setup.php claude_admin01 claude_manager01 claude_employee01 claude_employee02 claude_guest01

# 이미 만들어진 검토 계정을 막으려면: 지우지 말고 **비활성화**합니다.
# users 를 지우면 files·audit_logs 의 참조가 깨집니다 (감사 추적이 끊어집니다).
# 한두 개면 계정 관리 화면(/tbox/users, F-10)에서 사유와 함께 — 누가 왜 막았는지 감사에 남습니다.
# 아래 psql 은 운영 배포 전 일괄 정리용(사용자 몫)이고 감사에 남지 않습니다.
sudo -u postgres psql -d tbox_re -c "UPDATE users SET is_active=false WHERE username LIKE 'qa\_%' OR username LIKE 'claude\_%'"
sudo -u postgres psql -d tbox_re -c "DELETE FROM sessions WHERE user_id IN (SELECT id FROM users WHERE username LIKE 'qa\_%' OR username LIKE 'claude\_%')"
```

시험 스크립트의 「사용자가 지금 쓰는 중인가」 검사(`SECURITY.md` R-73)는 두 접두를 모두 검토 계정으로 셉니다 — 판정 조각은 `tests/lib/review_accounts.sh` 한 곳입니다.
