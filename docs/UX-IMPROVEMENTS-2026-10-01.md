# Qaredi 업무 화면 개선 — 2026-10-01

사용자 「진행 해」에 따라 디자인 감사의 개선안을 화면에 연결했다. Astra·Aurora·Bloom·Nova가 같은 작업 흐름을 쓰고 Claude는 원래 파일 행 배치를 유지한다. 편집기·문서 스키마·문서 팔레트·서버 정책은 이번 변경 대상에 포함되지 않는다.

## 동작과 데이터

행 메뉴는 서버가 내려 준 can_edit·can_delete로 이미 만들어진 원래 버튼을 사용한다. 공유의 실행 파일 제외, 검사 중/격리 파일의 미리보기·받기 제한, 삭제 확인, 실행 파일 재인증 처리는 기존 코드가 계속 담당한다. 메뉴를 여는 요청은 없다. 버튼을 숨기는 것은 편의이며 서버는 매 요청 다시 권한을 판정한다.

홈은 먼저 기존 계정 API를 읽고, 계정 절차가 남아 있지 않을 때만 두 모듈의 개인 목록을 읽는다. 제목은 textContent, 문서 경로는 검증한 UUID, 파일 검색은 URL 인코딩을 쓴다. 빠른 보기 전환은 이전 응답을 버린다. 401은 목록을 비우고 재로그인 안내, 모듈 한쪽 실패는 성공한 쪽과 재시도 안내를 보여 준다. 주기적 요청은 없다.

미로그인 홈에는 개인 작업 마크업과 start.js가 없다. Claude에서는 개인 작업 영역을 숨기고 API를 부르지 않는다. 테마 미리보기를 취소해 Claude로 돌아가면 표시된 개인 목록을 지운다. 기존 로그인·쿠키·Authz·CSP·DB·API 구현은 수정하지 않았다. 원본 app.css도 유지한다.

## 확인 방법

`python3 tests/ux_browser.py`는 실제 PHP 화면과 app.js/design.js/start.js를 실행하고 API만 합성 응답으로 대체한다. 긴 한글 파일명·HTML 형태 문자열·권한별 메뉴·검사/실행 파일·원래 확인 창·Escape/초점·검색/빈 목록·최초 절차·5테마/2밝기/360·412·820·1280·1440px·최근/즐겨찾기·잘못된 UUID·null 항목·6건 제한·부분 실패·401·이전 응답 무시·미로그인 비노출·커뮤니티 읽기 폭을 확인한다. 합성 API 검증은 운영 서버의 인가 검증을 대체하지 않는다.

배포 후에는 예약된 검토 계정으로 실제 JS/API의 읽기 전용 화면을 확인한다. 생성·수정·공유·삭제·문서 편집·DB 쓰기 요청을 보내지 않는다. 결과는 `docs/ux-results.json`과 보안 검토 이력에 기록한다.
