# 커뮤니티 공유·연동 사용 안내

커뮤니티 왼쪽 「모음」의 「공유·연동 설정」에서 모음, 권한 그룹, 내 웹 공개, 메신저 알림을 관리합니다.

- **모음**: 「모음 만들기」로 이름과 상위 모음을 정합니다. 페이지 더보기의 「모음에 넣기」로 정리합니다. 나만 보는 목록이며 페이지 권한은 바뀌지 않습니다. 3단계 깊이, 50개 모음, 모음마다 500개 페이지까지 지원합니다. 볼 수 없어진 페이지는 목록에서 빠지고 권한이 돌아오면 다시 보입니다.
- **권한 그룹**: 관리자와 Manager가 그룹을 만들 수 있습니다. Manager는 현재 자기 팀원과 자신만 넣습니다. 페이지 더보기의 「그룹에 공유하기」에서 보기·편집을 고릅니다. 구성원을 추가하면 그룹에 공유된 페이지가 즉시 열리고, 빼거나 그룹을 삭제하면 그 권한이 즉시 사라집니다. Guest에게 편집 권한을 주어도 편집할 수 없습니다.
- **동기화 블록**: 페이지 더보기의 「동기화 블록」에서 본문을 원본 묶음으로 만들고 원본 번호를 복사합니다. 다른 페이지의 같은 메뉴에 원본 번호를 넣으면 참조가 생깁니다. 원본 페이지에서 내용을 고치며 참조는 읽기 전용입니다. 원본을 볼 수 없는 사람에게 내용이 전달되지 않습니다. 이 메뉴에서 현재 볼 수 있는 사용처도 확인합니다.
- **웹 공개**: 관리자가 공간의 웹 게시를 허용한 뒤, 페이지 관리자가 더보기의 「웹에 공개하기」를 사용합니다. 공개할 하위 페이지를 직접 고르고 만료와 공개 확인을 설정합니다. 주소는 한 번만 표시됩니다. 주소를 아는 누구나 읽을 수 있고 이후 수정 내용도 반영됩니다. 첨부, 댓글, 속성, 내부 멘션 이름은 공개하지 않습니다. 공개 배지와 「웹 공개 회수」 메뉴로 상태를 확인하고 닫습니다.
- **공개 폼**: 먼저 DB 페이지에 웹 공개 주소를 만듭니다. 폼 뷰 설정에서 「웹 공개 폼」과 「응답 받기」를 켭니다. 공개 주소 뒤에 `/form/뷰번호`를 붙이면 로그인 없는 제출 화면이 열립니다. 글·숫자·체크·날짜·선택 질문만 지원합니다. 답변의 IP를 행에 저장하지 않으며, 응답은 DB 편집자와 응답 행을 직접 공유받은 사람에게만 보입니다. 로그인하지 않은 제출자는 응답 행 주소를 받지 않습니다.
- **메신저 알림**: 관리자가 등록한 연결에서 받을 종류만 선택합니다. 등록된 연결이 없어도 정상입니다. 실제 연결 대상은 나중에 지정할 수 있습니다. 비공개·팀 범위 페이지는 제목을 숨기고, 알림 종류와 Qaredi 주소만 보냅니다. 본문·댓글·행위자 이름을 보내지 않습니다.
- **외부 데이터**: 관리자가 대상 DB, 공개 HTTPS 호스트, API 경로, 실행 주기, 원본 키→속성 키 연결을 등록합니다. 원본 응답은 `external_key`가 있는 JSON 행 배열입니다. 같은 키는 갱신하고 사라진 행은 삭제하지 않고 「원본에 없음」으로 표시합니다. 가져온 값은 읽기 전용이며 본문·댓글은 쓸 수 있습니다.

## 관리자 연결 설정

「공유·연동 설정」 → 「관리자 연결 설정」 → 「설정 열기」에서 재인증 후 등록·수정·중지합니다. 등록은 기본 중지 상태입니다. 비밀 주소나 키를 웹 화면에 입력하지 않습니다. 연결할 실제 대상은 추후 지정하며, 가짜 자격정보를 생성하지 않습니다.

등록 결과에 표시되는 숫자를 사용해 서버 운영자가 다음 파일을 준비합니다.

| 용도 | 파일 | 소유권·권한 | 내용 |
|---|---|---|---|
| 메신저 | `/etc/tbox-v2/hooks/<숫자>.url` | `root:tbox-php`, `0640` | 등록한 호스트와 일치하는 HTTPS 웹훅 주소 |
| 외부 API | `/etc/tbox-v2/connectors/<숫자>.key` | `root:tbox-php`, `0640` | Bearer 인증 키 |

화면은 파일 내용 대신 준비 여부만 표시합니다. 파일이 없으면 `secret_missing`으로 기록되고 전송하지 않습니다. 파일의 소유자·그룹·권한·일반 파일 여부를 확인하며 심볼릭 링크를 읽지 않습니다. 외부 연결은 HTTPS 443만 허용하고, DNS 결과에 사설·특수 IP가 있으면 거부하며 리다이렉트를 따라가지 않습니다. 메신저, 외부 API, t-box 파일 가져오기의 호스트 목록은 서로 독립입니다.

기존 자동 작업 배치가 연결을 실행합니다. 새로운 cron이나 시스템 계정을 만들지 않습니다. 실행 직전에 받는 사람·실행자의 현재 권한을 다시 확인합니다. 외부 데이터 실행자가 권한을 잃으면 연결을 중지하고 알림을 남깁니다. 메신저 실패는 1·5·30분 간격으로 세 번 더 시도한 후 실패 처리합니다.

## 구현·통합 메모

- 마이그레이션은 `2026-10-03_community_groups_synced.sql`, `2026-10-04_community_web_publish.sql`, `2026-10-05_community_outbound.sql` 세 파일입니다. `tbox_owner`로 실행한 뒤 `db/community/grants.sql`을 적용합니다. 공개 폼에는 11단계 DB 뷰 마이그레이션이 먼저 필요합니다. 기존 정리 함수는 수정된 `2026-09-26_community_purge.sql`로 갱신합니다.
- `community_sync_after_save()`는 10단계 공통 저장 hook 안에서 같은 트랜잭션으로 실행합니다. 신규 source UUID의 동시 저장도 소유권 조건이 붙은 upsert와 rowCount 검사로 하나의 페이지에만 귀속시킵니다.
- 공개 폼과 외부 데이터 새 행은 11단계 `community_insert_page()`를 사용합니다. 공개 폼만 actor를 NULL로 넘기며 `public_form_response` CHECK로 제한합니다. 공개 응답 내용은 일반 page.create 감사에 넣지 않습니다.
- nginx 공개 경로에는 독립 60회/분, 제출 경로에는 5회/분 제한과 64KB 본문 상한을 둡니다. 원문/정규화 경로 로그를 가리고 공개 location의 오류 로그에 토큰을 기록하지 않습니다. nginx가 직접 내는 429·413에도 no-store를 붙입니다.
- JS 부품은 통합이 끝난 뒤 `php scripts/community_asset_version.php`로 버전을 다시 찍습니다.

## 검증

`tests/community/stage12_harness.py`는 고유한 `tbox_stage12_test_` DB, 가짜 계정, 로컬 포트 8678·8679만 사용하고 종료 때 제거합니다. 운영 업무 데이터를 복사하지 않습니다.

```sh
python3 tests/community/stage12_harness.py --port 8678 --suite stage12_extended.py --output ../extended12-evidence
python3 tests/community/stage12_harness.py --port 8678 --suite stage12_browser.py --output ../browser12-evidence
python3 tests/community/stage12_harness.py --port 8678 --suite stage12_nginx.py --output ../nginx12-evidence
python3 tests/community/stage12_transport.py --output ../transport12-evidence
bash scripts/security_lint.sh
```

전송 검증은 기본 경로가 없는 네트워크 namespace의 가짜 DNS·HTTPS 수신기와 실제 TLS 검증을 사용합니다. Fetch 구현에 테스트 우회를 넣지 않습니다. 실제 메신저나 외부 데이터 대상에는 접속하지 않습니다. nginx 검증은 배포 사본의 공개 제한·헤더·로그 규칙을 그대로 읽고, PHP 연결 부분만 소유한 HTTP 테스트 서버로 연결합니다. 운영 프록시의 캐시 정책과 실제 대상 인증·응답 계약은 대상 지정 및 운영 반영 때 별도로 확인합니다.
