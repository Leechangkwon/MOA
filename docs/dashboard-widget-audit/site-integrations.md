# 사이트·공간·통합 기능 실물 코드 감사

기준: 운영 checkout `/var/www/qaredi/tbox-v2` HEAD `93668ff`. 실제 route/handler/view/assets 읽기만 수행. 운영 API 호출·DB 조회·외부 제공자 호출·설정 파일 값 조회·코드 수정 없음. 따라서 아래 **구현·배포 코드 존재**는 확인했지만 현재 계정별 사용 가능/외부 연결 성공은 별도 상태다. S/M/L은 제안이며 현재 구현된 고정 preset이라고 해석하지 않는다.

- **구현·배포 코드 존재**: 라우트와 실행 핸들러/화면 있음. 세션/권한/동의 조건 충족시 사용 경로가 있으나 이번 감사에서 로그인 실사용을 확인하지 않음.

## S/M/L 및 잠금 설계에 넘길 제약

1. 사용자 결정은 **위젯별 잠금 + 전체 배치 저장**이다. 현재 v2 서버widget schema에는 id/visible/desktop/mobile만 있고 lock·preset field는 없다 (`/var/www/qaredi/tbox-v2/src/site/ProductSpaces.php:169`). 따라서 잠금은 아직 구현됐다고 주장할 수 없다. 영구 저장하려면 root가 schema/API 호환계약을 먼저 확정해야 한다. 기존 GET 무쓰기·revision원자성 유지.
2. 크기와 정보밀도는 구분한다. S 제목·핵심한줄, M 주요목록, L 필터/상세; 숨김이 데이터 삭제를 의미하지 않고 사용자입력 draft/권한/비밀은layout에 넣지 않는다. 전체페이지 기능을 단순히 좁은카드로 잘라 넣지 않는다.
3. 위젯잠금은 이동·resize·hide 등배치조작만 제어할지 정보action까지 막을지 명시해야 한다. 완료하기·읽음·다운로드·대화송신을배치잠금에묶으면 기능손실 발생. 콘텐츠 권한은서버기존검증 그대로.
4. AI/connector/PC/MCP를 단일 'AI 연결됨'으로 합치지 않는다. 서버Gemini, community AI, 브라우저localhost ChatGPT, 외부buddy scopedtoken, ChatGPT 원격MCP는 준비조건·권한·데이터·고장경로가 다르다.
5. 기능사용가능 taxonomy는 비로그인/첫로그인동의/Guest/acting/뷰어/보관/설정미완료/외부실패/empty를 구분. 인증/보안/초대secret/관리기능은 페이지 또는 modal로 남긴다.
6. 현재 product-home activity는 notice/task/event만, 공간 story는 텍스트 항목만, 회사/모임은 동일 5종을 사용한다. **제품 공간 전용** 일정 달력·공간별 사진 갤러리·전체 제품을 합친 unread 집계가 이미 존재한다고 분류하지 않는다. 커뮤니티에는 별도의 작업/DB 달력과 사진 앨범이 있다. T-box 교차조사로 **공통 셸의 문서·댓글·파일 통합 검색은 이미 구현**됐음을 확인했다(`public/assets/search.js:212`, `:254`; 두 API를 합성). 이는 제품 공간 콘텐츠까지 검색하는 단일 전역 API와는 다르다.

## 미검증/후속 확인

실제flags·quota·provider준비·MCP운영allowlist·PC설치/승인·connector스케줄실행·notificationdelivery는 확인하지 않았다. 비밀없는 ready/status API의 사용권한 있는 실제사용자 읽기 확인 또는 root운영상태자료가있을때만 '사용가능'으로 승격한다. 본 감사는 코드기반 taxonomy이며 기능 실행승인/새 UX 구현검토/배포완료 판단이 아니다.
