# 모아 대시보드: 전체 기능 조사와 위젯 콘텐츠 설계

2026-10-11 · 기준 코드 `93668ff466ba604d99deb266c26a50707c83b62f` · 운영 기록 v2.55.0

**문서 상태: 기능 조사 완료 후 제안하는 설계안. 새 위젯·소/중/대·개별 잠금은 아직 구현하거나 운영 반영하지 않았다.** 사용자가 확정한 요구와 아래의 설계 제안을 구분한다. 세부 픽셀 값·기본 구성·우선순위는 제안이며 사용자가 확정한 값이 아니다.

## 1. 결론과 사용자 요구

대시보드는 **내가 참여하는 회사·모임의 일을 확인하고, 필요한 행동을 시작하는 개인 첫 화면**으로 설계한다. 회사·모임의 공동 홈은 그 공간의 공지·업무·활동을 보여 주는 별도 문맥이다. 같은 위젯 부품을 사용하되 개인의 메시지·여행·작업을 공동 홈의 공용 정보로 취급하지 않는다.

현재 개인 홈은 최근 작업·서비스 안내·연락/시작 안내·이야기라는 큰 영역 4개를 옮기고 줄이는 구조다. 공간 홈은 공지·할 일·일정·자료·이야기 5종이다. 기존 화면을 상자에 넣어 크기를 바꾸는 방식에서는 작은 상자에 버튼과 긴 본문이 남는다. **먼저 한 가지 목적을 가진 위젯으로 나누고, 소·중·대별 정보와 행동을 정의해야 한다.**

사용자가 확정한 요구:

- 첫 가입 후 기본 대시보드와 기능별 안내를 제공한다.
- 필요한 위젯을 골라 대시보드에 등록하고 드래그로 위치를 조정한다.
- 위젯 크기는 소·중·대처럼 선택하기 쉬워야 하며 크기별로 보여 주는 내용이 달라야 한다.
- 각 위젯의 위치·크기를 잠그고, 전체 배치를 저장한다.
- 크기 조절·잠금·저장 기능을 사용자가 눈으로 발견할 수 있어야 한다.
- 기능을 상세히 파악한 뒤 설계한다. 버튼 과다, 한글 잘림, 단조로운 화면을 반복하지 않는다.

## 2. 조사 범위와 판단의 한계

실제 라우트 → 핸들러/서비스 → 화면/자산을 대조했다. 이전 기획 문서나 테스트 이름만으로 구현 여부를 판단하지 않았다. T-box 178, 커뮤니티 206, MCP 11개의 **라우트 선언 395개**와 표 밖의 런처/MCP 진입점을 대조했다. 이는 기능 수가 아니며 정적 파일·작업기까지 합한 전체 실행 경로 수라는 뜻도 아니다. 라우트 원문과 도메인별 근거는 부록에 보관한다.

| 조사 영역 | 상세 근거 |
|---|---|
| 자료실·파일·폴더·공유·권한·관리 | [T-box 기능 조사](dashboard-widget-audit/tbox.md) |
| 업무·문서·프로젝트·DB 보기·이야기·여행 | [커뮤니티 기능 조사](dashboard-widget-audit/community.md) |
| 가입·개인 홈·회사/모임 공간·메신저·AI·연결 | [사이트와 통합 기능 조사](dashboard-widget-audit/site-integrations.md) |
| 전체 라우트와 누락 교차 점검 | [기능 범위 대조](dashboard-widget-audit/coverage.md), [라우트 목록](dashboard-widget-audit/route-inventory.json) |

‘구현 확인’은 이 기준 코드에 실행 경로가 있다는 뜻이다. 이번에는 운영 API를 호출하거나 실제 사용자 데이터·설정 비밀값을 읽지 않았다. AI 제공자, 원격 MCP, PC 설치, 외부 알림, 수집기, 예약 작업의 현재 연결 성공은 **조건부·운영 상태 미확인**으로 분류한다. 회사 전체 사용량·실제 인기 기능·빈 화면 비율은 측정하지 않았으며 만들어 내지 않는다.

## 4. 소·중·대의 의미

**소는 확인, 중은 실행, 대는 비교·계획**이다. 같은 제목·출처·주행동을 유지하면서 목록 수·문맥·보기 방식을 바꾼다. 본문 폰트나 버튼을 비례 축소하지 않는다.

| 크기 | 사용자가 바로 답을 얻을 질문 | 표시 원칙 |
|---|---|---|
| 소 | 지금 가장 필요한 것이 무엇이지? | 우선 항목 1~2개 또는 정의가 분명한 지표 1개. 출처와 상태. 대표 행동 1개 |
| 중 | 지금 여기서 무엇을 처리하면 되지? | 우선 항목 3~5개, 필요한 기한/작성자/프로젝트, 가능한 간단 동작 |
| 대 | 여러 항목을 어떻게 비교하고 계획하지? | 6~10개 내외, 날짜/상태 묶음 또는 적절한 달력·보드·차트. 필터와 전체 보기 |

표시 개수는 최대치다. 긴 한국어 제목·확대 글꼴·필요한 정보가 있으면 개수를 줄인다. API에서 받은 항목 수를 전체 건수로 표현하지 않는다. 불필요한 빈칸을 채우려고 가짜 데이터나 장식을 추가하지 않는다.

### 크기와 자유 조절의 관계 — 제안

- 편집 시 눈에 보이는 **소 / 중 / 대** 버튼을 기본 조작으로 제공한다. 선택 즉시 위젯별 추천 폭·높이와 해당 콘텐츠 표현을 미리 보여준다.
- 드래그 이동은 유지한다. 정렬 가이드는 돕는 기능이며 임의 위치·의도한 여백을 강제로 없애지 않는다.
- 사용자가 앞서 요청한 가로·세로 자유 조절은 보조 기능으로 유지한다. 직접 조절할 때 실제 폭·높이에 맞는 소/중/대 표현으로 전환하고 선택 표시도 함께 바꾼다. 확대 시 상위 표현의 최소 폭·높이를 모두 충족해야 상향하고, 축소 시 가독성이 부족해지기 전에 하향한다. 경계에서 반복 전환되지 않도록 여유 구간을 둔다. 읽을 수 없는 최소 크기 아래로는 줄이지 않는다.
- 데스크톱 시작 치수 예시: 목록형 소 약 300×200, 중 480×320, 대 720×440. 최종 치수는 콘텐츠 시험 후 결정하고 화면 비율로 글자를 줄이지 않는다. 달력·사진·수치형은 각자의 최소 크기를 갖는다.
- 휴대폰 기본은 한 열, 같은 폭이다. 소·중·대는 주로 높이·표시 정보량을 바꾼다. 한 열은 추천값이지 모든 화면에 강제하는 규칙이 아니다. 읽을 수 있는 최소 폭과 화면 경계 안에서 자유 위치·폭 조절을 유지하고, 두 칸이 들어가지 않는 작은 화면에는 한 열이 남는다. PC와 휴대폰의 배치는 별도 저장한다.
- 대형 보드/달력이 휴대폰에 들어가지 않으면 날짜/상태별 목록으로 표현한다. 가로 스크롤로 작은 글씨를 읽게 하지 않는다.
- 목록 위젯은 기본적으로 내부 스크롤 없이 제한된 항목+‘전체 보기’로 마무리한다. 긴 대화처럼 스크롤이 본래 행동인 위젯만 명시적으로 예외를 둔다.

별도 대형 위젯보다 공통 내비게이션이 적합한 것: 서비스 목록, 공간 전환, 문서/파일 검색, 계정·테마 설정. 계속 사용할 수 있게 두되 홈 전체를 차지하는 안내 카드로 반복하지 않는 안을 권장한다.

이름이 비슷해도 데이터 계약이 다르면 각각 카탈로그 항목으로 제공한다. ‘사진 이야기’에는 모임별 피드 필터가 현재 있다고 가정하지 않는다. 선택한 회사·모임의 것만 보여 주려면 별도 연결 기능이 필요하다. W29의 기존 공유 목록에는 원문 URL이 없으므로 ‘링크 다시 복사’를 만들지 않는다. W31은 최대 하나의 현재 게시 프로그램이며 PC 설치 여부·업데이트 필요 여부를 자동 판정하지 않는다. W26의 통합 관리 요약은 아직 별도 조회 계약이 필요하다.

카탈로그 자체도 계정 자격과 실제 준비 상태를 확인한다. 여행은 현재 Guest의 단순 읽기도 허용하는 기능이 아니다. W24의 템플릿 생성·W30 업로드 등 쓰기 행동은 현재 역할로 보기/쓰기 자격·원본 목적지 권한을 충족할 때만 제공한다. 일반회원 폼 제출과 공개 폼 제출은 각 원본 정책을 따르며 문서 수정 권한과 일괄 동일시하지 않는다.

W25의 서버 비서 runs는 `assistant.run` 개인 토큰 경로이고, 현재 run Provider의 일반 추론은 미연결 상태로 정의돼 있다(명시적 도구 실행/격리 테스트 경로와 구분). 별도의 chat 경로와 웹/커뮤니티 AI를 같은 준비 상태로 표시하지 않는다. 브라우저 세션 위젯이 이 API를 바로 부를 수 있다고 가정하거나 개인 토큰을 레이아웃에 넣지 않는다. 실행 이력 위젯에는 별도 세션 읽기 계약이 필요하다. 화면 호출이 없는 커뮤니티의 옛 GPT 경로는 활성 도구 목록에 포함하지 않는다.

### 개인 홈과 공동 홈의 배치 가능 범위

| 범위 | 후보 | 공동 홈에서의 원칙 |
|---|---|---|
| 개인 전용 | W01~W04, W17~W19, W21~W23, W28~W29 | 개인 대시보드에서만 추가. 내 작업·메시지·여행·공유받은 자료를 공동 기본 배치에 넣지 않음 |
| 선택 공간 콘텐츠 | W05~W09 | 공동 홈에서는 그 공간으로 출처 고정. 원본 파일 권한도 별도 적용 |
| 원본 선택형 | W11~W16, W20, W24, W27 | 공동 배치 지원은 후속 설계. 원본이 공동 표시 가능한 범위인지 저장 시 확인하고 방문자별 권한으로 조회. 편집자에게만 보이는 제목을 저장해 다른 구성원에게 노출하지 않음 |
| 개인 피드·도구 | W10, W25, W30, W31 | 초기에는 개인 선택형. 공동 사진 피드/공유 업로드 정책은 별도 설계 |
| 관리자용 | W26 | 관리자 개인 홈에서만. 글로벌 관리자 권한과 제품 공간 관리자 권한을 혼동하지 않음 |

첫 단계의 공동 홈은 기존 다섯 콘텐츠 종류를 위젯으로 개선한다. 모든 개인 위젯을 공동 홈에 즉시 추가하는 방식으로 확장하지 않는다. 위 표의 제한은 추가 메뉴뿐 아니라 서버의 레이아웃 타입/출처 검증에도 적용한다. 개인 여행 ID·대화 상대 ID·개인 자료 제목 등 금지된 설정을 직접 저장 요청으로 보낼 수도 없게 한다.

## 6. 첫 구현 후보 7종의 구체적인 내용 계약

‘내 작업’과 ‘공간 할 일’은 별도 원본이므로 첫 묶음에도 각각 포함한다. 회사 초대 사용자는 공간 할 일, 기존 문서 업무 사용자는 내 작업을 기본으로 제안한다.

### W01 내 작업

- 원본: 커뮤니티 `GET /community/api/my-tasks`, 현재 본인이 볼 수 있는 내 담당/담당 없는 내 작업. 제품 공간 task는 포함하지 않는다.
- 순서: 지난 기한 → 오늘 → 이번 주 → 이후 → 기한 없음. 각 묶음에서 원본 API 순서 유지, 고정된 항목 ID로 동률 처리.
- 소: 제목 최대 두 줄, 지난 기한/오늘 표시, 마감일. 긴급한 것이 없으면 다음 작업 한 개를 보여 준다.
- 중: 최대 4개. 제목·기한·프로젝트(없으면 문서 공간). 체크는 서버가 수정 가능하다고 판정한 항목에만 제공한다.
- 대: 지난 기한/오늘/이번 주의 구분과 최대 8개. 선택한 항목은 기존 상세 화면/패널로 연다. 전체 편집기를 카드 안에 넣지 않는다.
- 현재 API에 정확한 전체 건수와 행별 수정 capability가 없는 부분은 집계/동작 계약을 보완하기 전 수치 배지·바로 완료를 넣지 않는다. ‘4개 표시 · 더 있음’은 ‘총 4개’와 다르다.
- 빈 상태: ‘아직 내 작업이 없어요’. 쓰기 가능한 경우에만 ‘첫 작업 만들기’, 읽기 전용이면 업무 둘러보기/도움말을 제공한다. 특정 필터 결과가 빈 경우 ‘조건에 맞는 작업이 없어요’. 권한 부족과 빈 목록을 구별한다.

### W02 오늘 챙길 것

- 원본: `GET /community/api/briefing`. 제한된 우선 항목 목록이며 전사 업무 전체 통계가 아니다.
- W01이 함께 있으면 수신된 브리핑 항목 중 실제로 표시한 작업과 겹치는 기한 알림만 선택적으로 줄인다. 문서 ID가 같다는 이유로 검토/멘션 항목 전체를 숨기지 않는다.
- 현재 `Briefing::group()`은 문서 key별로 이미 하나로 합치므로 같은 문서의 기한·검토 등 여러 이유 중 일부는 응답 전에 소실될 수 있다. 클라이언트가 소실된 이유를 복원할 수 없다. 모든 이유를 보존하면서 다른 알림을 우선하는 기능은 서버의 `reasons` 또는 이유별 항목 계약을 먼저 보완해야 한다.
- 소 1개, 중 4개, 대 8개. 제목보다 ‘왜 지금 봐야 하는지’가 함께 보여야 한다. 예: ‘답변이 필요한 멘션’, ‘검증 기한 지남’.
- 클릭은 해당 원문/댓글로 이동. 홈을 보는 것만으로 공지를 읽음 처리하거나 외부 AI 브리핑을 생성하지 않는다.
- 빈 상태: ‘지금 확인할 알림이 없어요’. 요청 실패 시 ‘없음’으로 표시하지 않는다.

### W03 최근 자료

- 원본: T-box `/api/files/recent` + 커뮤니티 `/api/me/recent`. 파일은 최근 30일 내 사용, 문서는 해당 API의 최근 열람 범위다. 정렬은 각 API의 실제 사용 시각을 정규화한 뒤 병합한다.
- 제목 옆에 파일/문서 종류를 표시한다. 파일은 기존 `/tbox/?file=UUID` 진입을 활용해 정확한 대상의 미리보기/권한 확인으로 연결한다. 현재 홈의 파일이름 검색 링크를 그대로 재사용하지 않는다.
- 소 2개, 중 4개, 대 8개. 소에서는 이름/종류, 중에서는 사용 시각, 대에서는 권한 있는 위치를 더한다. UUID나 등급 코드 같은 구현용 값은 표시하지 않는다.
- 파일 미리보기, 문서 열기, 지원하지 않는 파일의 다운로드는 원본 흐름을 따른다. 파일 검사·권한 상태는 축소 시에도 숨기지 않는다.
- 한 출처만 실패하면 성공한 자료는 보여 주고 실패한 출처를 명시한다. 파일과 문서 둘 다 없을 때 ‘자료실 열기’로 이어 준다.

### W04 즐겨찾기

- 원본: 파일/폴더 즐겨찾기 + 문서 즐겨찾기. 개인 모음은 후속 선택 출처다.
- 소 2개, 중 4개, 대 8개. 소부터 제목과 종류를 표시한다. ‘고정’은 위젯 위치 잠금과 혼동되므로 자료 쪽은 ‘즐겨찾기’, 편집 쪽은 ‘위치·크기 잠금’으로 부른다.
- 서로 다른 출처의 기존 즐겨찾기 순서는 보존한다. 출처를 합친 사용자 지정 순서는 새 설정 계약이 필요하며 임의로 기존 순서를 덮지 않는다.
- 위젯에서 숨겨도 원본 즐겨찾기는 해제하지 않는다. 자료 삭제/권한 회수 시 오래된 이름을 계속 표시하지 않는다.
- 빈 상태: ‘자주 쓰는 자료를 즐겨찾기에 담아 보세요’와 자료/문서 탐색 진입.

### W05 공간 공지

- 원본: 사용자가 선택한 제품 공간의 notice. 현재 갱신 시각 기준 목록이며 공지 고정/필독/미읽음 속성이 있다고 가정하지 않는다.
- 소 1개, 중 3개, 대 6개. 제목·공간 이름·작성/갱신 시각. 중은 본문 한 줄, 대는 선택한 공지 발췌를 제공한다.
- 여러 회사·모임의 공지를 넣으려면 공간별로 위젯을 복제한다. 전체 참여 공간 통합은 권한과 갱신 순서가 정의된 별도 출처로 제공할 수 있다.
- 공지 등록은 해당 공간 생성 권한이 있을 때 보조 동작/더보기에서 제공한다. 편집 권한을 글로벌 관리자라는 이유만으로 추정하지 않는다.
- 빈 상태: 일반 구성원에게는 ‘아직 공지가 없어요’, 작성 가능한 사람에게만 등록 진입.

### W06 공간 일정

- 원본: 선택한 제품 공간 event의 starts_at/ends_at. 커뮤니티 작업 due나 개인 여행을 자동으로 섞지 않는다.
- 순서: 진행 중인 일정 → 가까운 시작 일정. 종료된 일정은 기본 제외하고 전체 보기에서 접근한다. 시간대는 현재 서비스 기준 Asia/Seoul로 명시한다.
- 종료 시각이 있을 때만 시작≤현재<종료를 ‘진행 중’으로 분류한다. 종료 시각 없는 일정은 시작 시각 중심으로 다루며, 지난 시작은 당일 목록에 ‘종료 시각 미정’으로 남기고 다음 날 기본 목록에서 제외하는 안을 제안한다. 이를 실제 종료·완료 판정으로 저장하지 않고 전체 보기에서 계속 접근하게 한다. 존재하지 않는 종일/기본 소요시간을 임의 생성하지 않는다.
- 소 다음 일정 1개, 중 오늘/이번 주 4개, 대 날짜별 8개. 대형 PC 주간 달력은 새 위젯 표현이며 현재 공간 홈에 이미 있는 달력이라고 소개하지 않는다.
- 현재 제품 공간 home은 종류별 최신 6개, items는 상한 100개다. 이를 받아 화면에서 날짜순으로만 정렬하면 오래전에 등록한 가까운 일정을 누락할 수 있다. **일정 기간/정렬/페이지 처리 계약을 먼저 보완해야 한다.**
- 제목·날짜·시각을 우선하고 실제 필드가 없는 장소/참석 여부/참석자 수는 만들지 않는다. 상세 열기/등록은 기존 권한을 따른다.
- 빈 상태: ‘다가오는 일정이 없어요’. 보관된 공간과 권한 해제를 별도 상태로 처리한다.

### W07 공간 할 일

- 원본: 선택한 제품 공간의 task. 개인 홈에서는 ‘나에게 배정된 것/공간 전체’를 명확히 선택하고, 공동 홈 기본은 그 공간 전체의 접근 가능한 작업이다.
- 소 1개, 중 4개, 대 최대 8개. 완료 제외 후 지난 기한→오늘→가까운 기한→기한 없음 순으로 제안한다. 상태(todo/doing/done)·담당·마감은 이 원본의 뜻 그대로 표시한다.
- 현재 목록은 최신 갱신순과 개수 상한이 있으므로 나의 담당·마감 우선·전체 건수를 정확히 제공하는 조회 계약이 선행되어야 한다. 100개만 받아 정렬한 것을 전체 우선순위로 표시하지 않는다.
- `can_edit`가 참인 행에만 완료/수정 동작을 제공하고 해당 항목 revision으로 갱신한다. member에게는 본인 작성 여부 등 원본 판정이 적용되므로 ‘담당=수정 가능’으로 추정하지 않는다.
- 글 내용과 담당을 바꾸는 편집은 기존 상세 흐름에 둔다. 빈 상태의 ‘할 일 등록’도 공간 쓰기 capability가 있을 때만 제공한다.

## 7. 처음 가입한 사람의 기본 화면

회사용/모임용을 강제로 묻고 막지 않는다. 초대받은 공간 문맥을 활용하고, 문맥이 없으면 ‘내 홈’ 기본형을 제공한다. 사용자는 추천 구성을 바꿀 수 있다.

| 상황 | 처음 배치할 위젯 제안 | 안내 |
|---|---|---|
| 참여 공간 없는 새 계정 | 최근 자료 중, 즐겨찾기 소, 오늘 챙길 것 소 + 임시 시작 안내 | 공간 만들기/초대로 참여, 첫 자료 열기, 위젯 추가 중 다음 행동 하나씩 |
| 회사 초대로 가입 | 공간 할 일 중, 회사 공지 소, 회사 일정 중, 최근 자료 중, 즐겨찾기 소 | 실제 소속/권한 확인 후 해당 공간 지정. 커뮤니티 문서 업무를 쓰는 사람은 별도 ‘내 작업’ 위젯 추가 |
| 모임 초대로 가입 | 모임 일정 중, 모임 공지 소, 모임 이야기 중, 모임 자료 소 | 사진 이야기는 공간과 자동 연결되지 않으므로 개인 피드 추가를 별도 선택으로 안내 |
| 기존 사용자 | 저장된 배치 유지, 새 위젯 카탈로그 안내 | 새 추천 구성은 미리보기 후 사용자가 적용. 기존 배치를 강제 교체하지 않음 |

처음 배치는 약 3~5개를 권장한다. 전체 카탈로그를 첫 화면에 깔지 않는다. 시작 안내는 완료·나중에 하기·다시 보기 상태가 있으며 업무 위젯을 영구적으로 가리지 않는다.

첫 로그인·필요한 인증·동의 관문은 추천 구성보다 먼저 적용한다. 공간 만들기·작업 만들기·자료 올리기는 서버가 해당 행동을 허용할 때만 안내한다. 읽기 전용 사용자는 참여한 공간 둘러보기·자료 읽기처럼 가능한 행동으로 시작한다. 회사 초대만으로 커뮤니티 내 작업이 자동 연결되는 것은 아니다.

기능 안내의 순서: ① 각 위젯의 빈 상태에서 첫 행동 ② 첫 정상 데이터가 생기면 짧은 문맥 안내 ③ ‘대시보드 편집’에서 위젯 추가, 소·중·대, 드래그, 잠금, 저장 순으로 선택 안내. 가입 직후 여러 모달을 연속으로 띄우지 않는다.

## 8. 편집·잠금·저장 동작

### 평상시와 편집 중을 구분

평상시는 데이터·주행동·전체 보기만 보여 준다. ‘대시보드 편집’을 누르면 편집 상태와 변경 여부가 분명해진다. 모든 위젯에 많은 큰 버튼을 펼치지 않는다.

- 선택한 위젯에 **크기 [소] [중] [대] / 위치·크기 잠금 / 더보기**를 제공한다. 손잡이는 이동 목적과 키보드 조작을 설명한다.
- ‘숨기기’와 ‘직접 크기 조절’은 더보기에서 접근한다. 잠긴 위젯에는 잠금 상태가 보이고, 잠금 해제는 바로 찾을 수 있다.
- 화면을 아래로 내려도 **취소 / 배치 저장·완료**를 찾을 수 있는 편집 막대를 제공한다. 모바일 하단 안전영역·키보드·다른 고정 UI와 겹치지 않게 한다.
- 위젯 추가 목록은 기능별 묶음과 소/중/대 미리보기를 제공한다. 출처가 필요한 위젯은 공간/DB/폴더를 먼저 선택한다.

### 잠금의 정확한 의미

잠금은 **그 위젯의 위치와 크기**를 보호한다. 평상시에는 내용 갱신, 상세 열기, 허용된 할 일 완료가 계속 가능하다. 보안 권한이나 내용 읽기 전용 설정이 아니다. 배치 편집 모드에서 업무 행동을 잠시 멈추는 아래 정책과 구별한다.

잠긴 위젯은 드래그, 모서리 조절, 소·중·대 변경, 다른 위젯의 겹침 정리로도 이동하지 않는다. 숨김/제거는 실수를 줄이기 위해 잠금을 해제한 뒤 가능하도록 제안한다. 다른 위젯을 잠긴 영역에 놓으면 가능한 빈 영역을 보여 주거나 해당 이동만 되돌리고 이유를 안내한다.

잠금은 위젯별로 저장하고 PC·휴대폰 양쪽 편집에서 적용하는 안을 권장한다. 좌표와 추천 크기는 화면별로 다를 수 있다. 좁은 화면에서 읽기 위한 반응형 표현 변경과 사용자의 위치/크기 변경을 구분한다.

### 저장과 취소

- 편집 초안에 추가·위치·크기·표시·출처·잠금 상태를 함께 담는다. 저장 성공 후 편집을 끝낸다.
- 취소하면 편집 시작 시의 배치와 잠금 상태로 돌아간다. 자료를 삭제하거나 완료한 실제 업무 행동을 배치 취소로 되돌리지 않는다. 배치 편집 중에는 모든 위젯의 업무 변경·다운로드·원문 이동을 일시 멈추고 배치만 편집하도록 제안한다. 저장/취소로 편집을 끝내면 원래 권한에 따른 행동이 복원된다. 이는 개별 위치 잠금과 독립적인 편집 모드 정책이다.
- 저장 중 중복 조작을 막는다. 실패하면 초안을 유지하고 재시도할 수 있다. 다른 기기/관리자가 먼저 저장한 revision 충돌은 자동 덮어쓰지 않는다.
- 개인 홈은 본인 계정에, 공동 홈은 현재 edit_dashboard 권한으로 저장한다. 공동 홈 저장은 구성원에게 적용됨을 편집 화면에서 알린다.
- 기존 v1/v2 배치를 읽을 때 자동으로 DB를 고치지 않는다. 새 카탈로그 전환은 기존 배치 보존·미리보기·명시 저장을 전제로 설계한다.

## 9. 데이터와 구현을 위한 설계 과제

아래는 설계 시 해결해야 할 계약이며 구현 지시서나 이미 존재하는 API 선언이 아니다.

1. **위젯 종류와 인스턴스를 분리한다.** 현재 개인 4개/공간 5개의 고정 ID 배열만 허용한다. 같은 ‘공간 공지’를 서로 다른 두 공간으로 추가하려면 위젯 종류, 인스턴스 ID, 출처, 크기별 표현, 잠금의 저장 계약이 필요하다.
2. **공통 프레임과 실제 내용을 분리한다.** 프레임은 제목/출처/전체 보기/편집/상태, 내용은 위젯별 소·중·대 렌더러가 담당한다. 기존 화면 DOM 전체를 다시 넣지 않는다.
3. **각 원본의 판정을 유지한다.** 집계·개수·항목·클릭 목적지 모두 권한 필터 후 생성한다. 공유 홈에 개인 API 응답을 저장하거나 다음 사용자에게 재사용하지 않는다.
4. **정확한 목록 계약을 정한다.** 기간·정렬·limit/cursor·has_more·합계 의미·갱신 시각·행별 capability·원문 링크를 정리한다. 특히 다가오는 일정, 전체 공간 내 할 일, 프로젝트 목록, 파일 직행, 여행 직행은 기존 응답만으로 충분하다고 가정하지 않는다.
5. **홈 조회는 부작용을 최소화한다.** 공지 읽음/조회수/최근 기록을 만드는 상세 GET, 개인 문서 공간을 초기 생성하는 GET, 외부 AI 호출을 자동으로 연쇄 실행하지 않는다. 목록/요약 전용 읽기 모델을 쓴다.
6. **불필요한 요청을 줄인다.** 숨겨진 위젯은 데이터 요청하지 않는다. 같은 출처의 여러 위젯은 요청을 합치거나 짧은 캐시를 공유하되 사용자·공간·필터·권한 변경을 분리한다. 화면 밖 로딩과 필요할 때 갱신을 우선한다.
7. **모든 상태를 설계한다.** 로딩 / 데이터 없음 / 필터 결과 없음 / 권한 없음 / 삭제·보관 / 연결 미설정 / 일부 실패 / 전체 실패 / 오래된 결과를 다르게 표시한다. 권한이 사라지면 예전 제목·본문·사진도 즉시 비운다.
8. **설정과 내용을 구분한다.** 저장 레이아웃은 좌표·크기·잠금·출처 식별자·표시 선호만 가진다. 문서 본문·메시지·사진·토큰·공유 비밀 URL은 넣지 않는다. 실제 content 권한은 저장 때와 조회 때 각각 재확인한다.
9. **반응형 내용을 검증한다.** 320/390/768/1280 화면, 긴 한국어 제목, 200% 확대, 터치·키보드, 밝은/어두운/고대비에서 같은 행동에 접근할 수 있어야 한다. native 선택창의 글자 잘림도 실제 기기에서 별도 확인한다.

## 10. 화면 디자인 기준

자료실은 파랑, 업무는 청록, 이야기에는 따뜻한 색, AI는 보라 계열의 기존 서비스 구분을 유지하는 안을 권장한다. 색은 제목 옆 작은 표시나 선택 상태에 쓰고 카드 전체를 강하게 칠하지 않는다. 배경·카드·입력·선택 상태의 명도 차이를 주고 읽는 부분은 중립 표면을 쓴다.

위젯 하나에 강조 버튼은 최대 하나다. 제목·출처·본문·보조 정보 순으로 읽히게 하고, 동일한 ‘등록/보기/관리’ 버튼을 매 행에 반복하지 않는다. 상태는 색만으로 설명하지 않고 ‘기한 지남’, ‘잠금’ 등 글자를 함께 둔다. 소형에서도 제목과 핵심 시각은 잘리지 않아야 한다. 작은 카드에 맞추려고 본문 글자를 줄이지 않는다.

## 11. 권장 진행 순서와 완료 기준

| 순서 | 결과물 | 완료를 판단할 기준 |
|---|---|---|
| 1 · 이번 기획 | 실제 기능 목록, 출처 구분, 크기별 내용 계약 | 세 라우트 표와 별도 진입점 대조, 구현/조건부/제안 구분 |
| 2 · 대표 위젯 검증 | 작업·자료·일정의 소/중/대 시안 | 작은 크기에도 정보/행동이 명확함, 커질 때 실제 쓸모 있는 정보가 늘어남 |
| 3 · 편집 기반 | 공통 위젯 프레임·카탈로그·개별 잠금·전체 저장 | 잠긴 위젯은 충돌에도 불변, 저장/취소/재접속/다중기기 충돌 검증 |
| 4 · 첫 7종 연결 | W01~W07의 실제 데이터 위젯 | 권한·필터·원문 이동·빈 상태·실패·건수 의미 일치 |
| 5 · 신규 사용자 경험 | 기본 구성·기능 안내·직접 꾸미기 | 처음 가입해 안내에서 실제 행동으로 이동하고, 안내를 건너뛰거나 다시 볼 수 있음 |
| 6 · 업무·모임 확장 | W08~W17, W27~W28부터 실제 활용에 따라 추가 | 회사/모임/개인 출처가 혼동되지 않음, 모바일에서 완료 가능 |
| 7 · 선택 도구 | W18~W26, W29~W31, 연결 가능한 기능만 제공 | 조건부 도구의 미설정 상태를 오해 없이 안내 |

출시 검증은 단순 좌표 변경 횟수보다 실제 사용 과업으로 한다: ① 신규 사용자가 다음 행동을 찾는다 ② 내 작업을 찾아 완료한다 ③ 다가오는 일정을 놓치지 않는다 ④ 자료를 원본으로 연다 ⑤ 위젯을 중형으로 바꾸고 잠근다 ⑥ 다른 위젯을 옮겨도 잠금이 유지된다 ⑦ 배치를 저장하고 다시 로그인해 확인한다 ⑧ 권한 해제 후 이전 내용이 남지 않는다.

이 문서는 전체 기능을 조사한 뒤 제안하는 설계 기준이다. 현재 운영 v2.55.0의 동작, DB, 서비스 설정은 이번 조사로 바뀌지 않았다.
