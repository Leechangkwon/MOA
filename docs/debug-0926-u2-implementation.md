## 4. 재인증 창 Esc

- 원인: 공용 재인증 창(`openReauthModal`)은 「닫기」·통과 때만 `close()`(빗장 `reauthOpen` 풀기 · 창 지우기)를 불렀다. Esc 는 브라우저가 창만 닫아(cancel → close) 빗장이 남았고, 다음 403 `next:"reauth"` 에서 `openReauthModal` 이 곧바로 돌아와 **새로고침 전까지 재인증 창이 다시 뜨지 않았다**. 수정 창(파일 고치기 — 묶음 S-8 과 합친 길)은 문구 없이 저장 단추만 살아 있었다. 닫힌 창은 DOM 에 쌓였다.
- 고침: 창의 `close` 이벤트에서 `close()` — 닫히는 **모든 길**(닫기 · ✕ · Esc · 통과)이 빗장을 풀고 창을 지운다. 창마다 `closed` 표시를 둬 늦게 온 close 이벤트가 **다음** 재인증 창의 빗장을 풀지 않게. 머리에 ✕. 파일 고치기 창에는 재인증이 끼어들면 **서버가 준 이유 한 줄**(「관리 기능을 쓰려면 비밀번호를 다시 확인하세요」)을 남긴다 — 다시 「저장하기」를 누르면 재인증 창이 다시 뜨고, 통과하면 같은 값을 다시 보낸다.
- DESIGN 2.7 「모달 안에 모달을 열지 않는다」에 예외 한 줄: 공용 재인증 창만 이미 열린 창 위에 겹쳐 뜬다(적어 둔 값을 지키고 같은 값을 다시 보내야 해서).

## 6. M12 터치 대상 44px
