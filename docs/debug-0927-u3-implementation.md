## 2. 경로 줄 첫 칸 = 실제 공간

`editor.js` `crumbRoot()` — 이름은 전부 창구 값, 고르는 값은 창구 판정 결과 `granted_by`:

| 페이지 | 첫 칸 | 링크 |
|---|---|---|
| 게시판 글(`board.kind = post`) | `board.name` — 창구는 그 게시판을 볼 수 있을 때만 싣는다(쓴 사람은 늘) | 그 게시판 `/community/b/{id}` |
| 팀 공간 | `space.name`(팀 이름) | 팀원(`granted_by = team_member`)만 그 팀 공간 `?space=` · 공유·관리자 열람은 글자만 |
| 남의 개인 공간(`granted_by ≠ owner`) | `space.name` = 「아이디 의 공간」(공유받은 페이지 목록 카드가 이미 보이는 글자) | 없음(`span.crumb__item` — 들어갈 화면이 없다, 올려도 밑줄 없음) |
| 내 페이지 | 「내 공간」 | 커뮤니티 첫 화면 |
| 게시판 이름을 받지 못한 게시판 공간 | 「게시판」(이름을 짓지 않는다) | 없음 |

볼 수 없는 공간 이름이 새지 않는다 — 새 값을 싣지 않았고(`space`·`board` 는 전과 같은 창구 응답), 그 응답은 페이지를 읽을 수 있는 사람에게만 간다. 게시된 남의 페이지는 실제 자리(주인의 공간)를 보이고, 게시판은 속성 줄 「게시판」에 그대로 있다.

## 3. 댓글 속 주소 링크 · 댓글 글자색

- `editor.js` `linkifyInto(el, text)` — `split(/(https?:\/\/[^\s<>"'「」『』ㄱ-ㆎ가-힣]+)/)` 로 조각을 나눠 **글자 노드와 `<a>` 를 하나씩** 붙인다(문자열 → HTML 0 · 정규식 `exec` 0 — 보안 린트).
- 걸린 조각도 `new URL()` 로 다시 읽어 **스킴이 http·https · 호스트 있음 · 아이디·비밀번호 없음**일 때만 링크(`https://좋은곳@다른곳` 은 글자). `javascript:`·`data:` 등 다른 스킴은 정규식에 걸리지 않아 글자로 남는다.
- 끝 문장 부호 `. , ; : ! ? ) ] } ' " 。 、 …` 는 주소에서 떼고 뒤에 글자로. 한글이 붙으면 거기서 끊는다(복사한 주소의 한글은 %xx 다 — 「…/path에서」).
- `rel="noopener noreferrer"` 는 늘 · 사이트 안(`url.origin === location.origin`)은 같은 창 · 밖은 `target="_blank"`. `href` 는 `url.href`(정규화한 값), 보이는 글자는 쓴 글자 그대로.
- 링크에 **클래스를 달지 않는다** — app.css 끝 터치 넓힘(`a[class]::before`)이 윗줄·아랫줄 글자를 덮어 다른 링크를 가져가지 않게(DESIGN 4장 「글 속 링크는 규칙 밖」). 모양은 `#page-comments .list__body a`(파랑 `--accent` + 밑줄 — 색만으로 가르지 않는다).
- 댓글 본문 `#page-comments .list__body` 는 `display: block`(`.list__body` 의 flex 를 풀어 글자·링크 조각이 한 흐름 — 처음 판은 flex 라 조각마다 칸이 벌어졌다, 탐색 중 발견) · 글자색 `--fg`(전 `--muted` 흰 바탕 4.83:1 → 19.9:1 · 다크 18:1). 「지운/숨긴 댓글입니다」 안내는 회색 그대로.

## 6. 없는 주소 — 「찾을 수 없는 페이지」

- 새 파일 `src/site/not_found_page.php` — `qaredi_not_found(bool $isApi)`: **브라우저 화면 요청**(① 모듈 경로가 `/api/` 로 시작하지 않음 ② GET·HEAD ③ `Accept` 에 `text/html`)이면 404 + 셸 없는 독립 화면(`.app > .main` > `.page-head` 「찾을 수 없는 페이지」 + `.panel.panel--narrow` 할 일 한 문장 + `.btn` 「첫 화면으로」 → `/`), 그 밖은 전과 같은 `{"error":"찾을 수 없습니다"}` 404. `Vary: Accept` · `Cache-Control: no-store` · HEAD 는 머리만. 스크립트 0 · 인라인 0 · 요청 주소를 되비추지 않는다.
- 부르는 곳(라우터의 404 갈래만 — 한 줄 → 두 줄): `public/index.php` ① 모듈 밖 주소(옛 t-box 경로 308 뒤) ② `/tbox` 모듈 경로 매칭 실패(405 뒤) · `src/community/routes.php` 커뮤니티 경로 매칭 실패. 셋 다 **인증 [2] 보다 앞**이라 세션을 읽지 않는다 — 로그인 전·후 같은 바이트, 새 쿠키 0, 감사 행 0(13장).
- **새지 않나(확인한 것)**: 로그인 전·후 없는 주소 본문 sha 같음 · 계정 이름 0 · 요청 주소 글자 0 · 새 쿠키 0 · 감사 행 0. **있는데 권한 없는 주소**(직원 `/tbox/users`)는 이 함수에 오지 않는다 — 라우터 [4] 인가가 전과 같은 403 JSON(바꾸지 않은 갈래). 로그인 전 있는 화면 주소는 전과 같은 302(로그인으로). 곧 「있는데 권한 없음(403) · 로그인 전 있는 화면(302) · 없음(404 화면)」의 모양은 **전과 같이 서로 다르다** — 라우트 표는 모든 사람에게 같은 목록이라(공개 코드와 같은 정보) 이 차이가 새로 알려 주는 것은 없고, 이 묶음이 더한 정보도 없다. 같은 모양으로 맞추려면 403 갈래를 바꿔야 해서 지시 범위(404 갈래만) 밖이다 — 15장 결정 거리.
- 남은 것(보고만): 핸들러 안에서 내는 404(공유 링크 `/tbox/s/{token}` 이 지났거나 틀림 · 위키 없는 글 등)는 전과 같이 JSON 이다 — 라우터 밖(핸들러·보안 쪽 파일)이라 이 묶음에서 고치지 않았다.

## 8. 공개 게시 거부 문장(file_narrower)

거부는 맞는 동작이다 — 상태 코드 400 · 사유 코드 `file_narrower` · 감사 `page.publish deny file_narrower` 는 그대로. 화면은 서버 문장을 그대로 보이므로(DESIGN 5장 「오류」) **서버 문장**을 고쳤다:

| 창구 | 전 | 후 |
|---|---|---|
| `POST /api/pages/{id}/publish` | 이 게시판을 보는 사람이 볼 수 없는 파일이 붙어 있습니다. 파일 등급을 넓히거나 빼고 게시하세요 | 이 페이지에 「공개」 게시판에 올릴 수 없는 그림이나 파일이 들어 있습니다. t-box 에서 그 파일의 등급을 「공개」로 올리거나, 페이지에서 빼고 다시 게시하세요(「사내」·「팀」 게시판은 「사내」 이상으로 · 「팀」 이상으로) |
| `PATCH /api/pages/{id}/visibility` | 새 범위의 사람이 볼 수 없는 파일이 붙어 있습니다. 파일 등급을 넓히거나 빼고 바꾸세요 | 이 페이지(하위 포함)에 새 공개 범위의 사람이 볼 수 없는 그림이나 파일이 들어 있습니다(파일 등급이 더 좁음). t-box 에서 그 파일의 등급을 올리거나, 페이지에서 빼고 다시 바꾸세요 |
