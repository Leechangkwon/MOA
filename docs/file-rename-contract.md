# 개인 파일명 변경 계약 — 2026-10-01

기준 운영 판 a39ec15는 토큰 PATCH에서 `folder_id`만 허용해 `name`/`expected_name`을400 bad_request로 거부한다. 아래는 이번 구현의 확정 계약이다. 운영 반영·실측 검증 여부는 별도 인계 보고를 따른다.

PATCH `/tbox/api/files/{uuid}` · `X-API-Token` 개인 파일 토큰 · `Content-Type: application/json`.

```json
{"name":"8월_최종_품목정보.xlsx","expected_name":"품목정보.xlsx"}
```

- 정확히 두 키 모두 필수이며 폴더/등급/설명 변경과 혼합할 수 없다.
- 최소 범위 `read+upload`, `read+upload+delete`도 가능. `read`, 공용 토큰, 로그인/커뮤니티/비서 전용 토큰으로 대체하지 않는다. 쿠키만으로는 이름 변경을 실행하지 않는다.
- 본인이 올린 파일만 변경한다. 읽기/수정 권한·현재 계정·토큰 유효성·소유권은 행 잠금 안에서 다시 확인한다. Admin/Manager의 타인 파일 관리 권한은 이 개인 이름 변경에 적용하지 않는다.
- `name`은 경로 없는 완전한 파일명(확장자 포함), UTF-8 최대255자. 빈 이름·앞뒤 공백·경로 구분자·Windows 경로 문자·제어/방향 제어 문자·업로드에서 금지하는 이중 확장자는400이다. 현재 저장 확장자와 일치해야 하며 대소문자만 다른 확장자는 허용한다.
- `expected_name`은 서버 목록에서 읽은 원래 이름 문자열 그대로 보낸다. 대소문자/공백/Unicode를 임의 정규화하지 않는다. 불일치는409이며 다른 요청이 바꾼 이름을 덮어쓰지 않는다. 목록을 새로 읽고 사용자에게 충돌을 표시한다.
- 성공200은 아래 두 키다. UUID 유지, 표시 이름만 변경. 같은 현재 이름을 다시 저장하는 요청은200이고 추가 변경 감사는 만들지 않는다.

```json
{"id":"11111111-1111-4111-8111-111111111111","name":"8월_최종_품목정보.xlsx"}
```

실제 UUID는 선택 행의 ID를 사용한다. 같은 이름의 다른 파일을 찾아 바꾸지 않는다. 원본 바이트/hash·stored_name·mime·ext·폴더·등급·팀·업로더는 유지한다. GET 파일 검색은 새 이름/기존 설명을 찾고 다운로드의 Content-Disposition은 새 이름을 반환한다.

거부:401 인증/만료/회수,403 scope/개인 토큰/현재 권한/소유권,404 없거나 삭제한 UUID,400 형식/이름/확장자,409 이전 이름 충돌. 이름 변경 분기의 오류는 기존 파일 API와 같은 문자열 `error`에 기계 판독 `code`를 함께 둔다. 라우터의 기존 인증·scope 거부에는 `code`가 없을 수 있어 HTTP 상태와 문자열 `error`도 처리한다. 403은 권한 원인의 상세를 공개하지 않는다. 감사에는 허용/거부와 이전/새 이름·기존 파일 hash/크기·소유자/토큰 행 참조가 남고 인증 값은 기록하지 않는다.

운영 반영:2026-10-01 완료(`docs/file-rename-handoff.md`, 외부 `runtime-deployment.json`). 로컬 `SUPPORTS_FILE_RENAME=true`로 연결할 수 있다. 이 기능은 기존 개인 파일 토큰을 쓰며 assistant.run/tools 신설 없이 F2/명시적 비서 명령으로 호출할 수 있다. 자연어 추론·자동 이름 결정·일괄 변경은 이 계약에 포함하지 않는다.
