목표: 사용자가 승인한 컴팩트 업무형의 중립 배경·카드와 소량의 브랜드색을 실제 서비스에 적용하고, 모바일에서 개인 대시보드가 첫 화면에 보이지 않는 원인을 고친다. 기준 main 566872d0eeacbd0609967ef3383bb87d2372d8f8 / v2.58.1. 실제 역할은 Codex root·구현·독립 검토이며 사용 불가한 Fable/Opus로 주장하지 않는다. 기존 승인 범위의 구현·검증·운영 반영·기록/push까지 진행한다.

## 요구와 경계

1. 큰 면의 색 역할을 분리한다. Astra/Aurora/Bloom/Nova 공통 밝은 회백색 canvas·흰 surface, 어두운 charcoal canvas·명도 차이 회색 surface. 글자/보조글자/테두리는 중립축, 브랜드색은 primary/선택/포커스·작은 아이콘에 집중. Moa의 기존 중립 표면과 함께 조화되게 한다. 컬러 glow/대형 서비스 gradient는 낮추되 기능별 아이콘 색/의미색은 보존한다. 불필요한 신규 라이브러리·이미지·외부요청0.
2. explicit light/dark·system fallback을 모두 검사한다. 고대비/forced-colors와 Claude 원본은 별도 예외를 유지한다. 문서 --bg·nt/pal 토큰·원문 JSON·명시색/cell>row>header를 덮어쓰지 않는다. 최근 검정 본문 수정 및 서식 표 편집은 회귀 검사한다.
3. 모바일 첫 진입은 원인 조사 후 최소 수정한다. 일반 로그인/새로 연 기본 홈은 내 대시보드 중심으로, 사용자가 연 파일/글/초대/PC연결 등의 명시적인 안전한 목적지는 기존대로 보존한다. 미로그인 권한·최초 비밀번호/OTP·동의 강제절차는 우회하지 않는다. 기존 저장된 개인 위젯이 없는 신규 사용자는 기존 유효 기본 구성을 이용한다. 모바일 최상단 고정 소개/서비스 덩어리가 밀어내는지 실제 화면으로 검사한다.
4. PC/모바일 모두 실데이터 위젯·아이콘 바로가기와 단일 편집 진입을 유지. 문서 전체가 예시 화면의 복제품이 되는 변경은 하지 않는다.
