- **창고 이름이 곧 장소 모델**: `플란치과_지점_층_용도` — 용도 어휘: 공급실 · 수술방 · 중앙장 · 중앙공급실(수술/보철) · 의약품창고 · 의약품공급실 · 소모품창고 · 구매팀 창고 · 상담실 · 의료장비 · 기구 · 서비스금액. 구분 「공장」+생산공정 「수술」 인 행 1개(부산점 13층 수술방).
- 지점 이름(캡처): 강남·부평·검단·동탄·부산·수원·일산 + 라미트치과·메가젠 창고 임시.
- 담당자 표기 `플란치과_부평_김희라 선생님`, `이창권 팀장`, `정진영 대리` → **담당자 이름에 지점이 붙어** 있다(사원 마스터에 지점 필드가 없어 이름으로 대신하는 것으로 보임 — 추정).

## 4. 흐름과 연결(캡처로 확인된 것)
```
발주요청(선생님, 창고=지점 장소, 담당=선생님)  ──전표불러오기──▶  발주서(구매팀, 거래처별, 발송 표시, 참조 「[지점] 자동발주」)
                                                                    │ 생성한 전표
                                                                    ▼
                                                              구매(입고, 불러온 전표일자/No 로 역추적)
```
- 발주요청은 **지점 담당자(선생님)** 가, 발주서·구매는 **구매팀(팀장·대리)** 이 만든다(담당자명 패턴으로 확인).
- 같은 날 한 지점에서 발주요청 여러 건(일자-No `-1`~`-5`) → 거래처별 발주서로 재편(부평점 `-8`~`-19` 하루 12건).
- 발주서 참조 「[부평점] 자동발주」 → 지점 단위로 묶어 자동 생성하는 운영이 이미 있다(추정: 이카운트 기능 또는 수작업 관행).
- 수량 단위 두 겹: **수량(박스/포장)** 과 **낱개수량**(당수량 분자/분모로 환산). 발주서는 낱개수량·박스수량 둘 다.

## 5. 우리 설계에 바로 쓰는 결론
1. **장소(location) 마스터**는 `지점 × 용도` 두 축으로 정규화한다(이카운트는 이름에 넣었다). 용도 어휘는 위 관찰 목록에서 시작.
2. **품목코드는 거래처 코드 문자열**을 그대로 보관하고 내부 id 는 따로 둔다. 분류 3단 + 지점 태그(품목계층그룹)는 유지.
3. **포장 단위**(당수량 분자/분모 → 낱개 환산)는 1차부터 필요하다. 요청·발주·입고 모두 낱개 기준으로 재고를 계산.
4. **전표 상태**는 이카운트 어휘(미확인·확인·진행중·완료·결재중)를 그대로 쓰면 사용자가 배울 것이 없다.
5. **불러오기**(전표 불러오기)와 **역추적**(불러온 전표 No, 생성한 전표)이 핵심 사용성 — 우리 설계의 `src_line_id` 가 그것.
6. **음수 정정 전표** 관행이 있다 → 정정은 음수 행이 아니라 「정정 전표(사유 필수)」로 바꾸되, 화면 표기는 이카운트와 비슷하게.
7. 담당자에 지점을 이름으로 붙이는 관행 → 우리 계정에는 **지점 소속**을 필드로 둔다(t-box 의 `team` 을 지점으로 쓰거나 `branch_id` 신설 — 설계 결정 필요).

## 6. 캡처에 없어 확인이 필요한 것
- 거래처등록·창고등록 **입력 폼**(필수 필드), 재고현황·수불부 화면, 창고이동·실사 화면, 단가관리(거래처별 특별단가) 실제 사용 여부, 전자결재 사용 여부, 엑셀 업로드 양식.
