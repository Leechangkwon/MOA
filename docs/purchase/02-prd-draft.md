## 1. 사용자와 역할 (구매 모듈 권한)

t-box 4역할 위에 **모듈 역할**을 둔다(`purchase_role`: `requester` · `buyer` · `stock` · `viewer`, 계정마다 하나, Admin 은 전부).

| 역할 | 누구 | 할 수 있는 것 |
|---|---|---|
| requester (요청자) | 지점 선생님·실장 | 자기 지점 발주요청 입력·조회, 자기 지점 재고 보기, 사용(수술방 소모) 입력 |
| buyer (구매팀) | 팀장·대리 | 전 지점 요청 불러오기 → 발주서, 입고, 이동, 월 대사, 기초정보 편집 |
| stock (재고 담당) | 지점 재고 담당 | 자기 지점 이동·실사 입력 |
| viewer | 검토자 (Q-18④ 확정) | 전 지점 읽기 + 발주서 미리보기·오류 재점검 뒤 **송부**(`purchase.send`) |

**지점 격리가 1순위**: requester·stock 은 `users.branch_id` 밖의 데이터를 목록에서 **보지 못한다**(응답에 없음 — t-box S-02 원칙). buyer·viewer 는 전 지점.

## 1-1. 사용자 피드백 반영 (2026-09-13, 시안 1판 검토)

| # | 요구(요지) | 반영 |
|---|---|---|
| R1 | 품목은 드롭다운이 아니라 **품목 등록 API 를 직접 호출**해 조건을 정해 검색하고 **다중 선택** | F-P2 「품목 찾기」 모달: 서버 검색(20건 페이지·총 건수), 조건(키워드·브랜드·대/중/소·거래처·지점 사용 품목·재고 부족·최근 주문), 필터를 바꿔도 선택 유지, 수량 미리 입력, 한 번에 담기. 시안 ② |
| R2 | 담당자별 **자주 주문 추천 리스트** + 본인이 만드는 **커스텀 발주 리스트** (발주요청서·발주서 공통) | F-P2-1 신설: 추천 = 내 요청 줄 품목별 빈도(90일, 지점 전체로 전환 가능) · 내 리스트 = 여러 개, 기본 수량, 순서, 지점 공유 선택, 「전체 담기」. 시안 ③ |
| R3 | 불러오기의 묶는 기준은 **다중 선택**(거래처 + 창고 + 담당자 …) | F-P3: 기준 여러 개 선택, 누른 순서 = 트리 층. 시안 ④ |
| R4 | 발주요청서 → 발주서 → 구매의 **전표 번호 매칭**과 사이클(누가 요청·발주·구매, 미입고 여부) | 시안 ⑤(발주서 줄에 출처 PR 번호) ⑥(입고 줄에 출처 PO·PR) ⑨ 사이클 추적(요청 줄 = 한 행, PR/PO/GR 번호·사람·시각·미발주·미입고). 구현은 `doc_lines.src_line_id` 하나 |
| R5 | "시안 6장이 다냐" — 요구 기능이 빠져 보임 | 맞다, 1판은 핵심 6장이었다. 2판 16장·3페이지로 전표 5종 입력(요청·발주·입고·이동/사용/실사), 기초정보(장소·품목), 엑셀 가져오기, 현황 4종(재고·미입고·주간 사용량·월 대사), 사이클 추적을 채웠다 |
| R6 | (추가 요구) **미입고 현황** — 발주서 제출 뒤 구매입력 없는 것 | F-P5 에 미입고 현황 추가: 거래처별 묶기, 납기 지남·경과일, 독촉 문구, 바로 입고 입력, 30일 초과 경보 후보. 시안 ⑪ |

## 2. 기능 목록 (F-P1 ~ F-P9)

| ID | 기능 | 화면 시안 | 핵심 규칙 |
|---|---|---|---|
| F-P1 | **기초정보** — 브랜드·지점·장소(지점×용도), 거래처, 품목(대/중/소·포장·재고관리 여부·재고 규칙 3칸·사용 지점), 지점별 인가량 | ⑤ | 품목코드 = 거래처 코드 문자열, 거래처 안 중복 금지. 사용 중단은 삭제 아님. 변경은 before/after 감사 |
| F-P2 | **발주요청** 입력·전표·현황 | ①② | 재고 불변. 품목은 「품목 찾기」 모달(품목 API 조건 검색·다중 선택·수량 미리 입력, R1), 결과에 현재고·인가량 배지. 상태 미확인→진행중→일부 발주→완료 |
| F-P2-1 | **추천 · 내 발주 리스트** | ③ | 추천(담당자별 90일 빈도), 내 리스트(여러 개·기본 수량·순서·지점 공유), 발주요청·발주서 공통 「전체 담기」 (R2) |
| F-P3 | **불러오기 → 발주서** | ④⑤ | 미발주 잔량만, 묶는 기준 **다중 선택·순서 = 트리 층**(R3), 부분 담기, 발주서 줄마다 출처 PR 번호(R4), 미지정 거래처 즉석 지정(품목 기본 거래처 학습), `src_line_id` 로 역추적. 발주서 PDF 1장·"보냄" 표시 |
| F-P4 | **입고(구매) · 이동 · 사용 · 실사** | ③ | 입고 = 재고 +, 이동 = −/+, 사용 = −, 실사 = 차이만 ±. 재고관리 안 하는 품목은 입고 = 사용. 수술방은 「인가량 유지 가정」이라 실사로만 보정 |
| F-P5 | **현황** — 장소별 재고(현재고·인가량·과부족·미입고·주평균·발주 제안), 수불부, **미입고 현황(R6)**, **사이클 추적(R4)**, 주간 사용량(대/중/소·지점) | ⑨⑩⑪⑫ | 현재고는 원장(`stock_moves`) 집계, 컬럼 아님. 발주 제안 = ⌈(인가+안전−현재고−미입고+조달기간 예상)÷최소단위⌉×최소단위, 제안값 |
| F-P6 | **엑셀 가져오기 / 내려받기** | ⑤(버튼) | 기초정보 3종·발주요청 일괄. 열 매핑 저장. 확정 전 미리보기(행별 상태). t-box 업로드 검사 그대로 |
| F-P7 | **거래처 월 대사** | ⑥ | 우리 입고 vs 명세서(엑셀·PDF 텍스트, 열 매핑). 차이 자동 분류(단가·수량·우리누락·명세서누락). 월 마감 → 그 달 전표 잠금(수정은 사유+감사) |
| F-P8 | **기공 명세서 → 전표 자동 생성** | ⑥ 변형 | 재고관리 안 하는 품목. 업로드→매핑→미리보기→확정 시 입고=사용 전표 |
| F-P9 | **감사·경보** | — | 모든 전표 생성·수정·취소·마감·기초정보 변경은 t-box `audit_logs` 문장 틀로. 경보 후보: 마감 뒤 수정, 대량 취소, 단가 급변 |

비목표(이번): 웹 오피스·동기화·OCR(이미지 PDF)·바코드 스캐너 연동(2차)·전자결재·원가 계산·이카운트 API 연동.

      stock_managed bool, safety_qty, lead_days, min_order_qty, price_in(VAT별도), barcode, is_active)

docs(id, doc_type pr|po|gr|mv|is|adj, doc_no, doc_date, branch_id, vendor_id, from_location_id, to_location_id,
     manager_id, status draft|unconfirmed|confirmed|in_progress|done|void, memo, created_by, sent_at, locked_month)

잔량 = 요청 qty − Σ(자식 라인 qty). 현재고(location, item) = Σ qty_delta. **DB 계정**: 모듈 표는 `tbox_app` 에 SELECT·INSERT·UPDATE, `stock_moves`·`audit_logs` 는 INSERT 만(취소는 반대 부호 행).
