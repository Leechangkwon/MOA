## 1. 한 줄

한글은 PHP(`src/SearchText.php`)가 「두 글자 조각 + 한 글자」로 나눠 기존 `search_tsv`(GIN)에 넣고, 찾을 때는 조각이 다 있는 행을 색인으로 추린 뒤 원문에 그 말이 이어져 있는지 다시 확인한다. 영문·숫자는 지금처럼 ILIKE(J-10 ⓑ). 판정은 각 앱의 기존 조건절 그대로(새 권한 코드 0). 두 앱 공통 Ctrl+K 창에서 페이지·댓글·파일을 한 번에.

## 3. 지시서와 다르게 간 곳 · 빈칸을 채운 곳

| # | 무엇 | 왜 |
|---|---|---|
| D-1 | `pages_tags_put.php` 를 고쳤다(수정 파일 목록에 없다) | J-4 「태그 이름은 페이지 벡터에」를 지키려면 태그가 바뀔 때 벡터도 바뀌어야 한다. 안 고치면 태그를 단 뒤 다음 본문 저장까지 태그로 못 찾고, 뺀 태그로는 계속 찾힌다(색인과 ILIKE 다시 확인이 어긋남). 판정·감사 코드는 그대로이고 같은 트랜잭션에서 `UPDATE … search_tsv` 한 줄 |
| D-2 | **기준선** = 「판정 조건절 그대로 + 낱말마다 **NFC 로 합친** 제목·본문·태그에 ILIKE, 여러 낱말은 AND」 | 5장 ③ 「지금의 ILIKE 결과와 같다(여러 낱말은 ILIKE AND)」를 그대로 쓰면 ① 맥 NFD 문서(5장 1 말뭉치에 넣으라는 것) · ② 태그로만 맞는 페이지(J-4) 에서 새 검색이 「더」 찾아 어긋난다. 기준선을 이 두 가지를 포함한 ILIKE 로 적었다(시험 도우미 `baseline` — 색인을 쓰지 않는 SQL). 옛 5-B(검색어 통째로 원문 ILIKE 한 번)와 결과가 달라진 검색어는 시험이 목록으로 찍는다(6장 표) — 전부 이 둘 + 여러 낱말 AND + J-11 |
| D-3 | 다시 확인에 `normalize(…, NFC)` | 색인은 조합한 글자로 만들므로 NFD 문서가 후보로 오는데, 원문 ILIKE 로만 다시 확인하면 떨어진다. PG 13+ 내장 함수(확장 아님). 원문이 먼저 맞으면 부르지 않는다 |
| D-4 | 댓글의 「게시 뒤만」 규칙은 **좁은 쪽 근사** | comments_list 는 「게시판 등급으로만 보는 사람」에게 게시 뒤 댓글만 준다(`since`). 그 갈래를 SQL 로 가르려면 판정을 새로 적어야 해서, 「게시 중인 개인 페이지에서 공간 주인이 아니면 게시 전 댓글(과 그 답글)을 뺀다」로 좁혔다. 목록에서 보이는 사람(공유·팀)이 검색에서 덜 보는 일은 있어도, 목록에서 못 보는 댓글이 검색에 나오는 일은 없다(T2 전수 대조로 확인) |

## 4. 보안 — 새 권한 코드 0 을 지킨 방법(2.6 대조)

- 페이지: `community_search_pages_where` 문자열을 **그대로** 문장에 넣는다(LATERAL 안). 바꾼 것은 그 조건을 매기는 줄의 순서·수뿐.
- 댓글: 같은 조건절 + `deleted_at IS NULL AND hidden_at IS NULL` + 숨긴 게시판 글 제외 + D-4 의 좁은 쪽 규칙.
- 파일: 서버 코드 0 — 화면이 기존 `GET /tbox/api/files?q=`(전역)를 부른다.
- 입력: 1~100자(`Http::queryText`), 낱말 60개 상한, tsquery 는 한글 음절 토큰만, 모든 값 바인딩, SQL 조각은 nowdoc 상수 + 정수 번호. ORDER BY 고정. 전체 개수 없음.
- 화면: textContent 만, `<mark>` 는 요소 + textContent, 인라인 style 0. 주소는 서버가 준 기준에 붙인다.
- 계획 설정 `SET LOCAL enable_seqscan` 은 검색 창구의 읽기 트랜잭션 안에서만 걸리고 커밋·롤백 때 풀린다(영속 연결 P-2 에 남지 않는다).
- 시험 증거: T2 전수 대조(5계정 × 16검색어 결과 전부 판정 함수 허락) · 완전성 · 숨긴·지운 댓글 0 · 게시 전 댓글 0 · Guest · T3 주입 32개 × 2창구 · 보안 린트 0.
