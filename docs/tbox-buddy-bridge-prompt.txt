3. 제안 리스너와 페어링 — 구현 전 검토하고 결정 근거 기록

- 별도 IPv4 127.0.0.1:43821 고정 포트 제안. 충돌 여부를 Windows에서 확인하고
  하나의 명시적 포트를 문서로 확정해 줘. 포트 자동 탐색/0.0.0.0/LAN/IPv6 모든
  주소 바인딩 금지. 중복 앱 실행은 실패 안내. OAuth 콜백과 소켓/경로를 분리해 줘.
- 기본 자동 연결 off, 사용자가 PC 앱에서 연결 시작/중지/해제를 할 수 있게 해 줘.
- Host는 정확히 127.0.0.1:43821, Origin은 정확히 https://changkwon.mso.so.
  누락/null/중복/다중 Origin/다른 포트/localhost 별칭/서브도메인 모두 거절.
  연결 peer도 loopback 확인. proxy forwarded 헤더로 Host/Origin을 대체하지 마.
- 사용자가 PC에서 페어링 시작 → 128비트 이상 일회용 난수 코드 표시(2분 만료)
  → 향후 웹 페어링 UI에서 직접 입력 → PC에 정확한 Origin 확인창 → 명시 승인.
  코드 시도 5회 이내/시간 제한, 한 번만 소모. GET/URL에 비밀을 넣지 마.
  승인 전에는 실행 권한을 주지 마. 악성 사이트가 선점한 요청은 취소 가능해야 한다.
- 페어링 자격은 OpenAI 토큰과 별개의 256비트 난수. 브라우저에는 승인 후 1회만
  반환하고 메모리에만 유지. 기본 30분 만료/탭 종료 후 재페어링, 수동 철회 지원.
  초기 버전은 재시작 시 모두 무효화. 설치별 난수 키는 별도 DPAPI 저장소에서 관리.
  pairing 상태에 OAuth 토큰/계정 식별자를 직렬화하지 마.
- 요청 인증은 Authorization: MoaLocal <pairing credential> 헤더 제안.
  쿠키나 Moa 세션/파일 토큰/assistant.run으로 대신하지 마.
  CORS는 정확한 허용 Origin, Vary: Origin, 필요한 메서드/헤더만.
  OPTIONS도 Host/Origin 검증, 부작용 없음. credentials: omit, wildcard 금지.
  성공/오류 모두 Cache-Control: no-store; 리디렉션/디버그 스택/원문 로그 금지.
- 제한된 엔드포인트 제안: POST /v1/pair, POST /v1/jobs,
  GET /v1/jobs/{request_id}, POST /v1/jobs/{request_id}/cancel, POST /v1/unpair.
  페어링 승인 대기/거절 상태를 정확히 표현하고 만료 후 대기 요청도 종료해 줘.
  구체적인 페어링 요청/응답과 HTTP 상태를 docs에 확정해 다음 웹 세션에 넘겨 줘.
  인증 실패 시 job 데이터/존재 여부를 노출하지 마.

4. 작업 계약 v1 — 필드 추가 없이 엄격히 적용

요청:
{
  "schema_version": 1,
  "request_id": "<새 UUIDv4>",
  "action": "polish | spelling | translate",
  "text": "<사용자가 확인한 원문>",
  "target_language": "ko | en | ja | zh | vi | es | null"
}
위 action/언어 문자열은 열거값 설명이다. 실제 요청에는 하나의 값만 사용한다.
schema_version은 bool을 허용하지 않는 정수 1, request_id는 UUIDv4.
text는 공백만 있는 값 불가, Unicode 코드 포인트 1~4,000자.
번역 이외 target_language는 JSON null. 누락/알 수 없는 필드/중복 JSON 키/다른 버전
/불법 Unicode/부적절한 타입을 거절. 원문 공백을 자동 trim하거나 자르지 마.
application/json 및 올바른 UTF-8만. 본문은 읽는 중에도 32 KiB 상한을 적용.
HTTP 파싱은 중복 Content-Length, TE/CL 모순, 무한 chunk/slow 요청을 안전하게
거절하고 연결/읽기 타임아웃·최대 헤더·동시 연결 상한을 적용해 줘.

응답:
{
  "request_id": "<원래 요청 ID>",
  "state": "awaiting_confirmation | running | completed | cancelled | failed",
  "text": "<completed일 때만 최종 결과, 그 외 JSON null>",
  "provider": "openai_chatgpt_plan",
  "model": "<실제 선택/사용 slug, 선택 전 JSON null>",
  "error_code": "<다음 공개 오류 코드 또는 JSON null>"
}
오류 코드: eligibility_unconfirmed, reauth_required, permission_denied,
usage_limit, unavailable, unsupported, invalid_input, model_required, cancelled,
stream_interrupted, incomplete, network_error, protocol_error, busy, unexpected_error.
성공은 error_code=null. 토큰/쿠키/OAuth URL/이메일/subject/issued client_id/
다른 대화/내부 오류 원문을 응답에 넣지 마. SSE 조각을 completed로 반환하지 마.
실제 inference가 response.completed로 확인되어야만 최종 결과를 반환해 줘.
웹 작성란은 결과도 4,000자 제한이다. 초과 응답을 자동 절단하지 말고 로컬에서
알리며 incomplete/null로 전달하는 정책을 문서화해 줘. 별도 유료 재요청 금지.

5. 재전송·생명 주기

- 버전1 JSON은 유지하고 시간/만료/nonce는 X-Moa-Timestamp,
  X-Moa-Expires, X-Moa-Nonce 헤더로 전달하는 안을 검토해 줘.
  단위/인코딩을 명시: timestamp/expiry=UTC Unix 초 정수, nonce=128비트 이상 base64url.
  허용 시계 차이 60초, 최초 제출 만료 최대120초. 확인 대기는 별도2분 제한.
  nonce는 페어링별로 소모하며 모든 인증된 요청(GET/취소 포함)마다 새 값 필요.
- request_id는 원문/action/language/version의 정규화한 JSON 해시 및 페어링 채널에
  묶는다. 같은 ID/내용 재조회·재전송은 기존 상태만, 다른 내용은 충돌/거절.
  네트워크 오류로 상태가 불명확해도 자동으로 AI를 다시 호출하지 마.
- 한 PC에 대기/실행 작업 한 개부터 시작하고 추가 요청은 busy.
  동시 요청·확인·취소·계정 전환을 원자적으로 조정. Tk UI는 메인 스레드에 queue로 전달.
- 최종 결과 메모리 TTL 10분, 중복 ID/해시 tombstone은 페어링 수명 전체 보존.
  만료 결과를 요청하면 명시적 오류, 같은 ID로 새 실행 금지.
  재시작은 페어링 전부 철회/작업 취소. 저장된 미완료 작업 자동 재개 금지.
- 로그아웃/계정 전환/페어링 해제 시 대기 및 실행 작업 취소, 늦은 SSE 무시.
  한도 초과는 usage_limit로 종료하며 다른 계정/유료 API로 자동 전환하지 마.

6. 요청별 로컬 사용자 확인

페어링과 AI 실행 확인은 별개다. 매 요청 원문/작업/번역 언어/선택 계정/실제 모델/
ChatGPT 요금제 사용을 PC UI에 보여 주고 사용자가 실행 또는 취소하게 해 줘.
계정 정보는 PC에만 표시하고 웹 계약에는 넣지 마.
자격 확인, 로그인, 필요한 권한, 모델 선택이 충족되어야 실행 가능하다.
확인창이 닫히거나 만료되면 실행하지 마. 팝업 없이 백그라운드 실행 금지.
일반 대화 이력/파일/이미지는 계약 범위에 넣지 마.

웹은 결과를 원래 request_id/대화상대/원문/작업/언어 revision과 대조해야 한다.
자동 결과 도착도 미리보기까지만; 적용과 메신저 보내기는 각각 사용자 동작이다.
다른 상대/바뀐 작성란을 덮어쓰지 않는 계약을 서버 인계에 명시해 줘.

7. HTTPS 브라우저 제약

현재 모아 CSP는 default-src 'self'이고 loopback을 허용하지 않는다.
후속 서버 세션에서 메신저에 한정한 connect-src http://127.0.0.1:43821 예외를
검토해야 한다. 이번 Windows 작업에서 운영 웹 설정을 임의 변경하지 마.
https://developer.chrome.com/blog/local-network-access
https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Local_network_access
LNA 권한·mixed content·CORS·기업 브라우저 정책을 실제 Windows Chrome/Edge/
Firefox 버전별로 확인. 테스트용 HTTPS 페이지는 운영 Origin으로 오인시키지 말고
운영에서 허용되지 않는 테스트 설정으로 분리해 줘. 보안 기능 비활성화/우회 금지.
거부·미지원·미실행·포트 충돌 시 기존 수동 복사로 안내해 줘.
브라우저 직접 연결이 어려우면 확장/native messaging을 별도 제안해 줘.
Moa 서버가 개인 구독을 대신 호출하는 OAuth/추론 프록시는 만들지 마.

8. 시험 및 인계

기존 Windows 테스트와 다음 시험을 실행하고 명령/환경/결과를 기록해 줘.
- 잘못된 Host/Origin, missing/null/중복 헤더, 악성사이트 preflight와 simple request.
- 페어링 만료/5회 실패/철회/중복 소비/미승인 요청/다른 채널/재시작.
- 누락·추가·중복 필드, bool 버전, UUID, 6언어/null 규칙, UTF8 32KiB 경계,
  emoji 4000/4001, 공백 원문, HTTP 과대/느린 요청.
- nonce 재사용, 시간 만료, ID 재전송/본문 충돌/동시 도착에도 inference는 최대1회.
- 매 요청 확인, 취소/계정 전환/로그아웃/늦은 SSE/네트워크 끊김/한도초과.
- 완료 이벤트 없는 SSE가 결과를 유출하지 않는지, response/model/error 최소 필드.
- UI 사용 중 리스너 종료/중복 실행/포트 충돌, DPAPI 회귀, 비밀 없는 로그.
- 가짜 provider 호출 횟수로 자동 재시도/자동 전송이 없음을 검증.
- 실제 ChatGPT 시험은 자격 확인이 끝난 경우에만, 사용자 선택한 계정/모델로 최소 요청.
  Windows 테스트/모의 provider/실제 OAuth·추론/브라우저 통합을 각각 구분해 줘.
