tbox-buddy 로컬 세션에 전달할 구현 프롬프트 (2026-10-02)

현재 PC에 있는 tbox-buddy의 소스를 찾아 구조와 로컬 지침을 읽고, 개인 ChatGPT 계정의 구독 사용량을 공식 방식으로 활용하는 연결을 구현해 줘. 기존 Gemini 연결과 다른 작업 중인 변경은 보존해 줘.

배경
- 모아는 https://changkwon.mso.so 에 있는 사내 커뮤니티·자료실·메신저다. 웹 앱 소스는 Linux 서버 /var/www/qaredi/tbox-v2이며 이 PC에 동일 경로가 있다고 가정하면 안 된다.
- 웹 메신저에는 Gemini 3.5 Flash 공용 API로 나만의 AI 대화와 문장 다듬기/맞춤법/번역을 구현했다. 한국어·영어·일본어·중국어·베트남어·스페인어를 선택할 수 있다.
- 이미지는 별도 Gemini 3.1 Flash Lite Image 유료 API로 미리보기 → 첨부 → 사람이 전송한다. 관리자가 켜기 전에는 꺼져 있다.
- 사용자는 tbox-buddy가 Windows PC에서 실행되는 로컬 AI 비서라고 확인했다. 이번 작업은 그 로컬 앱에서 개인의 ChatGPT 로그인과 추론을 처리하는 것이다.

확정된 진행 순서 (사용자 동의 2026-10-02)
- 사용자는 모아 웹사이트 연동을 위한 Sign in with ChatGPT 신청서를 제출했다고 알렸다. 승인 결과와 일정은 확인되지 않았으며, 웹사이트 직접 연동은 승인 대기 상태로 둔다.
- 이 로컬 작업은 먼저 tbox-buddy의 배포 형태와 사용자의 계정이 공식 로컬·오픈소스 경로의 적용 대상인지 확인한다. 대상이면 웹사이트 파트너 승인 대기를 이유로 개발을 멈추지 말고, 문서의 첫 로그인 등록 방식으로 진행한다.
- 첫 목표는 사용자가 'Continue with ChatGPT' → 브라우저에서 로그인·사용 승인 → buddy로 복귀 → 대화/다듬기/맞춤법/번역 결과 미리보기·복사를 할 수 있는 독립된 로컬 기능이다. 사용자가 API 키를 발급하거나 입력하는 단계를 요구하지 않는다.
- 그다음 모아 메신저와 연결할 계약·방식을 정리한다. 로컬에서 대화가 된 것과 모아 웹사이트 연동 승인을 받은 것은 별도로 기록한다.

개발 전에 현재 문서를 실제로 읽어 제공 범위와 tbox-buddy의 배포 형태/라이선스가 맞는지 확인해 줘. 문서는 오픈소스·로컬 호스팅 앱 흐름을 안내하고, 유료 또는 원격 호스팅 앱은 별도 신청 대상으로 안내한다. 모아 웹 서버를 대신하는 공용 OAuth 프록시로 우회하지 마. 필요 조건이 불분명하면 정확한 차이와 가능한 공식 경로를 보고하고, 계정 없이 할 수 있는 화면과 연결 구조부터 완성해 줘. 저장소 공개나 서비스 신청을 임의로 진행하지 마.

구현 범위
1. 설정/첫 실행 안내에 'Continue with ChatGPT' 연결 버튼, 연결된 계정·워크스페이스 표시, 계정 전환, 로그아웃/연결 해제를 추가해 줘. 모아 로그인과 ChatGPT 로그인은 서로 다른 계정 연결로 설명해 줘.
2. 공식 시스템 브라우저 OAuth Authorization Code + PKCE S256 흐름을 사용해 줘. 로컬 콜백은 127.0.0.1에만 바인딩하고, state/nonce/단일 사용/타임아웃/정확한 redirect_uri를 검사해 줘. 현재 안내의 dynamic_agent_client는 첫 등록 진입값이며 토큰 교환·보관은 반환된 issued client_id로 해야 한다. 호스트별 ext_agent_host_id는 난수로 생성해 재시작 후에도 유지해 줘.
3. ID 토큰의 서명/JWKS·issuer·audience·만료·nonce를 확인하고, 실제 허용된 chatgpt.tokens.use.direct scope를 확인해 줘. 단순 로그인 성공이나 구독 여부만으로 추론 권한이 생겼다고 판단하지 마. 기존 계정 재인증 때 다른 계정의 토큰으로 덮어쓰지 마.
4. access/refresh/ID token은 계정과 issued client_id별로 Windows Credential Manager/DPAPI 등 OS 보안 저장소에 보관해 줘. 갱신과 회전, 취소/실패, 로그아웃 시 정리를 구현해 줘. 브라우저 쿠키·다른 앱의 저장된 토큰을 추출하거나 수동 붙여 넣게 하지 마. 키/토큰을 로그·클립보드·URL·저장소·모아 서버에 보내지 마.
5. 해당 사용자의 OAuth 토큰으로 공식 GET https://api.openai.com/v1/models 를 조회해 계정이 실제로 사용할 수 있는 모델을 보여 줘. 응답 형식은 일반 API 키의 모델 목록과 같다고 가정하지 마. 표시 이름과 실제 slug를 구분하고 임의로 최신 모델을 고정하지 마.
6. 공식 POST https://api.openai.com/v1/responses 를 사용해 줘. 현재 구독 사용 경로의 요구사항은 store:false, stream:true, input 배열이며 SSE를 끝까지 처리해야 한다. 개발자 지시는 instructions/developer 메시지에 넣고, 지원하지 않는 파라미터와 도구는 최신 문서에 맞춰 제외해 줘. ChatGPT backend-api 비공식 경로를 호출하지 마.
7. 로컬 비서에서 일반 대화, 문장 다듬기, 맞춤법, 번역을 지원해 줘. 문장 도구는 사용자가 선택/붙여 넣은 텍스트만 처리하고 원문과 결과를 보여 줘. 결과 복사, 원문 되돌리기를 제공하고 메신저 전송·클립보드 읽기·파일 수집을 자동 수행하지 마.
8. '개인 ChatGPT 요금제 사용 중'과 공식 사용량 관리 링크를 보여 줘. 최초 사용 안내, 사용 한도 초과/계정 권한 없음/재로그인 필요 상태를 구분해 줘. 무료·무제한이라고 표시하거나 한도 초과 시 유료 API로 자동 전환하지 마.
9. 현재 문서상 이 구독 연결 경로는 이미지 생성 도구를 지원하지 않는다. 텍스트 연결에 이미지 기능이 포함된다고 꾸미지 마. 이미지 기능은 기존 지원 공급자가 있을 때 그 공급자와 과금 방식을 따로 표시하고, 없으면 ChatGPT 앱에서 직접 만드는 동선을 제공해 줘.

모아와의 연결 경계
- 우선 로컬 비서에서 텍스트 입력 → 구독으로 처리 → 결과 미리보기/복사까지 독립적으로 완성해 줘. 웹에서는 현재 '요청문 복사 → ChatGPT 열기' 수동 경로도 제공한다.
- 이후 웹에서 로컬 비서로 요청을 넘길 때 필요한 최소 계약을 문서화해 줘: schema_version, request_id, action(polish/spelling/translate), text(최대 4,000자), target_language; 응답은 request_id, state, text, provider, model, 공개해도 되는 error_code. 토큰·쿠키·다른 대화 기록은 넣지 않는다.
- 브라우저-로컬 자동 연결을 기존 지원 없이 임의로 만들지 마. 실제 전달 방식은 후속 웹 작업과 맞춰야 한다. 필요하면 127.0.0.1 고정 리스너, 명시적 페어링, Origin/Host 허용 목록, 재전송 방지, 요청별 사용자 확인, 로컬 네트워크 권한과 HTTPS 웹페이지 제약을 검토한 설계를 남겨 줘. 0.0.0.0에 서비스하거나 모아 서버가 개인의 구독을 대리 호출하는 구조는 만들지 마.
- 현재 웹 메신저 API는 브라우저 세션·CSRF와 사용자별 권한 검사로 동작하며 기존 tbox-buddy 파일 API 토큰에 메신저 권한이 자동 추가되지는 않았다. 자동 전송에 성공했다고 가정하지 마.

진행과 보고
- 소스를 찾을 수 없을 때만 실제 폴더 위치를 물어보고, 있으면 routine 구현은 자율적으로 진행해 줘.
- 사용자가 직접 해야 하는 ChatGPT 로그인만 필요한 단계에서 요청해 줘. 계정 연결 전에는 UI·콜백 처리·저장 구조·오류 처리를 구체적으로 완성해 줘.
- 테스트 추가/실행, 배포, 계정 로그인은 해당 세션의 사용자·상위 지침을 따른다. 실제 로그인/추론을 하지 않았으면 성공으로 보고하지 마.
- 마지막에 변경 파일, 로컬 실행 방법, 문서 확인 날짜/링크, 실제 확인한 것과 미확인 항목, 다음 웹 세션에 전달할 연동 계약을 정리해 줘.
