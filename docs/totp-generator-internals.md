## 동기화 (F-42, 2026-09-15 구현)

코드는 시각의 함수(스텝 = `시각 ÷ 30`)라 PC 시계가 어긋나면 화면의 코드가 서버에서 거부된다. 그래서 생성기는 **열릴 때 한 번과 그 뒤 5분마다** 서버에 시각을 물어 「서버 − PC」 차이를 구하고, 남은 초와 코드 계산에 그 차이를 더한다. 서버 시각을 파일에 박아 넣지 않는다(사용자 결정 2026-09-15).

**창구** — `GET /api/time` (`src/handlers/time.php`, 라우트 정책 `POLICY_PUBLIC`). 응답은 `{"now": <유닉스 초>, "period": 30}` 뿐이고 `Cache-Control: no-store` 다. 로그인·CSRF·감사 기록이 없다 — 읽기만 하고 대상이 없으며, 같은 값이 응답 헤더 `Date` 로도 이미 나간다.

**공식** — 보낸 때 `t0`, 받은 때 `t1`(둘 다 PC 시계), 응답 `now`(초):

```
offset = now × 1000 + (t1 − t0) ÷ 2 − t1        (밀리초, 「서버 − PC」)
serverNow() = Date.now() + offset
```

왕복 지연의 절반을 더해 **답이 만들어진 순간**을 `t1` 에 맞춘다. `Date.now()` 는 `serverNow()`·`syncTime()` 안에서만 쓰고, `tick()` 과 코드 계산은 `serverNow()` 만 본다.

**저장 키** — `localStorage['tbox-totp-offset'] = {"offset": <ms>, "at": <마지막으로 맞춘 때, PC 시계 ms>, "base": "<물어본 t-box 주소>"}`. 비밀 키는 이 값에 들어가지 않는다. 서버에서 **받는 것은 시각뿐이고 보내는 것은 없다**(SECURITY R-40 보충).

**상태 3종** (「시각 확인」 칸)

| 상태 | 언제 | 문구 |
|---|---|---|
| 맞춰짐 | 이번 화면에서 `/api/time` 응답을 받았다 | 「서버와 동기화됨 · 서버 시각 HH:MM:SS · PC 와 ±N초」 |
| 오프라인 · 보정값 | 서버에 닿지 못했지만 적어 둔 차이가 있다 | 「오프라인 · 저장된 보정값 사용(마지막 동기화 M분 전)」 |
| 오프라인 · PC | 한 번도 맞추지 못했다 | 「오프라인 · PC 시각 사용 — 코드가 틀리면 PC 시계를 맞추세요」 |

차이가 ±60초를 넘으면 상태 줄이 경고색이 된다.

**`file://` 처리** — 파일로 열면 `location.origin` 이 없어 물어볼 곳을 모른다. 그래서 상태 줄 아래에 t-box 주소 입력칸을 한 번 보여 주고(`https?://` 로 시작하는 값만 받는다), 적은 값을 `base` 로 저장한 뒤 맞추기를 시도한다. 서버에서 연 화면에는 이 칸이 없다.

**CORS 근거** — 생성기는 PC 에 받아 `file://` 로 여는 것이 전제라 출처가 달라진다. `/api/time` 이 내주는 것은 시각 하나뿐이라 다른 출처가 읽어도 잃을 것이 없어, `Access-Control-Allow-Origin: *`·`Access-Control-Allow-Methods: GET` 을 **이 핸들러에서만** 붙인다. 세션 쿠키로 내용이 갈리는 다른 응답에는 붙이지 않는다.

**CSP** — 생성기 전용 CSP(`deploy/sites/tbox-v2.conf` 의 location, 그리고 파일 안 `<meta>`)는 `default-src 'none'` 이라 어떤 연결도 막는다. 여기에 `connect-src 'self'` 한 칸만 더한다. `'self'` 라서 **이 서버 말고는 어디로도 보낼 수 없다** — 비밀 키가 새는 경로를 만들지 않는 것이 이 한 칸의 요점이다. 적용 전에는 fetch 가 막혀 상태 줄이 「오프라인」 이 되고, 그 상태에서도 코드는 PC 시계로 계속 나온다. 파일로 연 문서에는 `'self'` 에 해당하는 출처가 없으므로, 주소를 적어도 실제 맞추기는 CSP 를 그 주소까지 넓히는 결정이 있어야 동작한다(넓히면 「어디로도 보낼 수 없다」는 성질이 약해진다 — 미결).

**잠금 문구** — 최소 길이 12자(`MIN_PASS`). 안내는 「잠금 문구는 12자 이상이어야 합니다. 단어 2~3개를 권합니다.」
