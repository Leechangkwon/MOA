# 커뮤니티 스레드·메신저 — 적용과 검증

현재 상태(2026-10-03): 아래 최초 클라우드 인계 이후 기존 기능은 v2.43.1로 운영 반영됐다(`docs/completion-release-2026-10-03.md`). 이후 발견된 사진 첨부 누락 수정은 별도로 운영 반영을 기다린다. 최신 수정·서버 수락 절차는 `docs/thread-photo-fix-2026-10-03.md`를 따른다.

커뮤니티의 기존 공통 셸에 모든 스레드·나의 스레드·공유 스레드를 추가한다. `/community/`의 작성란에서 사진/영상/짧은 글을 남기고, 기존 문서(`/community/workspace`)·공간·게시판도 같은 메뉴에서 사용한다. 이전 `?space=`/`?trash=` 문서 링크는 계속 동작한다. 별도 앱이나 메신저 페이지는 없다. 회원 1:1 대화와 GPT 대화는 어느 커뮤니티 화면에서도 같은 모달로 연다.

## 화면 견본

`docs/theme-shots/travel-memories-{desktop,mobile,compose}.png`와 `community-messenger-{desktop,mobile}.png`는 실제 컴포넌트 및 축약한 공통 셸 fixture로 만든 브라우저 견본이다. PHP로 렌더한 운영 화면은 아니다. 개인 페이지의 여행자·풍경·글은 합성 시험 데이터이며 실제 게시물이 아니다.

## 사용 흐름

- 사진·영상 10개, 사진당 20MB·영상당 100MB, 계정당 2GB. JPG/PNG/WebP/GIF와 MP4/MOV/WebM을 받는다. HEIC는 JPG로 내보내야 한다. 브라우저·기기별 영상 코덱 재생 가능 여부는 다르다.
- 기본은 나만 보기. 커뮤니티 공개는 로그인한 사용자에게 보인다. 링크 공유는 커뮤니티에도 보이며, 발급한 링크로 로그인 없는 친구도 볼 수 있다. 개인 페이지 링크에는 그 소유자의 ‘링크 공유’ 기록만 나온다. 링크는 30일 만료이며 전체 해제가 가능하다. 한 글의 공개 범위를 좁히면 해당 글의 개별 링크를 폐기한다.
- 짧은 글만으로도 저장 가능. 개인 페이지에서 피드/앨범 전환, 검색, 댓글, 좋아요, 수정과 삭제를 사용할 수 있다.
- 계정별 IndexedDB 임시 저장은 텍스트와 선택한 파일을 보관한다. 앱을 처음 여는 데와 서버 저장에는 인터넷이 필요하다. 자동 게시·백그라운드 동기화는 하지 않는다. 기기/브라우저 데이터 삭제 시 임시 저장은 사라진다.
- GPT 메신저는 서버 API 설정 후 실제 텍스트 대화를 지원한다. 전송 버튼을 누른 글과 본인의 최근 GPT 대화 10턴만 OpenAI에 전달한다. 회원 대화·문서·사진/영상은 자동으로 읽거나 전송하지 않는다. 응답은 복사하거나 스레드 꾸미기 화면으로 가져와 확인한 뒤 저장한다. 원본 메모와 첫 첨부파일은 소유자에게 보존한다.
- 사진/영상 가공은 요청문과 원본을 ChatGPT에 전달하고 결과 파일을 가져오는 방식이다. 앱 안에서 사진/영상 생성이 자동 실행되는 기능은 아니다. 실제 가능 여부는 사용하는 ChatGPT 기능에 따른다.
- 회원 메시지는 참여자만, GPT 이력은 본인만 읽는다. 회원 검색은 두 글자부터 시작한다. 회원 전송은 분당 30건, GPT 성공 응답은 시간당 20회다. 모달을 열어 둔 동안 5초마다 회원 대화를 확인하며, 읽은 마지막 메시지까지만 읽음 처리한다. 푸시 알림은 없다.
- 회원/GPT 작성 중인 메시지는 현재 페이지의 메모리에 각각 보관하여 탭 전환·모달 닫기 후에도 남는다. 새로고침/다른 페이지 이동 시 미전송 메시지는 사라진다. 서버 전송 재시도는 같은 요청 ID를 사용해 중복 저장을 방지한다. GPT 공급자 응답 후 DB 저장 실패/네트워크 타임아웃 같은 경계에서는 재시도 시 공급자 비용이 다시 발생할 수 있다.

## 서버 적용

현재 클라우드는 git2만 접속할 수 있다. **운영 서버·DB에 적용하지 않았고 실제 앱에 배포된 상태가 아니다.** 서버 운영 환경에서 다음을 순서대로 진행한다.

1. 기존 코드/DB/파일 백업을 확보한다. 격리된 검증 환경에서 먼저 아래 검사를 완료한다. DB 통합 수락 항목과 기존 공통 회귀 묶음은 여기서 실행하지 못했다.
2. DB 소유자/배포 계정으로 `db/migrations/2026-10-03_community_memories.sql`, `db/migrations/2026-10-03_community_messenger.sql`을 순서대로 `psql -X -v ON_ERROR_STOP=1 -f ...`로 적용한다. 재실행 가능하고 기존 표는 수정하지 않는다. `tbox_app` 쓰기 권한과 `tbox_backup` 읽기 권한을 포함한다. 커스텀 역할을 쓰는 설치는 해당 역할에도 같은 최소 권한을 적용한다.
3. 검증한 작업 브랜치의 앱 파일을 배포한다. `STORAGE_DIR` 아래 `memories/`가 PHP 사용자 소유 0700으로 생성된다. 파일은 무작위 UUID 이름·0600이며 public 밖에 있다. 기존 storage 백업에 포함되고 정합성 검사에서 SHA-256을 대조한다.
4. `deploy/sites/tbox-v2.conf`와 로컬용 설정의 **여행 화면 전용 location**을 실제 nginx 설정에 반영한다. `nginx -t` 후 reload한다. 공통 CSP를 느슨하게 하지 않고 여행 화면에서 앱의 blob 미리보기 CSP를 전달한다. 미반영 시 nginx의 두 번째 CSP가 사진·영상 미리보기를 막는다. 공유 토큰이 nginx 접근 로그에 남지 않도록 해당 location은 `access_log off`다. 앞단 프록시가 별도 접근 로그를 남긴다면 공유 경로도 같은 방식으로 제외해야 한다.
5. 기존 PHP 업로드 100M/post 105M와 nginx 101m 설정을 유지한다. OPcache 운영 방식에 맞게 PHP-FPM을 reload한다.
6. GPT를 사용할 서버의 public 밖 `.env`에 `COMMUNITY_GPT_ENABLED=1`, `OPENAI_API_KEY=<서버 전용 키>`, `COMMUNITY_GPT_MODEL=gpt-4.1-mini`를 설정한다. PHP cURL과 서버의 `api.openai.com:443` 송신/DNS가 필요하다. 고정 HTTPS 목적지, 공인 IP 검사/IP 고정, TLS 검증, 리다이렉트 금지, 25초 제한, 응답 256KiB 제한을 적용한다. 목적지 URL을 사용자 입력/환경변수로 변경할 수 없다. 설정 전에는 GPT 미연결 안내를 표시한다. 클라우드의 git2 전용 정책을 변경하지 않았으며 실제 공급자 호출도 하지 않았다.
7. 실제 휴대폰에서 로그인 복귀, 촬영/앨범/영상, 저장, 외부 친구의 링크와 회원/GPT 모달을 확인한다.

게시되지 않은 업로드는 기본 dry run인 `php scripts/memories_cleanup.php`로 확인하며, 명시적으로 `--apply`를 주면 7일 넘게 어느 글에도 붙지 않은 파일만 최대 500개 정리한다. 게시된 원본·삭제한 글의 파일은 이 스크립트가 지우지 않는다. 정리 후 오래된 임시 저장의 첨부가 사라졌다면 원본 파일을 다시 골라야 한다. 별도 예약 작업은 만들지 않았다.

롤백: 이전 앱 코드와 nginx 설정을 복원한다. 새 memory_* 및 conversations/messages/gpt_turns 표와 파일은 보존한다. GPT 설정은 비활성으로 돌린다. 기존 앱은 이 표를 참조하지 않는다. 여행 파일이 남아 있는 동안 정합성 검사 스크립트의 여행 미디어 지원은 유지해야 고아 파일 오탐이 발생하지 않는다.

## 검증 상태

이 환경에서 완료:

- `node --check` — 스레드/메신저 UI와 수정한 문서 편집기·공통 app.js.
- `bash scripts/security_lint.sh` — 금지 패턴 0건.
- `python3 tests/community/memories_browser.py` — 실제 Chromium + 합성 HTTP 응답으로 12개 시나리오. 320/390/768/1024px, 촬영 입력, 사진 포함 임시 저장 복구, 업로드 실패, 저장 재시도 중 요청 ID/업로드 재사용, 비공개 기본값, XSS 문자열, 좋아요/댓글, GPT 요청문·결과 가져오기, 공유 해제, 개인 앨범, 익명 읽기 UI, 계정별 초안, 읽기 전용 계정.
- `python3 tests/community/messenger_browser.py` — Chromium + 합성 HTTP로 9개 시나리오: 스레드/공통 내비 연결, 페이지 이동 없는 모달, XSS 문자열, 읽음 처리, 탭/닫기 후 초안, 전송 실패/중복 방지, 회원 검색, GPT 응답 지연 중 다른 대화 보호, 꾸미기 편집 연결, 모바일 목록 전환/Escape, GPT 미설정 안내.
- 커뮤니티 import 버전은 저장소 PHP 스크립트와 동일한 정규화/해시 알고리즘으로 갱신했다. PHP 구현 자체의 `--check`는 아래 환경에서 실행해야 한다.

**미실행**: 이 클라우드에는 PHP·PostgreSQL·nginx가 없다. 따라서 PHP 구문 실행, 실제 템플릿 렌더, PHP 권한/입력 단위 검사, SQL migration, DB 통합, nginx 설정 검사, 위키 검사, 공통 회귀 묶음은 통과로 간주하면 안 된다. 브라우저 검사는 서버 권한 검증을 대체하지 않는다.

PHP가 있는 환경에서 `bash tests/community/memories_check.sh`를 실행한다. PHP가 없으면 명확히 종료 코드 2를 반환한다. 브라우저 검사는 실제 컴포넌트 HTML에 고정 URL과 축약한 공통 셸을 대입한다. PHP가 있는 환경에서는 `memories_render.php`로 실제 공통 셸/공개 화면 렌더와 ID 중복·로그인 복귀 경로를 별도로 확인한다. `tests/community/memories_unit.php`에는 비공개/다른 소유자/글별 capability/공개 범위 축소/대량 할당/입력 형식 거부 검사 24개와 메신저 참여자/입력 검사 11개를 준비했다.

격리된 DB/서버에서 반드시 확인할 항목:

- 사용자 A/B/Guest로 새 업로드·글·수정·삭제·미디어 요청의 세션/CSRF/소유권 검사. A의 private 글·첨부는 B/익명에게 404. Guest 쓰기는 라우터에서 거부.
- 변경 전 revision 수정은 409, 중복 request_id 생성은 기존 ID 한 건, 다른 사용자/다른 글에 붙은 media_id 재사용은 거부.
- profile/post 링크는 shared 기록만 반환. 임의 UUID, 변조 토큰, 다른 글 파일, 미게시 파일, 원본으로 교체되어 숨겨진 파일, 만료/해제 링크, 비활성/만료 계정은 외부에서 읽을 수 없어야 함.
- 실제 MIME/용량 검사, 파일 권한, SHA-256 정합성, 백업 계정이 새 표를 읽는지 확인. 비디오 Range(정상/접미/잘못된/범위 밖) 206/416 확인.
- 사용자 A/B 대화 ID를 C/Guest/익명에게 넘겨 목록·본문·전송·읽음 접근이 거부되는지 확인. 만료/비활성 상대 및 임의 UUID, CSRF 누락, 클라이언트 sender_id 위조, 중복 request_id 충돌, 페이지 나눔/동시 전송 순서, 읽음 커서가 다른 대화 ID로 전진하지 않는지 확인.
- A의 GPT 이력이 B에게 나오지 않는지, GPT 미설정/키 오류/타임아웃/과대 응답/공급자 429 시 내용이 남는지, 본문/키가 로그에 남지 않는지 확인. 명시 전송 전에는 공급자 요청이 없어야 한다. 실제 API 응답과 비용·서버 시간 제한도 확인한다.
- 기존 문서/게시판/오늘 페이지에서 공통 메신저와 알림·검색·계정 메뉴가 충돌하지 않는지 확인. 스레드 CSS가 기존 화면에 영향을 주지 않아야 한다.
- 기존 공통 회귀 묶음(`CLAUDE.md`): stage26, help_button, api_whoami, api_read, api_folders, f66, f68, q_launcher. 기존 규칙상 운영 쓰기 시험은 `tests/run.sh`의 보호를 따라야 한다. 전체 묶음은 20분 이상 걸릴 수 있다.
