## 1. 새 페이지 제목 (UX-1 · Q:T-11)

- 제목 칸 `#page-title-input` 에 자리표시 「제목」(`placeholder` — `page_view.php`, 고정 글자) · `enterkeyhint="next"`.
- 편집 모드에서 제목 값이 **서버 기본 제목**(「제목 없는 페이지」 · 「제목 없는 데이터베이스」 · 「제목 없는 글」 — `editor.js` `DEFAULT_TITLES`, 서버 글자와 같은지는 수락 시험이 대조)이면 칸을 비운다. 비운 채 두면 `save()` 는 전과 같이 `state.title`(서버 값)을 보낸다 — 저장 창구·규칙 그대로.
- **새로 만든 페이지 가리기** — 만든 쪽이 주소에 `&new=1` 을 붙인다(「새 페이지」 두 단추 `bindNewPage` · 트리 「하위 추가」). 편집기가 `?edit=1` 과 함께 읽고 `history.replaceState` 로 둘 다 지운다. `new=1` 이면 편집을 켤 때 **커서를 제목 칸**에(아니면 전처럼 본문).
- 트리 「하위 추가」 는 전에는 읽기 모드로 열렸다 — 이제 「새 페이지」와 같이 `?edit=1&new=1`(편집 모드 · 제목 칸).
- 제목 칸에서 **Enter** → 본문 첫 블록 맨 앞(`TextSelection.atStart`). 한글 조합 중 Enter(`isComposing` · keyCode 229)와 Shift·Ctrl·Alt·Meta 조합은 건드리지 않는다.
- **판단(지시서 요청)**: 기존 페이지 제목이 우연히 「제목 없는 페이지」여도 편집 모드에서는 **빈 칸 + 자리표시**로 보인다(권장안 그대로) — 사람이 그 글자를 제목으로 쓸 까닭이 없고, 비워 두면 값은 그대로 남는다. 커서는 새 페이지(`new=1`)일 때만 제목 칸.
- 페이지 안 「＋ 페이지」(`#page-new-child` — 하위 페이지 카드를 **제자리에** 더함 · `browser_smoke` 24 가 보는 동작)는 옮겨 가지 않게 그대로 두었다 — 그 카드를 열어 편집하면 위 규칙으로 빈 칸 + 자리표시.

## 2. 좁은 폭 편집 머리 (UX-2 · Q:T-12)

- 머리 한 줄 = 왼쪽 상태 배지 줄 + 오른쪽 「더보기」 · 「편집 끝」. 「사용 방법」·「이력」은 **더보기 맨 위**(`#page-more-help`(`data-help-open` — app.js 위임 그대로) · `#page-more-history`(같은 `openHistory`)) — 편집을 켤 때만 `hidden` 이 풀리고, 넓은 폭은 CSS 가 늘 숨긴다. 「이력」은 머리 「이력」이 열려 있을 때(창구가 페이지를 내준 뒤)만.
- 속성 요약(U3)은 한 줄(말줄임) · 칸 사이 20 → 12px · 빈 알림 줄이 칸 사이를 한 번 더 먹지 않게(`#msg:empty` 위 여백 −12px — 글자가 오면 제자리 · 알림 역할 그대로).

## 7. 2단계 코드 자동 제출 (UX-9 · Q:T-17)

- 로그인 화면 `initLogin` — 코드 칸 `input` 에서 2단계이고 · 보내는 중이 아니고 · `^[0-9]{6}$` 이고 · 마지막 자동 제출 코드와 다르면 `form.requestSubmit(submit)` 한 번. 제출 처리기는 `sending` 빗장으로 두 번째 제출을 버린다(자동 + Enter/단추가 겹쳐도 요청 1). 틀리면 기존대로 칸 비우고 초점(새 코드 → 다시 한 번). 1단계로 되돌아가면 기억한 코드를 지운다.
- 다른 코드 칸(재인증 · 권한 매트릭스 · 실행 파일 확인 · 토큰)은 그대로 — `requestSubmit` 은 app.js 에 한 곳(수락 시험 정적).

## 9. t-box 올리기 뒤 (UX-5 화면 부분 · Q:T-19)

- `upload()` 가 줄마다 결과를 모아 **모두 201**(그리고 id 가 UUID)이면 `finish()` 에서 고른 파일·진행 표를 비우고(다음에 열었을 때 같은 파일을 두 번 올리지 않게 — 설명·등급 고른 값은 둔다) 창을 닫는다. 목록을 다시 그린 `renderFiles` 끝의 `showFresh()` 가 이 화면이 방금 그린 줄(`pageRows`)에서 서버가 준 id 로 줄을 찾아 `tr.is-fresh`(2.5초 · `--accent-soft` 배경만 · 움직임 0) + `scrollIntoView({block:'center'})`(「움직임 줄이기」면 곧바로).
- 하나라도 거부 · 확인 필요(F-65) · 중단 · 오류면 창을 열어 둔다(전과 같다). **등급 기본값은 바꾸지 않았다**(「등급을 고르세요」 — 정책 결정 대기).
- 「검사 대기 안내」: 올리기 응답(`{id, name}`)에는 검사 상태가 없고 창에도 그런 안내가 없다 — 운영(`SCAN_ENABLED=1`)에서도 올린 직후 창이 닫히고, 새 줄의 「검사 중」 배지가 그 안내다.

## 11. 다른 탭에서 다시 로그인한 뒤 옛 탭 (UX-11 · Q:T-21)

- 원인(운영 11:32~): 탭 A 는 부팅 때 받은 CSRF 토큰을 계속 쓴다 → 다른 탭에서 다시 로그인하면 쿠키는 새 세션 · 토큰은 옛것 → heartbeat 30초마다 `csrf|deny|token_mismatch` · 저장은 일반 403.
- **한 곳 도우미** `probeSession(expectUser, sentToken)`(app.js · `window.qarediSessionProbe`) — `fetchMe(true)`(no-store)를 **진행 중 약속 하나로** 나눠 쓰고 `login · other · fresh(token) · same · check` 로 답한다.
- 커뮤니티 `api()`(editor.js — database·templates·palettes 등 부품도 이 함수를 넘겨받아 쓴다): 쓰기 403 이고 `next` 가 없으면 → fresh 면 토큰을 바꾸고 `qarediSetCsrf` 로 셸도 같게 한 뒤 **그 요청 한 번만** 다시(또 403 이면 그대로) · other 면 다시 보내지 않고 탭을 멈춤(`#msg` 「다른 계정으로 로그인되어 이 탭은 멈췄습니다 — 새로 고치세요」 · 뒤의 쓰기와 자동 폴링 요청 0) · login 이면 401 로 돌려줘 부르는 쪽의 기존 로그인 흐름(임시저장 지킴) · 자동 요청은 조용히 같은 길.
- 일괄 작업의 보내기 다섯은 `{sessionRetry: false}` — 제 `sessionCheck`(멈춤 · 「이어서 하기」) 그대로.
- t-box 파일 화면: 같은 문제 있음(한 건 쓰기가 403 「권한 없음」) → 한 건 쓰기 열 곳 + 즐겨찾기(`favFetch` 쓰기)를 `writeFetch`(같은 도우미 · 한 번 다시 · 다른 계정 멈춤)로. 일괄(`bulkFetch`)은 그대로. **관리 화면(계정·조직·권한·토큰)과 내 계정은 바꾸지 않았다**(재인증 관문 뒤 · 자동 요청 없음 · 범위) — 남은 것.
- SECURITY 7장 한 행(토큰은 같은 출처 `/api/me` no-store 답에서만 · 같은 계정일 때만 · 요청마다 한 번만 · 교차 사이트 공격자는 답을 읽을 수 없으니 CSRF 방어는 그대로 · 자동 제출 판단 포함).

## 14. 지시와 다르게 한 것 · 남은 것 · 사람 판단

- **값 있는 블록은 지시대로 두 단계**(누르면 미리보기 → 「넣기」). 그림·파일을 누르면 곧바로 고르기 창을 여는 쪽이 흐름 3 에서 한 번 더 줄지만(6 → 5) 지시가 「지금처럼」이라 두었다 — 판단 필요.
- **「최근」 판 자리** — 「맨 위」 대신 즐겨찾기 판 다음(결정 PK-D5). 즐겨찾기가 많으면 폰에서 최근이 밀린다 — 판단 필요.
- **☰ 에는 보이는 배지를 달지 않음** — 바로 옆 윗줄 종이 같은 숫자를 보이고 ☰ 이름(화면 읽기)에 숫자가 있다.
- **페이지 안 「＋ 페이지」(`#page-new-child`)는 제자리 카드 그대로** — 트리 「하위 추가」만 편집 모드 + 제목 칸으로. 제자리 카드를 열어 편집하면 빈 칸 + 자리표시.
- **t-box 관리 화면(계정·조직·권한·토큰)·내 계정의 쓰기**는 UX-11 도우미에 넣지 않았다(재인증 관문 뒤 · 자동 요청 없음) — 같은 문제가 남아 있다(다른 탭에서 다시 로그인하면 403 「권한 없음」).
- 이어 쓰기(흐름 2)는 5 → 4 — 「읽기 화면 본문 탭 = 편집」은 라운드 2.
- 등급 기본값(UX-5 뒷부분)·게시판 「새 글」 한 단계(UX-6 앞부분)·편집기 안 바로 올리기·빈 페이지 정리 — 라운드 2(지시 범위 밖).
- 흐름 8 시간(7.60 → 3.37초)은 기계 입력이라 사람이 코드를 옮겨 치는 시간이 빠져 있다 — 줄어든 것은 「로그인」 누름 하나.
- 운영 경보 로그: 이 작업 동안 AL-9 가 많이 늘었다 — 대부분 목록의 옛 회귀 시험(stage5a2 · stage7b · help_button · stage4c 사본)이 `sudo -u postgres psql -c '…'`(SQL 을 인자로)를 모양마다 부른 것이고, 이 묶음이 새로 쓴 셸(`ux_r1_ui.sh` · `regress.sh`)은 운영 읽기를 읽기 전용 역할 · 표준입력으로만 한다(`pg_dump` 한 번씩만 sudo).
