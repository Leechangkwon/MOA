# 프로젝트에 개발 과정과 기능 설명을 계속 기록하기

## 문서를 먼저 준비하기

업무 → 프로젝트 → 작업 추가에서 **개발 현황**, **기능 설명**, **개발 기록**을 만듭니다. 작업을 열고 설명을 누르면 바로 편집할 수 있고, 긴 글은 전체 화면으로 열어 작성합니다. 함께 쓰려면 팀 공간의 프로젝트나 편집 공유된 프로젝트를 선택합니다.

- 개발 현황: 지금 완료된 것, 진행 중인 것, 남은 문제를 최신 상태로 고칩니다.
- 기능 설명: 목적과 사용 순서를 유지하고 바뀐 문장만 고칩니다.
- 개발 기록: 날짜, 변경 이유, 변경 내용, 검사 결과, 배포 여부를 끝에 추가합니다. 구현 완료와 운영 반영은 구분합니다.

각 문서 주소를 AI에 알려 주면 같은 문서를 계속 갱신합니다. 주소를 모르겠으면 프로젝트 목록 → 그 아래 문서 목록 순서로 찾게 합니다. 같은 이름의 문서가 여러 개면 주소로 대상을 지정합니다. 새 문서를 프로젝트 아래에 만드는 일은 현재 웹에서 합니다.

## 연결 방식

**로컬 MCP**: 최신 `clients/mcp`를 설치한 환경에서 MCP 프로그램을 재시작합니다. 기존 설정의 모아 주소와 개인 프로그램 토큰을 사용합니다. 읽기는 「커뮤니티 읽기」, 갱신은 「커뮤니티 글쓰기」 범위가 필요합니다. 기존 토큰이 이미 쓰기 범위를 가지면 재발급할 필요가 없습니다. 프로그램 설치 방법은 `clients/mcp/README.md`에 있습니다.

**웹 OAuth MCP**: 원격 연결이 활성화된 환경에서 연결을 승인할 때 「업무 프로젝트·문서 읽기」와 필요하면 「업무 문서 갱신」을 선택합니다. 옛 연결에는 새 권한을 자동 추가하지 않습니다. 도구가 보이지 않으면 업무 권한을 요청하는 연결로 다시 승인합니다. 서버가 비활성이라고 표시되면 코드 배포만으로는 ChatGPT에서 쓸 수 없습니다. 운영 활성화와 실제 ChatGPT 계정 연결 검증은 별도 상태입니다. 이 기능에 OpenAI API 키를 붙여 넣지 않습니다.

## 이렇게 요청하기

> 이 프로젝트의 기능 설명과 개발 기록을 관리해 줘. 먼저 현재 문서를 읽고, 이번 개발로 달라진 문장만 수정해. 개발 기록 끝에는 날짜·변경 이유·검사 결과·배포 여부를 추가해. 기존 그림과 표는 보존하고, 다른 사람이 먼저 수정했다면 다시 읽고 충돌을 알려 줘. 문서 주소: …

## 제공하는 도구

| 도구 | 용도 |
|---|---|
| `qaredi_list_work_projects` | 프로젝트 찾기. `next_after_id`로 다음 목록 |
| `qaredi_list_work_documents` | `parent_id` 바로 아래 작업·문서 찾기 |
| `qaredi_read_work_document` | 원본 블록과 현재 `doc_version`, 편집 가능 여부 읽기 |
| `qaredi_create_work_document` | 지정한 기존 프로젝트의 작업 목록에 새 작업글 만들기 |
| `qaredi_update_work_document` | 지정 문구 교체와 끝에 기록 추가 |

갱신 예시: `page_id`, 읽은 `doc_version`, `replacements: [{block_id, old_text, new_text}]`, `append: [{type: "heading", level: 2, text: "개발 기록"}, {text: "검사 통과 / 운영 미반영"}]`. 추가 가능한 종류는 문단·제목·번호/글머리 목록·인용이며 `text`는 일반 글자입니다. Markdown 문법을 렌더링하지 않습니다. 문구 교체는 한 블록 안에서 정확히 한 번 나오는 문자열만 받습니다. 표·그림 자체와 멘션은 웹에서 편집합니다.

## 저장과 충돌

읽기 공유만 받은 문서는 수정할 수 없습니다. 관리자 특권만으로 보이는 문서, 게시판 글·게시된 문서는 이 도구에서 제외합니다. 쓰기를 허용하면 기존 문서를 함께 보는 사람에게도 바뀐 내용이 보입니다. 공유 범위·소유자·부모·첨부는 바꾸지 않습니다.

한 요청의 변경은 함께 저장되며 이전 판이 남습니다. 다른 창에서 먼저 저장했거나 지정 문구가 달라졌으면 변경하지 않고 충돌을 알립니다. 응답을 받지 못했을 때도 먼저 문서를 다시 읽어 저장 여부를 확인해야 합니다. 같은 기록을 무작정 재전송하지 않습니다.

점검봇은 아직 이 문서에 자동 게시하도록 연결되지 않았습니다. 확인된 점검 결과를 AI에게 주어 기록하게 할 수 있으며, 봇 자동 실행·게시·운영 배포는 이 기능에 포함되지 않습니다.

## 새 글을 프로젝트 작업 목록에 등록하기

기능별 개발 기록이나 예정 과제를 등록할 때는 프로젝트 설명 본문에 한꺼번에 덧붙이지 않습니다. 사용자가 지정한 프로젝트를 읽고 현재 섹션을 확인한 뒤, `qaredi_create_work_document`로 작업글을 하나씩 만듭니다. 프로젝트 설명은 서비스 개요·공통 기준을 둘 때 사용하고, 항목별 기록은 작업 목록에서 바로 열 수 있게 합니다.

입력은 `project_id`, 새 작업마다 고유한 `request_id` UUID, `title`, `blocks: [{type, text, level?}]`와 선택 항목 `status`, `section`입니다. 본문은 평문 문단·제목·목록·인용 1~100개이며 파일·그림·표는 웹에서 추가합니다. `section`에는 프로젝트 읽기의 `project.sections`에 나온 `value`를 사용합니다. 상태 기본은 할 일이고 완료·확인 대기는 근거에 따라 구분합니다.

응답이 불분명하면 `request_id`를 문서 주소로 다시 읽습니다. 같은 요청의 재전송은 같은 UUID를 유지하고, 본문이 달라졌거나 사람이 수정·삭제했다면 덮어쓰거나 다시 만들지 않습니다. 이 기능은 프로젝트 생성·섹션 설정·삭제·이동·공유 변경을 지원하지 않습니다. 외부 ChatGPT는 기존 `work.write` 승인, 로컬은 `community.write` 개인 토큰과 실제 프로젝트 편집 권한이 필요합니다.
