## 목적과 범위

사용자 요청: 위젯을 단순히 확대/축소하지 않고 소·중·대에서 무엇을 보여 주면 편리한지 전체 기능을 상세히 파악한 뒤 기획한다. 앞서 확인한 개별 위치·크기 잠금과 전체 배치 저장, 자유 배치 요구를 함께 반영한다.

실제 TBOX/COMMUNITY/MCP 라우트 선언 395개와 표 외 런처/MCP 진입점, 관련 handler/service/view/assets를 세 도메인으로 나눠 읽고 교차 대조했다. 라우트 개수는 사용자 기능 수가 아니다. API만 있는 기능, 휴면 화면 경로, 외부 설정 조건을 현재 사용 가능한 기능과 구분했다.

변경 파일:

- `docs/dashboard-widget-plan.md`: 전체 기능 지도, 31개 위젯 후보, 우선 7종의 정보·행동·원본·빈 상태 계약, 개인/공동 범위, 소/중/대와 자유 조절, 개별 잠금·전체 저장, 기본 구성·안내, 후속 설계 과제.
- `docs/dashboard-widget-audit/`: T-box/커뮤니티/사이트 도메인별 근거, 라우트 교차검토와 원문 목록, 계획 독립 검토.
- `docs/server-context/PRD.md`, `docs/server-context/STAGES.md`: 최신 사용자 요구와 기획 상태 기록. 부모 문서와의 통합은 후속 구현 착수 시 비교·병합한다.
- 이 작업 기록.

앱 코드, DB, 설정, 실제 사용자 콘텐츠는 변경하지 않는다. 문서만 담긴 작업 브랜치이며 이 문서를 기능 구현 지시서나 운영 배포 완료로 해석하지 않는다. 대화에 표시할 별도 ‘내 작업’ 시안은 합성 데이터와 로컬 상호작용만 사용한다.
