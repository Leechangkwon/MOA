## 목적과 범위

사용자 요청: 모아 서비스의 시작·완료·진행·예정 사항을 기획자 관점으로 새 프로젝트에 기록. 사용자가 ‘모아’ 프로젝트를 생성한 뒤 기본 세 섹션을 수정/삭제할 수 없음을 지적했고 먼저 개선하도록 지시했다. 프로젝트 화면은 섹션 추가만 제공한다.

섹션 머리에 관리 단추와 공통 모달을 제공해 이름 변경·삭제를 지원한다. 삭제는 작업 삭제가 아니며 기존 작업을 ‘섹션 없음’에 표시한다. 전부 삭제한 뒤 다시 추가할 수 있다. 이름 변경은 고정된 선택값에 표시 이름만 저장해 작업의 소속·본문·버전을 바꾸지 않는다. 목록·보드·속성 선택·작업 상세에서 같은 이름을 표시한다. 기존 권한(decidePageManage)과 스키마 낙관 잠금을 유지한다. DB migration·권한 우회·새 토큰 범위 없음.

## 검사

격리 합성 DB/실제 PHP와 Chromium: 기본 섹션 이름 변경 뒤 같은 작업 소속 유지, 보드/선택지 표시, 작업이 든 섹션 삭제 뒤 작업/본문/버전 보존, 마지막 섹션 삭제/추가, 중복·잘못된 값·409·CSRF·보기/편집 공유 관리 거부, 모바일/PC 키보드·초점·가로 넘침. 의미 있는 수락만 실행하고 비례 회귀는 밤 대기열에 넣는다. 실물 휴대폰 미검증을 구분한다.

## 서버 적용

암호화 백업·전체 복호화/파싱, 후보 고정·모의·운영/원격 drift 확인 후 FF와 발행·FPM reload, 실제 HTTPS와 기존 자료 보존 확인. 기존 업무 자료 변경은 사용자 지정 프로젝트에 요청받은 기록을 쓰는 정상 개인 토큰 요청만 별도로 수행한다. 기존 토큰은 프로젝트/하위 문서 생성과 스키마 관리를 지원하지 않으므로 해당 권한을 우회하지 않는다. 프로젝트 본문에는 전체 기획 기록을 저장할 수 있다. 내용에는 배포 완료/개발 완료/실사용 미검증/검토 대기/제안만 구분하고 근거·일자·완료 기준을 기재한다. Rea_ERP는 다른 프로젝트로 유지한다.
