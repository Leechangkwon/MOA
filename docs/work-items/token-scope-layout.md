## 목적과 범위

사용자가 토큰 발급 화면에서 체크박스가 어느 설명에 속하는지 구별하지 못해 읽기 전용·PC 로그인 범위를 잘못 선택했다. 범위 목록을 폼 전체 폭으로 넓히고, 제목·설명을 분리한 항목별 누름 영역으로 바꾼다. 체크박스는 제목 옆 첫 줄에 정렬한다. 문서 읽기/쓰기 용도와 PC 로그인 IP 제한을 명확히 안내한다.

수정 파일: `public/assets/app.css`, `public/assets/app.js`, `src/handlers/settings_page.php`, DESIGN/디자인 견본, 관련 안내·STAGES·SECURITY·위키·발행·배포 기록. 권한 옵션은 기존 서버 응답 그대로이며 기본 선택·연동·POST 내용·인증·DB 로직은 바꾸지 않는다.

연결 후속: 사용자가 실제 토큰 저장을 완료하여 지정한 프로젝트의 기존 작업 문서에 개발 현황·기능 설명·개발 기록을 추가했다. 정상 개인 토큰 API와 현재 판 번호를 사용했고 원래 2개 블록을 보존했다. 비공개 인계는 `~/.config/qaredi/rea-erp-handoff.json`이며 토큰/본문은 Git에 넣지 않는다. Codex 설정에는 토큰 파일 경로만 넣고 업무 문서 도구 5개를 등록한다.

실제 stdio 연결 중 기존 SDK1.12.4/Pydantic2.14.1 조합의 `eval_type_backport` import 실패를 발견했다. `clients/mcp/pyproject.toml`에 호환 Pydantic2.11.7을 고정하고 패키지/UA 버전을0.2.1로 맞춘다. `clients/mcp/tests/test_server.py`가 설치된 SDK의 ImportError까지 흉내 서버로 숨기던 부분을 수정한다. 해당4파일과 README/`deploy/DEPENDENCIES.md`, 이전 업무 MCP 검증 기록의 정정을 범위에 포함한다. PHP 운영 패키지는 바꾸지 않는다.

## 검사

실제 설정 화면 마크업·CSS·JS를 합성 계정/API로 렌더링해 PC/모바일에서 제목과 체크 정렬, 전체 폭, 행/제목/키보드 선택, 읽기·쓰기 의존 관계와 비서 단독 선택, 전송 범위를 확인한다. 실제 토큰 발급은 하지 않는다. 운영 반영 뒤 검토 계정으로 화면을 열어 같은 배치와 선택 동작을 확인한다. 관련 회귀 `core.qf10_multi_scope`는 기존 밤 대기열에 이미 포함돼 있으므로 중복 등록하지 않는다.

## 서버 적용

DB·패키지·설정·cron 변경 없음. 고정 후보·백업 복호화·모의 적용·드리프트 검사 후 코드 FF와 FPM reload. 기존 업무 자료·토큰·파일은 보존하며 시험은 토큰을 발급하지 않는다. 이상 시 중단하며 DB 자동 복원은 하지 않는다.
