# 휴가 전 미통합 기능 정리 — 서버 검증 기록

사용자 범위: 휴가 중 Git2로만 개발할 수 있도록 인계를 정리하고, 예전 미통합 기능까지 이어서 검증·배포한다. 기준 main은 `dd9611ac7f9e83a7ab707e96029cfd4b63d1dd49`(v2.45.0)이다.

- `wip/g0`: 개인 파일·폴더, 사람별 보기/편집 권한, 요청·승인·알림. 기존 파일 이름 변경, 공통 문서 저장, 모아·제안·자동화 알림을 유지했다.

- `wip/ux-r1`: 모바일 편집·제목 초점·블록 선택, 앱바 검색/알림, 최근 문서, 업로드 결과 표시, OTP 자동 제출, 세션 갱신 복구. 모아 메신저와 최신 편집 제안 기능을 보존했다.
- Git 인계: AGENTS, CLOUD-HANDOFF, 읽기 전용 work_status, 서버 검증 기록, 작업별 템플릿, 서버 부모 문서의 명시적 사본. 자동 배포는 구성하지 않았다.

## 서버 변경과 순서

새 패키지나 비밀 설정 변경 없음. 기존 Gemini 설정 및 GD를 그대로 사용한다. 암호화 백업 `/var/backups/tbox-v2/vacation-20261003`의 DB·코드/설정·사진 저장소와 복호화를 검증했다.

1. 고정한 후보 커밋의 전체 변경 파일과 해시를 확인하고 archive + binary diff 모의 적용.
2. 서버/원격 main의 드리프트와 백업 체크섬 확인.
3. `2026-10-10_access_grants.sql`을 코드보다 먼저 적용한다. 기존 16개 권한 행은 유지하고 개인 등급4행·새 표2개·알림 참조를 추가한다.
4. 고정한 코드를 fast-forward로 반영하고 `2026-10-13_api_tokens_multi_scope.sql`을 적용한다. 기존 community.write 토큰은 같은 읽기/쓰기 권한을 명시한 community.read+community.write로 정규화한다.
5. PHP-FPM reload, 실제 HTTPS·DB 권한·정적 파일·데이터 보존 확인 후 배포 기록 갱신 및 Git2 push.

코드 반영과 토큰 migration 사이에는 새 조합 발급이 잠시 실패할 수 있다. 기존 토큰 읽기는 새 코드가 호환한다. migration 실패 시 자동 복원·재시드·데이터 삭제를 하지 않고 현재 상태를 확인해 전진 보정한다. 개인 파일 또는 새 조합 토큰이 생긴 뒤에는 구버전 코드로 단순 되돌리지 않는다.

## 미검증과 다음 작업

실물 휴대폰의 남한산성 「AI로 꾸미기 → Gemini 초안 → 기존 글에 추가 → 저장」은 사용자 확인이 필요하다. 격리 저장 시험과 운영 모바일 브라우저 검증은 실물 확인을 대체하지 않는다. 운영의 기존 글을 시험 목적으로 저장하지 않는다.

앱 안 사진·영상 편집과 이 채팅에서 게시글을 읽고 수정할 MCP 연결은 신규 기능이다. 이번 문서용 MCP 검색 확장이 그 연결 완료를 의미하지 않는다. 별도 Windows 비서 브랜치의 설치·자격·배포물은 실Windows 환경 미검증이다. GPT 키 없음, 문서 AI 비활성, 비서 자연어 추론 미연결 상태는 유지된다.


## 운영 완료

v2.46.0 `56a4ae177865e3bbce44f67856f87553c8d36b53`를 main에 반영했다. 152개 변경 파일의 모의 적용/해시 확인, 두 DB migration, PHP-FPM reload 후 실제 HTTPS53/53을 통과했다. 서비스3개 active, 신규 개인 공유 조회와 토큰 선택지, 기존 Gemini 준비 상태, PC/휴대폰 화면·JS 오류0/5xx0을 확인했다.

배포 전후 사용자32·파일1037·폴더18·문서954·사진글3·첨부12와 기존 권한 행의 해시가 동일했다. 토큰106행은 community.write의 동등한 정규형 변경을 제외한 의미/데이터를 보존했다. 기존 사진 글에 시험 저장을 하지 않았다.

첫 운영 DB 적용은 folders/api_tokens의 실제 소유자가 postgres여서 tbox_owner 실행이 트랜잭션에서 중단됐다. 코드 반영 전이었고 신규 표/기존 행 변경은 없었다. 격리 사본의 원래 owner와 ACL을 모두 복원한 뒤 PostgreSQL 관리자 역할로6개 migration을2회 검증해 기존 소유권 보존까지 확인했다. 같은 권한으로 두 운영 migration을 성공 적용했다. 자동 백업 복원/재시드 없음.

배포 성공의 단일 기준은 deploy/production-state.json이다. 이후 인계·위키/상태 도구 기록 커밋은 발행 태그와 다를 수 있다. Git2 main/태그 동기화는 최종 검증 후 수행한다.
